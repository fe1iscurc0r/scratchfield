## 〇、一句话定位

让陆墨（脑）能**主动驱动 NEKO（皮）说话/换表情**——基于 M3.1a 的状态快照，判断「什么时候该主动开口」，而不是永远等用户先说话。**规则门先筛（零 LLM），LLM 只在候选过门后介入（token 可控）。**

## 一、背景与边界

### 现状
M3.1a 已完成「感知」：`LumoStateStore`（`apiserver/routes/lumo_state.py`）记录用户在 NEKO 侧的最近状态（输入/操作/TTS 打断/错误），并在下次对话时注入 `environment_snapshot`。但陆墨仍是**被动**的——只有用户发消息才响应。

M3 正向通道已打通：`POST /api/lumo/speak`（`NEKO/N.E.K.O/main_routers/lumo_inject_router.py`）能让 NEKO 说话/换表情。

### 做什么 / 不做什么

| 做 | 不做 |
|----|------|
| 主动搭话时机决策（规则门 + LLM 判定） | 主动搭话的**内容生成管线**（复用现有 speak 通道 + 陆墨对话） |
| 触发源：状态变化钩子 + 低频定时器 | 外部内容源接入（WEB/MUSIC/MEME，那是 N.E.K.O. 的源，不是我们的） |
| 三档冷却（accept/decline/ignore） | 多话题公平轮询（round-robin，M3.1b 首版单一话题即可） |
| 防打扰（静默期 + 频率 + 状态门） | 主动搭话的 UI/前端交互 |

**关键原则**：非侵入旁路。M3.1b 只读 `LumoStateStore`，不修改 M3.1a 的写路径；只调用已打通的 `/speak` 正向通道，不新造通信协议。

## 二、架构设计

```
触发源
├─ ① 状态变化钩子：lumo_state.update() 后 → 触发一次「检查」
└─ ② 低频定时器：每 N 分钟兜底检查（无事件时也能主动）

        ↓ 检查进入决策器 lumo_proactive.py
┌─────────────────────────────────────────────┐
│ 阶段 A：规则门（纯 Python，零 LLM）           │
│   ① 冷却门   accept 2h / decline 5h / ignore 30min │
│   ② 频率门   每小时最多 3 次                  │
│   ③ 状态门   用户活跃中 / TTS 播放中 → 跳过    │
│   ④ 静默门   23:00-07:00 → 跳过               │
│   ⑤ 话题衰减  同一话题半衰期 4h（防复读）      │
│   → 任何一门不通过 → 返回 pass（带 reason_code）│
└─────────────────────────────────────────────┘
        ↓ 过门（候选成立）
┌─────────────────────────────────────────────┐
│ 阶段 B：LLM 决策（单次，过门后才触发）        │
│   输入：状态快照 + 最近对话 + 人格 + 候选话题  │
│   输出：open（内容）/ close（不开）JSON       │
│   模型：gpt-4.1-nano（轻量，参考 intent_router）│
└─────────────────────────────────────────────┘
        ↓ open
   调用正向通道 POST /api/lumo/speak（已有）
        ↓ 用户回应（accept/decline/ignore）
   更新冷却 + 记录（供下次门控）
```

### 组件清单

| 组件 | 文件 | 类型 | 说明 |
|------|------|------|------|
| 主动决策器 | `apiserver/routes/lumo_proactive.py` | 新建 | 规则门 + LLM 决策 + 冷却状态 |
| 触发钩子 | `lumo_state.py` | 修改 | `update()` 后挂一个「检查」回调（可选，低耦合） |
| 定时器 | `lumo_proactive.py` 内 | 新建 | asyncio 后台任务，低频兜底 |

## 三、施工步骤

### 步骤 1：新建 `apiserver/routes/lumo_proactive.py`

核心类：`ProactiveDecider`，含规则门 + LLM 决策 + 冷却状态。代码骨架如下（可直接用）：

```python
"""M3.1b 主动搭话时机决策器 — 规则门先筛（零 LLM），LLM 只在过门后介入。

参考 N.E.K.O. proactive_chat：reason_code 门控 + 半衰期衰减 + 三档冷却。
本实现只读 lumo_state（M3.1a），只调正向通道 /api/lumo/speak，非侵入。
"""
from __future__ import annotations
import asyncio
import time
from dataclasses import dataclass, field
from typing import Optional

# ── 冷却/频率/静默配置（参考 N.E.K.O. proactive_settings，可调）──
COOLDOWN_ACCEPT_SECONDS = 2 * 3600      # 接受后 2h 静默
COOLDOWN_DECLINE_SECONDS = 5 * 3600     # 拒绝后 5h 静默
COOLDOWN_IGNORE_SECONDS = 30 * 60       # 无回应 30min 静默
MAX_PER_HOUR = 3                        # 每小时最多 3 次主动搭话
SILENT_START_HOUR = 23                  # 静默期开始
SILENT_END_HOUR = 7                     # 静默期结束
TOPIC_HALF_LIFE_SECONDS = 4 * 3600      # 话题半衰期 4h（防复读）

# 状态门判定：用户活跃中（最近 2 分钟有输入/操作）或 TTS 播放中 → 不打扰
ACTIVE_WINDOW_SECONDS = 120


@dataclass
class ProactiveState:
    """单 session 的主动搭话状态（内存态，与 lumo_state 同风格）。"""
    last_open_at: float = 0.0
    last_response: str = "ignore"          # accept / decline / ignore
    opens_this_hour: list[float] = field(default_factory=list)
    last_topics: dict[str, float] = field(default_factory=dict)  # topic_hash -> ts


class ProactiveDecider:
    """规则门 + LLM 决策 + 冷却状态。非线程安全，仅在 asyncio 单线程使用。"""

    def __init__(self) -> None:
        self._states: dict[str, ProactiveState] = {}
        self._http: Optional[object] = None  # httpx.AsyncClient，懒初始化

    # ── 阶段 A：规则门（纯 Python，零 LLM）──
    def _gate(self, sid: str, snapshot: str, now: float) -> Optional[str]:
        """过五道门，返回 None=通过，否则返回 reason_code（可审计）。"""
        st = self._states.setdefault(sid, ProactiveState())

        # ① 冷却门
        cooldown = {
            "accept": COOLDOWN_ACCEPT_SECONDS,
            "decline": COOLDOWN_DECLINE_SECONDS,
            "ignore": COOLDOWN_IGNORE_SECONDS,
        }[st.last_response]
        if now - st.last_open_at < cooldown:
            return "PASS_COOLDOWN"

        # ② 频率门
        st.opens_this_hour = [t for t in st.opens_this_hour if now - t < 3600]
        if len(st.opens_this_hour) >= MAX_PER_HOUR:
            return "PASS_THROTTLED"

        # ③ 状态门：用户活跃中（快照非空 = 最近 2 分钟有活动）→ 不打扰
        if snapshot:
            return "PASS_USER_ACTIVE"

        # ④ 静默门：深夜不打扰
        hour = time.localtime(now).tm_hour
        if hour >= SILENT_START_HOUR or hour < SILENT_END_HOUR:
            return "PASS_SILENT_HOURS"

        return None  # 通过所有门

    def _topic_decayed(self, sid: str, topic_hash: str, now: float) -> bool:
        """话题半衰期衰减：同一话题刚推过 → 跳过。"""
        st = self._states.setdefault(sid, ProactiveState())
        last = st.last_topics.get(topic_hash, 0.0)
        if last and (now - last) < TOPIC_HALF_LIFE_SECONDS:
            return False  # 未衰减，跳过
        return True

    # ── 阶段 B：LLM 决策（过门后才触发，单次）──
    async def _llm_decide(self, prompt: str) -> dict:
        """轻量 LLM 判定「开口/不开口」。模型 gpt-4.1-nano（参考 intent_router）。"""
        from litellm import acompletion
        from system.llm_params import get_llm_params, build_model_name
        resp = await acompletion(
            model=build_model_name("gpt-4.1-nano", model_type="router"),
            messages=[{"role": "system", "content": prompt}],
            temperature=0,
            max_tokens=120,
            **get_llm_params(model_type="router"),
        )
        # 解析 JSON：{"open": true/false, "text": "..."}
        import json
        raw = resp.choices[0].message.content or "{}"
        try:
            return json.loads(raw)
        except Exception:
            return {"open": False, "text": ""}

    # ── 主入口：一次「主动搭话检查」──
    async def check(self, sid: str, snapshot: str, topic: str) -> Optional[dict]:
        """规则门 → LLM 决策 → 返回行动（或 None=不搭话）。"""
        now = time.time()
        reason = self._gate(sid, snapshot, now)
        if reason:
            return None  # 门不通过，静默（可加日志记 reason_code）

        # 话题衰减
        topic_hash = topic[:32]  # 简化：首版用话题前缀做 hash
        if not self._topic_decayed(sid, topic_hash, now):
            return None

        # LLM 决策（过门后单次）
        prompt = (
            "你是陆墨，一个主动陪伴用户的 AI 搭档。判断是否该主动说话。\n"
            f"候选话题：{topic}\n"
            "只输出 JSON：{\"open\": true/false, \"text\": \"要说的内容\"}\n"
            "若话题不值得主动开口，输出 {\"open\": false}。"
        )
        decision = await self._llm_decide(prompt)
        if not decision.get("open"):
            return None

        st = self._states.setdefault(sid, ProactiveState())
        st.last_open_at = now
        st.opens_this_hour.append(now)
        st.last_topics[topic_hash] = now
        return {"text": decision.get("text", ""), "topic": topic}

    async def respond(self, sid: str, response: str) -> None:
        """用户回应（accept/decline/ignore）→ 更新冷却。"""
        st = self._states.setdefault(sid, ProactiveState())
        st.last_response = response if response in ("accept", "decline") else "ignore"


_decider = ProactiveDecider()


def get_decider() -> ProactiveDecider:
    return _decider
```

### 步骤 2：改 `lumo_state.py` 挂触发钩子（低耦合，可选）

在 `LumoStateStore.update()` 末尾加一行（不侵入主逻辑）：

```python
    # [M3.1b] 状态变化后触发一次主动搭话检查（fire-and-forget，不阻塞）
    try:
        from .lumo_proactive import get_decider
        import asyncio
        asyncio.create_task(get_decider().check(
            session_id, self._states[session_id].render(), "科研提醒"
        ))
    except Exception:
        pass  # M3.1b 未就绪或异常，不影响 M3.1a 状态写入
```

**注意**：这一步是「状态变化触发」，但 `check()` 里的规则门会挡住大部分（状态门：用户活跃中 → 不搭话），所以只有「用户长时间沉默」时才可能过门。

### 步骤 3：定时器兜底（`lumo_proactive.py` 内）

```python
async def _periodic_check(self, interval: int = 300):
    """每 5 分钟兜底检查一次（无事件时也能主动）。"""
    while True:
        await asyncio.sleep(interval)
        for sid in list(self._states.keys()):
            try:
                await self.check(sid, "", "科研提醒")
            except Exception:
                pass
```

定时器在 apiserver 启动时（lifespan）挂上，或作为独立后台任务。

## 五、已知限制（诚实标注）

1. **不生成内容管线**：本 SPEC 只做「时机决策 + 让 NEKO 说话」，主动搭话的**内容质量**（说什么）靠 LLM 单次生成，不做多候选精选（那是 N.E.K.O. 的 Phase 1/2 两阶段，首版简化）。
2. **回应回传缺 UI**：accept/decline 需要前端按钮，M3.1b 首版可能没有，全部走 ignore（30min 冷却）。这是「待联调」假设。
3. **话题衰减简化**：首版用 `topic[:32]` 做 hash，不是真正的语义去重。
4. **单 session 内存态**：`ProactiveState` 存内存，重启即丢冷却状态（与 M3.1a 同风格，可接受）。
5. **`_gate` 的 snapshot 判定**：用「快照非空 = 用户活跃」近似，实际 M3.1a 的 TTL 是 10min，这里 ACTIVE_WINDOW 是 2min——两者语义不同，首版按「快照非空」近似，精确活跃判定留后续。

## 六、测试用例（云服可跑，纯 Python）

```python
# 测试规则门（零 LLM，不需网络）
from lumo_proactive import ProactiveDecider, MAX_PER_HOUR
d = ProactiveDecider()

# 1. 状态门：用户活跃（快照非空）→ PASS_USER_ACTIVE
assert d._gate("s1", "有活动", time.time()) == "PASS_USER_ACTIVE"
print("PASS 1: 状态门拦截")

# 2. 静默门：深夜 → PASS_SILENT_HOURS（用 mock 时间或直接测逻辑）
# 3. 冷却门：刚 open 过 → PASS_COOLDOWN
st = d._states.setdefault("s2", type(d._states["s2"])() if "s2" in d._states else __import__("lumo_proactive", fromlist=["ProactiveState"]).ProactiveState())
st.last_open_at = time.time()
st.last_response = "accept"
assert d._gate("s2", "", time.time()) == "PASS_COOLDOWN"
print("PASS 2: 冷却门拦截")

# 4. 频率门：1 小时内已 3 次 → PASS_THROTTLED
st3 = d._states.setdefault("s3", __import__("lumo_proactive", fromlist=["ProactiveState"]).ProactiveState())
st3.opens_this_hour = [time.time()-10, time.time()-20, time.time()-30]
assert d._gate("s3", "", time.time()) == "PASS_THROTTLED"
print("PASS 3: 频率门拦截")

# 5. 过门：无活动 + 白天 + 无冷却 + 未超频 → None（通过）
st4 = d._states.setdefault("s4", __import__("lumo_proactive", fromlist=["ProactiveState"]).ProactiveState())
st4.last_open_at = time.time() - 3*3600  # 3h 前，冷却已过
st4.last_response = "accept"
import datetime
# 白天测试需当前时间非深夜，云服 CST 白天跑即可
assert d._gate("s4", "", time.time()) is None
print("PASS 4: 规则门通过（进入 LLM 决策）")
```
