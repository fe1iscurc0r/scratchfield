## 一、问题陈述

多 Agent 链中，**错误不是独立分布的，而是会被下游继承和放大**：一个 Agent 的不确定性输出，作为上游输入传给下一个 Agent，后者带着这份继承的不确定性继续推理，误差逐跳放大。若不显式建模，就无法知道"某条结论有多不可靠"。

PropUQ-MAS（2608.22130）首次系统建模 MAS 中 Agent 间不确定性的传播图，实证：AUROC 相对提升 +6.10%，PRR（正确保留率）+47.58%。

## 二、传播模型设计

### 2.1 通信结构图
把 MAS 建模为**有向通信图**：节点 = Agent，边 = 消息传递（带不确定性）。

### 2.2 不确定性传播规则
每个 Agent 的每一步输出，其不确定性 = **本地不确定性** + **上游继承不确定性** 的合成：

```
U_i(t) = U_local_i(t) ⊕ f( { U_j(t-1) : j 是 i 的上游 } )
```

- **本地不确定性**：Agent 自身对当前推理的置信度。
- **上游继承**：收到的消息里带有的不确定性，沿边传播并放大。
- 合成算子 ⊕ 刻画"错误如何叠加"（并非简单相加，而是依赖通信结构的传播）。

### 2.3 可靠性估计
对每一步 / 每一条结论，输出一个**可靠性分数**，用于：
- 标记高不确定性的结论（需额外验证）；
- 路由时优先重试高不确定性路径（对齐 A16/A17 的调度）。

## 三、风险分析

| 风险 | 来源 | 缓解 |
|---|---|---|
| 错误级联放大 | 上游继承不确定性 | 传播模型显式标注，触发验证 |
| 规模放大 | 链越长，累积不确定性越大 | 限制链长 / 关键跳引入验证门控（A20） |
| 假高置信 | Agent 过度自信 | 用 UQ 修正置信度（AUROC +6.10%） |

**结论**：MAS 的可靠性瓶颈在"Agent 间消息的可靠性"，错误传播必须显式建模，而不是假设独立同分布。
