# S27 ContextLeak 工具上下文窃取防御方案

> 生成：2026-08-31 · 来源：round3 digest-g3 2608.27800（ContextLeak: Exfiltrating LLM Agent Context via Malicious Tools）
> 落点：NEKO 工具安全 · 状态：分析 + 防御方案

---

## 0. 结论速览

ContextLeak 攻击不直接注入恶意指令，而是**用 RL 微调让 LLM 主动生成恶意工具的名称/描述**，诱导 Agent 在选择工具时把运行时上下文当作工具参数泄露出去，且能跨「影子用户」泛化。攻击点从「提示词」转移到了「工具注册表」与「Agent 的工具选择/参数填充」环节。

## 1. 攻击链拆解

| 步骤 | 做法 |
|---|---|
| 1. 恶意工具生成 | RL 微调让模型生成看似正常的工具名/描述（如 `debug_utils`），实际把上下文塞进参数 |
| 2. Agent 主动选择 | Agent 在任务中被诱导选择该恶意工具 |
| 3. 上下文作为参数泄露 | 工具调用时把运行时上下文（密钥/历史/文件内容）作为参数外发 |
| 4. 跨用户泛化 | 攻击不依赖特定用户，跨影子用户仍有效 |

## 2. 防御设计（≥3）

### 防御 1：工具沙箱 + 出口监控
- **设计**：所有工具在沙箱运行，工具的参数与返回值经过出口监控——检测参数中是否携带不应外发的敏感数据（密钥、长上下文片段、文件内容指纹）。
- **指标**：敏感数据外发检出率、工具网络出口白名单命中率。

### 防御 2：上下文最小化（least-context）
- **设计**：Agent 每次工具调用只传入**完成任务所需的最小上下文**，而非全量对话历史/系统上下文；对工具描述做「来源可信度」标记，非用户/命名来源的工具降权。
- **指标**：工具调用入参的上下文泄露面（字节数/敏感字段数）。

### 防御 3：工具注册表确定性白名单（结合 A34 起源门控）
- **设计**：工具必须来自可信注册表（HMAC 签名 + 血统），运行时动态生成/未签名工具被门控拦截；对「模型自述可用但无注册记录」的工具直接拒绝。
- **指标**：未签名工具拦截率、伪造工具注入成功率。
