# 多跳频谱感知协作 · 方案

> 来源工单：R25 · 分组 group1-无线电
> 参考 digest：[digest-g1-4-2026-08-30.md](../paper-round2-2026-08-30/digests/digest-g1-4-2026-08-30.md)（授粉点 3 · 论文 2608.26225 Agent Mesh + 2608.27146 SARA）
> 日期：2026-08-30

---

## 1. 结论先行

把 Agent 协作的最小原语——**角色（identity）、承诺（commitment）、验证（verification）**——引入多节点频谱感知：每个节点对「环境频谱状态」的断言必须**可验证**，错误身份/证据会导致整个频谱分配出错。据此设计协作协议，覆盖状态机与冲突处理。

---

## 2. 协作原语（角色/承诺/验证）

| 原语 | 含义 | 频谱感知映射 |
|---|---|---|
| 角色（identity adequacy） | 身份须能区分「正确/错误」答案 | 节点身份须经物理层指纹（R18）认证，防冒名 |
| 承诺（commitment） | 节点对某频谱占用做出的断言 | "信道 C 被主用户占用，持续 T 秒" |
| 验证（evidence adequacy） | 可靠性决策须有可移动证据 | 断言须附证据（原始频谱帧/时间戳），可被其它节点复核 |

---

## 3. 协作状态机

```
 ┌─────────┐  广播感知请求   ┌─────────────┐   收集承诺    ┌─────────────┐
 │  发起者  │ ─────────────→ │  各节点(角色) │ ───────────→ │  聚合/验证   │
 └─────────┘                 └─────────────┘              └─────────────┘
       ↑                                                          │
       │                     ┌─────────────┐   冲突?             │
       └──── 达成一致 ────── │  共识仲裁    │ ←───────────────────┘
                             └─────────────┘
                                  │ 冲突不决 → 证据复核/降级到本地决策
```

状态：`IDLE → REQUESTING → COLLECTING → VERIFYING → CONSENSUS / CONFLICT → COMMITTED`。

---

## 4. 冲突处理

| 冲突类型 | 场景 | 处理 |
|---|---|---|
| 身份冲突 | 两节点声称同一身份 | 物理层指纹（R18）仲裁，假冒者剔除 |
| 证据冲突 | 两节点对同一信道断言矛盾 | 要求双方出示原始频谱证据 + 时间戳，交叉复核 |
| 观测差异 | 空间分集导致不同节点观测不同 | 按「谁离目标频段更近/信噪比更高」加权，或按 R33 共识合并 |
| 承诺违约 | 节点承诺后不执行/超时 | 超时降级，标记该节点可信度下降，重新分配 |

---

## 5. 落地建议

1. 身份用 R18 指纹 + 轻量签名；承诺带「断言 + 证据哈希 + 时间戳」。
2. 验证用「证据可移动性」：断言者可被要求重发原始帧，接收者独立复核。
3. 冲突仲裁用多数共识 + 就近加权（复用 R33 群体协同感知），避免单点。
4. 与 R01 事件缓存、R24 资源分配联动：协作结果直接喂入频谱决策层。
