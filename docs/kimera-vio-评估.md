## 1. 项目定位

开源 VIO（视觉惯性里程计）标杆：Stereo+IMU 主路径（可选 Mono+IMU），实时度量-语义
定位与建图（Kimera 家族）。MIT SPARK Lab 出品，ICRA'20 论文，Jenkins 公开 EuRoC
性能报告。**在避障链路中的位置**：避障算法（规划/反应式）的前提是「我在哪/怎么动」——
VIO 提供 6-DoF 位姿+速度估计，是深度相机避障与路径规划的**前置状态估计层**。

## 2. 架构拆解（顶层实测）

```
src/ include/        # C++ 主体（153 cpp + 123 头）：前端（视觉前端+IMU 预积分）/
                     # 后端（因子图优化）/ 回环 / mesh 重建（Kimera-Mesh 系）
params/              # 按数据集分组的 yaml 参数（Euroc/TUM…）——标定/噪声/阈值外置
examples/ tests/     # 可运行示例 + 单测
third_party/         # gtsam/gflags 等 vendored 依赖
cmake/ scripts/ dev_tools/
```

要点：
- **参数全外置 yaml**：IMU 噪声/相机标定/前端阈值按数据集分文件——VIO 工程化的
  关键实践，本仓若接 VIO 必先建「标定档案」目录。
- **mesh 输出**：Kimera 家族的 metric-semantic mesh 可喂规划层做占据/距离查询——
  「VIO→mesh→避障距离查询」是标准接法。
- **公开性能报告**：EuRoC 逐序列误差表可作选型基准，不必自跑全基准。

## 3. 硬件需求与可用性评估（如实标注）

- 运行需求：立体相机（或单目）+ 同步 IMU + x86/ARM Linux（ROS 可选）；
  依赖 gtsam/Eigen/boost/opencv 系。
- **本仓现实**：无深度相机、无立体相机、无 IMU 硬件；主控 ESP32-S3 跑不动 VIO。
  → **短期不可运行**；价值在（a）避障链路设计参照（状态估计层接口定义），
  （b）天选7 上做**数据集回放仿真**（EuRoC 公开集）验证管线理解，不接真机。
- 结论：**设计参照 + 回放仿真**定位，不进固件、不上主控。

## 4. 可落地借鉴点（≥3）

1. **状态估计层接口定义**：把「位姿+速度+协方差」作为避障规划的输入契约写进
   本仓避障模块设计（即使当前用 GPS/光流替代 VIO，接口不变，未来可换源）。
2. **标定档案目录**（params/ 按设备分 yaml）：本仓相机/IMU/光流传感器标定数据
   照此组织，避免硬编码。
3. **mesh→距离查询**的占据表示思路：避障规划层用「占据网格/voxel 距离场」作
   统一查询接口，深度相机/GPS fence/LoRa 测距都可写入同一占据层。
4. **公开基准回放**作为无硬件验证手段（EuRoC rosbag 回放），先跑通理解再谈集成。
