## 调研结果汇总

| # | 技术 | 成熟度 | 描述 | 贴栈理由 | 立项建议 |
|---|------|--------|------|----------|----------|
| 1 | **语义层（Semantic Layer）** | Trial | 数据仓库与消费应用之间的共享业务逻辑层，统一 metric 定义/join/访问规则。解决 LLM naive text-to-SQL 产生错误结果的问题。Snowflake Semantic Views、Databricks Metric Views、dbt MetricFlow、Open Semantic Interchange v1.0 | Agentic AI 的 naive SQL 幻觉问题；我们有多租户数据分析场景；语义层统一指标定义对 DORA 度量也有价值 | **建议立项**：在数据平台层接入语义层，解决 RAG→SQL 幻觉 + 指标口径不统一问题 |
| 2 | **Graphiti（时序知识图谱）** | Trial | Zep 开源的时序知识图谱引擎，为 LLM Agent 提供持久化记忆。Bi-temporal validity window 使旧事实失效而非覆盖；支持 MCP server；18.5% 精度提升 + 90% 延迟降低 benchmark | 我们已有 graphify/neo4j 图记忆，但 Graphiti 的时序特性（事实随时间失效）和 sub-second 检索更适合动态 Agent 记忆场景；与 MCP 原生集成 | **建议立项**：作为 Agent 跨会话持久记忆层，对接现有 MCP 基础设施 |
| 3 | **Feedback Sensors for Coding Agents** | Trial | 为 Coding Agent 引入确定性质量门（编译器/linter/类型检查/测试套件），使失败触发自动自纠正，降低人工审查负担。工具如 cargo-mutants、CodeScene、WuppieFuzz | 我们的 Agent 产出需要质量门；Feedback flywheel 理念与 skill_gate 机制天然契合；减少 Agent 产出到人类审核的循环次数 | **建议立项**：集成到 skill_gate 输出管道，作为 Agent 产出的自动校验层 |
| 4 | **Sandboxed Execution for Coding Agents** | Trial | 在隔离环境（microVM/container）中运行 Coding Agent，限制文件系统访问、受控网络连接、有限资源。工具：Shuru（ephemeral microVM）、Sprites（stateful checkpoint/restore）、Bubblewrap、Dev Containers | Coding Agent 权限越来越大（OpenClaw、Claude Cowork），安全风险上升；我们已有安全编排经验；沙箱化是"permission-hungry agents"的必要防线 | **建议立项**：为 Agent 执行层增加沙箱隔离，特别是对外部工具调用和文件写入操作 |
| 5 | **Small Language Models（SLMs）** | Assess | 蒸馏小模型（Phi-4-mini、Ministral 3 3B、Qwen3-0.6B）在特定任务上性价比高于大模型，推理成本低、延迟小。边缘设备友好 | 我们的 skill_gate/Agent 编排有成本压力；特定垂直任务（分类/摘要/工具路由）可用 SLM 替代大模型；与 rf_brain 的嵌入式场景天然匹配 | **建议立项**：在知识库召回路由、简单分类任务上试点 SLM，验证质量/成本平衡 |
| 6 | **LLM 评估：语义熵（Semantic Entropy）** | Assess | 通过语义信息熵而非词法变异检测 LLM 幻觉/confabulation，泛化到 unseen tasks，无需 prior knowledge | 我们有 RAG 管线；RAG 输出的幻觉检测是关键风险点；与 graphify 配合可形成"知识库→图谱→幻觉校验"闭环 | **建议试点**：集成到 RAG 管线输出层，对高风险输出做二次语义熵校验 |
| 7 | **Context Graph** | Assess | 将决策/策略/例外/先例建模为一阶连通图节点，专门为 AI 消费设计。与 GraphRAG 不同，维护 temporal validity on every edge | 我们已有 graphify，但 Context Graph 更强调"why"而非"what"——捕捉制度性推理链条；与 DORA 度量和反馈 flywheel 天然结合 | **建议调研**：对比 graphify/neo4j，评估 Context Graph 在多跳因果推理场景的增量价值 |
| 8 | **MITRE ATLAS（AI 对抗框架）** | Assess | 针对 AI/ML 系统的对抗战术知识库（补充 ATT&CK），覆盖 ML pipeline、LLM 应用、Agentic 系统威胁模型 | 我们的 Agent 系统越来越复杂；安全评估是合规必要；与我们的红队知识库（hunt-*）可整合 | **建议立项**：作为 Agent 安全评估框架，纳入安全开发生命周期 |
| 9 | **SigNoz（OTEL 原生可观测性）** | Trial | 开源 OpenTelemetry-native 可观测平台，统一 logs/metrics/traces，基于 ClickHouse 自存储，开源替代 Datadog | 我们已有可观测性基础设施；SigNoz 的 OTEL 原生+ClickHouse 架构与现有体系对齐；降低成本 | **建议试点**：在 Agent 执行链路追踪上试用 SigNoz，评估与 Langfuse 的互补性 |
| 10 | **AG-UI Protocol** | Assess | Agent-UI 通信开放协议，通过 SSE/WebSocket 实现流式 reasoning steps、状态同步、动态 UI 渲染 | 我们有前端能力；AG-UI 可以标准化 Agent 与前端的状态同步；但 MCP-UI 正在出现，协议层有竞争风险 | **建议观察**：先做 POC 验证，关注 MCP-UI 生态发展再决定 |

## Top 5 推荐立项方向

### 🥇 1. Feedback Sensors for Coding Agents（Feedback Sensors × skill_gate 集成）
**成熟度：Trial | 来源：Thoughtworks Radar Vol 34, Technique #9**

**核心逻辑**：将确定性质量门（编译器/linter/类型检查/mutation testing）直接接入 Agent 产出管道，失败自动触发自纠正。这正是我们 skill_gate 的缺失环节——目前 Agent 产出直接出人工审核，循环成本高。Thoughtworks 明确将此项列为 Trial，工具生态（cargo-mutants、CodeScene）已成熟。

**立项价值**：降低人工审核负担、加速 Agent 产出验证、与现有 skill_gate 无缝衔接。

---

### 🥈 2. Semantic Layer（语义层）
**成熟度：Trial | 来源：Thoughtworks Radar Vol 34, Technique #14**

**核心逻辑**：RAG→SQL 的 naive 幻觉是 Agentic AI 的致命弱点。语义层在数据仓库和 AI 应用之间建立统一业务逻辑层（Snowflake Semantic Views、dbt MetricFlow、Open Semantic Interchange v1.0），从源头消灭口径问题。Thoughtworks 特别指出这对 DORA metrics 统一也有价值。

**立项价值**：解决 RAG 输出的 SQL 幻觉问题、统一指标定义、对接现有数据平台。

---

### 🥉 3. Graphiti（时序知识图谱）→ Agent 持久记忆层
**成熟度：Trial | 来源：Thoughtworks Radar Vol 34, Platform #45**

**核心逻辑**：我们已有 graphify/neo4j，但 Graphiti 的 Bi-temporal validity window（旧事实失效而非覆盖）和 sub-second 检索是真正的增量。Thoughtworks 将其从 Assess 升到 Trial，18.5% 精度提升 + 90% 延迟降低，官方 MCP server 原生集成。

**立项价值**：作为 Agent 跨会话持久记忆层，与现有 MCP 基础设施对接，弥补 graphify 在动态时序记忆上的不足。

---

### 4. Sandboxed Execution（沙箱化执行）
**成熟度：Trial | 来源：Thoughtworks Radar Vol 34, Technique #13**

**核心逻辑**：Thoughtworks 的"permission-hungry agents"警告（Vol 34 Themes）直接命中我们的场景。OpenClaw、Claude Cowork 模式需要全局访问，沙箱化是唯一安全出路。工具链成熟：Dev Containers（ephemeral）、Sprites（stateful checkpoint/restore）。

**立项价值**：为 Agent 执行层构建安全边界，特别是外部工具调用和文件写入操作。

---

### 5. Small Language Models（SLMs）
**成熟度：Assess | 来源：Thoughtworks Radar Vol 34, Technique #29**

**核心逻辑**：Phi-4-mini、Ministral 3 3B、Qwen3-0.6B 等蒸馏模型在特定任务上性价比已超 GPT-4 级别大模型。推理成本降低 10x，延迟降低，对边缘/嵌入式场景天然友好。我们的 rf_brain 和 skill_gate 路由层是 SLM 的最佳切入点。

**立项价值**：降本（Token 成本）、提速（低延迟路由）、边缘部署可能性。

---
