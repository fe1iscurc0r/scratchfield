## SPEC-R1 · Graphiti 时序知识图谱 → Agent 跨会话持久记忆层

### 目标
把 Zep Graphiti 的 Bi-temporal 时序特性（旧事实失效而非覆盖）接入现有记忆体系，作为 Agent 跨会话持久记忆层。

### 现状
- 已有：graphify（代码→图谱）、neo4j 图记忆（W68-06）、memory_maas 五元组、summer_memory
- 缺口：动态 Agent 记忆（事实随会话失效）、sub-second 检索、MCP 原生集成

### 方案（纯 Python，新增文件，不碰现有模块核心）
1. `mcpserver/memory_maas/temporal_graph.py` — Bi-temporal 记忆图：
   - 事实节点带 `valid_from/valid_until`，旧事实失效而非覆盖
   - sub-second 检索（内存索引 + 惰性持久化）
   - MCP tool 暴露：`add_fact / query_facts / invalidate_fact`
2. `tools/test_temporal_graph.py` — pytest 验收硬线：
   - `test_fact_invalidated_not_overwritten`：同实体新事实写入后旧事实标记失效
   - `test_query_respects_time_window`：查询带时间窗返回该时段有效事实
   - `test_subsecond_lookup`：1000 事实下查询 < 1s
   - `test_mcp_tool_exposed`：三个 MCP tool 可注册

### 验收
`python -m pytest tools/test_temporal_graph.py -q` 全绿；不碰 memory_maas 现有模块核心。

## SPEC-R2 · Feedback Sensors → skill_gate 质量门升级

### 目标
把确定性质量门（编译器/linter/测试套件/mutation）接入 skill_gate 产出管道，失败自动触发自纠正。

### 现状
- 已有：W64-06 skill_gate（27 passed，方法门）、superpowers 流程、orchestration（18 passed）
- 缺口：质量门只是「校验」，没有「失败→自纠正」闭环

### 方案（纯 Python，新增文件）
1. `mcpserver/orchestration/feedback_sensor.py`：
   - `QualityGate` 抽象：静态检查/lint/测试/类型四种传感器
   - `FeedbackLoop`：产出 → 全门校验 → 失败收集错误 → 构造自纠正提示 → 重跑（限次）
   - 与 skill_gate 的 gate 结果打通（读其输出）
2. `tools/test_feedback_sensor.py` — pytest 验收硬线：
   - `test_gate_all_pass_no_retry`：全过不重试
   - `test_gate_fail_triggers_retry`：失败触发自纠正重试
   - `test_max_attempts_bounded`：重试次数有上限
   - `test_corrective_prompt_includes_error`：自纠正提示含错误信息

### 验收
`python -m pytest tools/test_feedback_sensor.py -q` 全绿；不碰 orchestration 现有模块核心。

## SPEC-R3 · Sandboxed Execution → Agent 沙箱执行层

### 目标
为 Agent 执行层构建沙箱隔离（限制文件系统/网络/资源），防御「permission-hungry agents」。

### 现状
- 已有：安全编排经验、蜜罐反制层（deception-layer）、W60-02 ContextLeak 防御
- 缺口：Agent 工具调用的运行时沙箱

### 方案（纯 Python 设计 + 模拟；真实沙箱标「待容器环境」）
1. `mcpserver/orchestration/exec_sandbox.py`：
   - `SandboxPolicy`：文件系统白名单 / 网络禁连 / 资源上限（CPU/内存/超时）
   - `SandboxedRunner`：拦截工具调用，按策略允许/拒绝/降级
   - 真实隔离（子进程/容器）留接口，云服可验部分用「策略模拟」
2. `tools/test_exec_sandbox.py` — pytest 验收硬线：
   - `test_policy_blocks_disallowed_path`：白名单外路径被拒
   - `test_policy_allows_whitelist`：白名单内放行
   - `test_network_blocked`：网络调用被拒
   - `test_resource_timeout`：超时强制终止
   - `test_deny_logged`：拒绝行为入审计日志

### 验收
`python -m pytest tools/test_exec_sandbox.py -q` 全绿；安全类只写防御；不碰现有模块核心。

## SPEC-R4 · SLM 小模型路由 → 降本路由层

### 目标
用小模型（分类/摘要/工具路由）替代大模型，降本 10x，验证质量/成本平衡。

### 现状
- 已有：rf_brain、skill_gate 路由层、memory_maas
- 缺口：小模型路由的量化验证

### 方案（纯 Python，新增文件，不引入重型依赖）
1. `tools/slm_router.py`：
   - `TaskClassifier`：规则/关键词路由（不调 LLM，纯可验证）
   - `SLMRouter`：按任务复杂度分派——简单→小模型（模拟），复杂→大模型（模拟）
   - 成本核算：token 数 × 单价，输出省了多少
2. `tools/test_slm_router.py` — pytest 验收硬线：
   - `test_simple_task_routed_small`：简单任务走小模型
   - `test_complex_task_routed_large`：复杂任务走大模型
   - `test_cost_reduction_computed`：成本降低比例可计算
   - `test_quality_gate_preserved`：质量门在路由后仍生效

### 验收
`python -m pytest tools/test_slm_router.py -q` 全绿；纯模拟不调真实 LLM；不碰现有模块核心。
