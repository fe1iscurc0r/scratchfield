# GitHub 扫货 — 跨域授粉计划 v1

> 不是「我们有什么就加什么」，是「把看似毫无关联的放进来，看它们怎么炸」。
>
> 授粉三原则：① 跨域扫描，不设边界 ② 落地难度×收益=优先级 ③ 非侵入式，只做旁路

---

## 零、核心思想：错位使用

同一个工具，换一个域就是新武器。

```
┌─────────────────────────────────────────────────────┐
│  传统用法              错位使用                      │
│  ─────────            ─────────                      │
│  游戏物理引擎 →        材料晶体结构模拟               │
│  音频DSP降噪 →         SDR频谱信号提纯               │
│  地图空间索引 →        知识图谱时空查询               │
│  编译器PEG解析 →       材料配方语法→结构化知识        │
│  共识算法(Raft) →      多Agent协同决策               │
│  CRDT无冲突数据 →      离线记忆同步                   │
│  零知识证明 →          隐私保护的知识共享验证          │
│  生物序列比对 →        材料合成路径优化               │
│  日语分词MeCab →       化学式分词（H₂O→[H,2,O]）     │
│  SQLite嵌入式DB →      Agent记忆的本地一等公民        │
└─────────────────────────────────────────────────────┘
```

**错位的本质**：A领域的核心数据结构，恰好能描述B领域的问题。发现这种「恰好」是授粉的全部价值。

| 源领域 | 概念 | 错位用途 | 依赖 |

## 五、授粉纪律

1. **每个授粉模块必须独立可运行**（`--simulate` 自测），不侵入现有管道
2. **先评估再动手**：落地难度(L/M/H) × 收益(1-10) → 优先级
3. **不因为"看起来不相关"就排除** — 核心数据结构的共鸣才是标准
4. **学术包 vs 安全包分离**：材料科学项目→知识提取(Markdown+JSON)，安全项目→MCP Agent
5. **GPL/AGPL 只能参考设计**，代码不入库。MIT/Apache 2.0 可以直接合
