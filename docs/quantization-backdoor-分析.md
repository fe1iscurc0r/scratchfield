## 0. 结论速览

量化触发后门利用**后训练量化制造的结构性「验证-部署」差距**：模型在 FP16 下通过合规检查（后门不激活、看起来干净），量化到 INT8/4bit 后后门才被触发。关键证据：敌对翻译模型量化后「敌友识别」从 0 升至 85.02%，说明后门逻辑被量化误差「唤醒」。这直接威胁「FP16 训练 → 端侧量化部署」的常规流程——**只验 FP16 等于没验**。

## 1. 攻击机制

1. **植入**：攻击者在训练/微调阶段植入一个对高精度权重不敏感、对量化误差敏感的后门触发器。
2. **潜伏**：FP16 推理时后门不激活，合规/安全扫描（红队、行为测试）全部通过。
3. **触发**：模型量化到 INT8/4bit 后，量化误差落在触发器的敏感区间，后门激活（敌友识别 0→85.02%）。
4. **迁移性**：跨量化器迁移性**因架构而非位宽而异**——某些架构的量化误差分布能稳定携带后门，换量化器也可能触发。

## 2. 防御建议（≥3）

1. **量化后复测**：安全/合规评估必须在**目标量化精度**（INT8/4bit）下重跑，不能只验 FP16。把「量化后行为测试」设为发布门禁。
2. **量化器级一致性审计**：对比同一模型在 FP16 与各量化精度下的输出分布，检测「量化后行为突变」的层/通道，作为后门定位信号。
3. **随机化量化/扰动鲁棒性**：用随机量化抖动或权重扰动重跑，若行为对扰动高度敏感，则可能存在量化触发后门；配合权重异常检测（偏离自然分布的量级）。

## 3. 端侧影响评估

- **影响：高**。NEKO/ESP32 端侧模型正是「FP16/全精度训练 → INT8 量化部署」的典型流程，量化触发后门是真实威胁。
- **落点**：端侧部署的 rf_brain/OTA-ELM/Bern2Edge 等模型，量化后必须补行为测试；LUT/定点链路虽简化了量化面，但「验证-部署」差距仍需显式闭合。
- **建议**：把「量化后复测」纳入端侧模型的发布 CI，与 `tools/elm_train.py` 的 int8 导出链路衔接。
