## 2. 406 的真实成因

- `fetch_arxiv.py:42` 的注释已写明：**arXiv 对 Python urllib 的 TLS 指纹返回 406**，改用 curl。
- 因此这不是"IP 被限流"，也不是"arXiv 不可用"：**是客户端 TLS 指纹被拒**。
- 10-20 实测：`curl` + 浏览器 UA → **200 / 38 ms**，31 大类全部有增量。
- 同类经验（供其他外网抓取脚本复用）：
  1. 先分清 **HTTP 状态码（403/406/429）** 与 **连接层失败（timeout/TLS）**；
  2. Python `urllib`/`requests` 的 TLS 指纹可能被 CDN 拦截 ⇒ 用 `curl` 或换 UA 复测；
  3. 复测必须是**同一 URL、同一时刻**的对照，否则无法区分"服务端变了"还是"客户端被拦"。

## 3. RSS 兜底的去留

- **结论：保留 API 为主路径**，RSS 降级为**诊断通道**（不当主路径）。
- 触发条件（切 RSS）：**API 连续 3 天非 200**，或连续 3 天 `new` 为 0 且已知 arXiv 有公告批次。
- 切回顾据（切回 API）：API 单日复测 200 且 `new > 0`。
