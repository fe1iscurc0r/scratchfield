## 1. 结论先行

把 Speech LLM 的少样本理解能力接到 rf_brain 上，形成「**语音指令 → 频谱操作**」闭环 Agent：管理员用自然语言查询/下发频谱任务，Agent 解析 → 执行 → 语音应答。**关键安全约束**：语音生物特征不稳定（声纹是条件概率分布，deepfake 可伪造），故高安全操作必须加**额外确认层**（如按键确认 / 多因素），不能仅凭声纹授权。

---

## 2. 流程架构

```
 语音输入
    │
 [VAD]  语音活动检测（端侧，识别说话边界）
    │
 [ASR]  语音识别（Speech LLM / 端侧 ASR）→ 文本指令
    │
 [LLM]  语义解析 → 意图 + 参数（复用 R19 指令集）
    │
 [安全门] 操作风险分级：低风险直接执行；高风险 → 语音回读确认 + 附加因子
    │
 [执行]  rf_brain 动作（scanner/decision_layer/spectrum_events 等）
    │
 [TTS]  语音应答（结果回读）
```

- **VAD → ASR → LLM → rf_brain 动作 → TTS**，全链路延迟目标 < 1s（查询类）。
- 意图与参数复用 R19 的 `INSTRUCTION_SET` / `map_text`，LLM 只做语义理解，物理层动作确定性执行。

## 3. 三个语音场景

| # | 语音指令 | 意图 | rf_brain 动作 | 语音应答 |
|---|---|---|---|---|
| S1 状态查询 | "433MHz 现在有干扰吗？" | `detect_interference` | 读取频谱事件缓存/当前干扰源 | "433MHz 检测到 2 个活跃干扰源，主干扰在 433.5MHz" |
| S2 紧急切换 | "紧急切到备用频段" | `emergency_alert` + 切频 | 切换 VFO/跳频策略，提高可靠频点 | "已切换至备用频段，重传 3 次确认" |
| S3 频谱普查 | "扫 430-440MHz 找出占用" | `spectrum_survey` | 宽带扫描 + 占用统计 | "430-440MHz 占用 3 处：431.2、433.5、437.8" |

## 4. 安全设计（声纹警示）

- **声纹不可作高安全身份凭证**（2608.07980）：说话人身份是概率分布，deepfake 可伪造。
- **分级授权**：
  - 查询类（只读频谱状态）→ 低风险，直接执行。
  - 操作类（切频/发射/改功率）→ 高风险，语音回读确认 + 附加因子（按键/一次性口令）。
- **审计**：所有语音指令 + 执行动作 + 确认过程落日志，可追溯。

---

## 5. 落地建议

1. ASR/LLM 用端侧小模型（ESP32 无法本地跑大模型，语音/LLM 放网关或云端，ESP32 只做 VAD + 执行）。
2. 复用 R19 指令集与 R01/R03 的 rf_brain 模块作为动作后端。
3. 安全门做成独立模块，可配置风险阈值。
