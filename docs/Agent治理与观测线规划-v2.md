# Agent 治理与观测线规划 v2 — 计算机比喻定稿：内存/FPU/前庭

> 沈遥 · 2026-10-09 · v1 升级：并入当夜"LLM 之外还缺什么"的架构定稿（用户拍板 OK）
> 比喻总纲：**LLM=CPU、KB=磁盘、VLM=外设；缺的是内存（实时状态）、FPU（确定性计算）、前庭（评估反射）**

## 零、认知架构定稿（本线的世界观）

```
        ┌─ 前庭（评估反射）：知道自己做错了
        │
  LLM ──┼─ CPU：推理决策（已有，够用）
        │
        ├─ 内存（实时状态）：查询即过期的"现在"——frp活吗/GPS在哪/频谱谁在发射
        ├─ 磁盘（KB）：LightRAG+FTS5+22k digest（已有结构，缺语料运营）
        └─ 外设（VLM）：只买两根线——谱图数字化、PCB目检（不为通用看图买单）

  FPU（确定性计算）：UNIFAC/基线校正/DE优化——MCP工具层已有，缺"必须交棒"的路由纪律
```

**原则**：内存与磁盘分流——实时数据进 InfluxDB 永不进 RAG（塞进 RAG 即污染）；KB 的护城河是私有语料（CASE/工单验收/发版事故根因链），不是存储结构。

## 一、前庭（评估反射）——v1 三件套不变，细化

1. **轨迹诊断**（工单227任务一在跑）：trace_diagnose 冻结跳反事实探针；后续接真实 hermes session 流
2. **观测对标**（P1 勘察）：RagaAI Catalyst（16k★ Apache）指标体系 + nanobot（48.9k★ MIT）轻量组织法对照，挑值得引进的指标（token成本/工具成功率/循环检测）
3. **评估闭环**（P2）：每周标准任务组自动跑，成功率/成本/延迟入 InfluxDB；digest 批每轮抽 20 篇人工核对并入
4. **patch 面完整性红线**（v5.2.7 事故沉淀）：凡 patch get_config 类配置函数，核对装配链每层导入来源；CI 干净环境验收（venv 无真 key 必须绿）

## 二、内存（实时状态层）——最大缺口，对接自部署规划波1/波3

- **读写协议**：工具层新增 `now_query`（读当前状态：服务/节点/频谱/位置）与状态谓词——LLM 决策前先看内存，不翻磁盘
- 数据源：Kuma 拨测（服务死活）、Traccar（位置）、ntfy（事件流）、InfluxDB（频谱/LoRa RSSI 时序）
- 验收（gra级）：问"桥还活着吗"→ 秒级回实况而非查记忆；"GPS 最后报点在哪"→ 地图坐标
- 红线：实时流只进 InfluxDB/查询接口，**永不入 RAG 索引**

## 三、FPU（确定性计算交棒纪律）

- 现状：UNIFAC/pybaselines/DE 已在或已在工单弹药里——**弹药不缺，缺纪律**
- 动作：llm_router 增加"禁心算"路由规则：数值计算/物性估算/基线校正类问题 → 强制工具调用，LLM 只解读结果不产数
- 验收：问"乙醇-水 50/50 的活度系数"→ 必须走工具返回带来源数值，content 中不得出现 LLM 编造的小数

## 四、磁盘语料运营（KB 内容管道，零新架构）

- 摄取管道：CASE-26/27 及后续每板 CASE、工单验收实录、发版事故根因链（v5.2.6/7/8 三连）、授粉设计稿 → 自动入 LightRAG
- 记忆手术刀：按 EngramEdit 报告的条件触发更新——高复用条目（被多文档引用）慎改，同义项多别名同改，防记忆污染
- 验收：EDA 知识库端点（PR#229）能答"BTB 错配是什么坑"并引用 CASE 原文——**私有语料开始产生检索价值**

## 五、外设（VLM 两根线，不为通用视觉买单）

- 线1 谱图数字化：论文 Raman/FTIR 曲线图 → 数据点提取入库（云端 glm-4.5v 或本地量化 Qwen-VL，天选7 8GB 只服务这一件事）
- 线2 PCB 目检：版图截图第二意见（丝印/间距/极性），喂过 CASE 库的检索增强目检
- 不做：通用看图/表情包/照片描述——伪需求
