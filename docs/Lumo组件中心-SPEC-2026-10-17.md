## 0 · 现状与缺位（为什么需要组件中心）

WO-251 之后，"**启动**路径"已通（缺什么会带 `reason` 返回）；但"**获取**路径"完全靠人：

- 前端 `apps.ts` 的 `launchLocalApp('neko')` 在 `neko-electron-shell/node_modules/electron/cli.js`
  不存在时只能报"请到组件中心获取"——**而组件中心不存在**；
- `build.md` 的官方口径是「NEKO / neko-electron-shell 属上游独立项目，自行获取」——
  对裸机非技术用户等于劝退（clone 撞墙、还要 `npm install`）。

### 0.1 进包决策（回应用户原问题，三个选项的取舍）

| 方案 | 结论 | 理由 |
|---|---|---|
| 一并打进主安装包 | ❌ | 约 **300 MB** 撞分卷线；上游吃更新就要重发整个主包 |
| 只给提示（现状） | ❌ | 非技术用户 clone 撞墙，最后回到人工喂文件 |
| **App 内组件中心** | ✅ **采用** | 正规软件体验；主包保持轻量；组件可独立更新 |

## 2 · 组件清单 schema（`components.json`）

**位置**：发布态 `dist/components.json`；开发态 `frontend/public/components.json`；
**源**：由运维侧生成并托管（见 §8 开放问题 Q1），App 只读不写。

```jsonc
{
  "schema_version": 1,
  "generated_at": "2026-10-17T00:00:00Z",
  "components": [
    {
      "id": "neko",                          // 稳定标识，与 userData/components/<id>/ 目录同名
      "display_name": "NEKO 桌宠",
      "version": "0.8.3",                    // 取自 neko-electron-shell/package.json
      "size_bytes": 314572800,               // 约 300M（下载前展示 + 磁盘配额判定）
      "license": "Apache-2.0",               // SPDX；解压后必须能找到 LICENSE 文件
      "install_type": "extract_zip",         // 解压即用；另两种预留：installer / portable_dir
      "platforms": ["win32", "darwin", "linux"],
      "architecture": ["x64", "arm64"],
      "urls": [
        { "url": "https://<self-hosted>/lumo/neko-0.8.3-win-x64.zip", "mirror": "primary", "size_bytes": 314572800 },
        { "url": "https://github.com/<org>/<repo>/releases/download/v0.8.3/neko-0.8.3-win-x64.zip", "mirror": "github", "size_bytes": 314572800 },
        { "url": "file:///", "mirror": "manual", "note": "用户从本地选 .zip" }
      ],
      "sha256": "ab12cd34…",                 // 全包校验；未提供则该源作废（见 §7 硬线 3）
      "expected_layout": [
        "neko-electron-shell/package.json",
        "neko-electron-shell/node_modules/electron/dist/electron.exe"   // win；mac 为 .app/Contents/MacOS/Electron
      ],
      "post_install": {
        "must_npm_install": true,            // 壳的 node_modules 上游不打包 ⇒ 需要一次 npm install
        "first_run_hint": "首次启动若报缺 node_modules，按界面引导一键安装"
      }
    }
  ]
}
```

### 2.1 字段硬约束

| 字段 | 约束 |
|---|---|
| `id` | `^[a-z0-9][a-z0-9_-]{1,31}$`；**与磁盘目录名一致**，不可随版本变化 |
| `version` | 语义化；与已装版本比对决定 `installed` / `updated_available` |
| `sha256` | 64 位小写 hex；**每源一份**（多源文件应字节相同，不一致即配置错误，启动自检告警） |
| `urls[].mirror` | 枚举 `primary` / `github` / `manual`；**顺序即回退顺序**，`manual` 必须存在 |
| `expected_layout` | ≥1 条；解压后**逐条 `existsSync`**，缺一即 `corrupted` |
| `size_bytes` | 用于下载前配额判定；与实际下载字节差异 >5% 时告警（可能是清单过期） |

## 3 · 状态机

| 状态 | 触发 | 转换 | UI 文案 / 按钮 |
|---|---|---|---|
| `not_installed` | 首次 / 卸载后 | → `downloading`（点下载）/ → `manual_import`（我有文件） | 「未安装（约 300M）」；【下载】【我有文件】 |
| `downloading` | 用户点下载 | 进度回调；完成 → `verifying`；取消 → `not_installed`；暂停 → `paused` | 进度条 + 速度 + ETA；【暂停】【取消】 |
| `paused` | 用户暂停 | → `downloading`（继续）；→ `not_installed`（取消并清理临时文件） | 【继续】【取消】 |
| `verifying` | 下载完成 | sha256 通过 → `installing`；不通过 → `corrupted` | 「正在校验…」（不可取消，≤30s） |
| `installing` | 校验通过 | 解压 + 探针 + 许可扫描；通过 → `installed`；失败 → `corrupted` | 「正在安装…」 |
| `corrupted` | 校验/探针/解压失败 | → `downloading`（重下）/ → `manual_import`（换文件） | 「文件损坏/结构不符：<具体原因>」 |
| `installed` | 安装完成 | → `updating`（有新版）/ → `uninstalling` | 「已安装 v0.8.3」；【启动】【卸载】 |
| `updating` | 清单 version > 已装 | 下载 → 校验 → 解压到侧目录 → 原子切换 | 「正在更新到 vX」 |
| `uninstalling` | 用户卸载 | 删目录 + 清注册 → `not_installed` | 「正在卸载…」 |
| `manual_import` | 用户选本地 zip | → `verifying`（同一校验链） | 「请选择 .zip 文件」 |

### 3.1 不变量（实现期必须冻结）

1. **禁止静默转换**：每次状态变化都 `appendBackendLog` + `components:progress` 推前端（同源）；
2. **原子安装**：解压先落到 `userData/components/.staging/<id>-<ts>/`，探针通过后**一次 rename** 到位；
   中断只会留下 `.staging`（下次启动清理），**不会出现半个 `<id>/`**；
3. **更新不破坏在跑的实例**：`updating` 期间旧目录保持可用；切换后旧目录改名为 `<id>.old-<ts>` 再删；
4. **失败可归因**：`corrupted` 必须带 `reason` 枚举（`sha_mismatch` / `layout_missing:<path>` /
   `unzip_failed` / `license_missing` / `disk_full` / `http_<code>`）；
5. **配额**：`userData/components/` 总占 ≥ **2 GiB** 时拒绝开始新的下载（提示清理），卸载后释放。

## 4 · 架构

```
┌───────────────────┐   IPC (preload 白名单)   ┌────────────────────────┐
│ Vue 前端          │ <──────────────────────> │ Electron 主进程         │
│ views/ComponentCenter/Index.vue               │ modules/components/     │
│ （列表/进度/引导） │                          │  registry.ts  清单加载  │
└───────────────────┘                           │  downloader.ts 下载/续传│
                                                │  installer.ts 校验/解压 │
                                                │  store.ts     状态持久化│
                                                └───────────┬────────────┘
                                                            │ HTTPS Range / file://
                                                            ▼
                                              ┌──────────────────────────┐
                                              │ 自建 CDN / GH Release /  │
                                              │ 用户本地 zip (manual)     │
                                              └──────────────────────────┘
```

| 模块 | 职责 | 关键决策 |
|---|---|---|
| `registry.ts` | 读 `components.json`；平台/架构过滤；与已装状态合并 | 清单**只读**；解析失败 → 全部组件降级为 `not_installed` 并记日志 |
| `downloader.ts` | `net.request` + `Range` 续传；写 `*.part`；算 sha256 流式 | 并发=1（单组件串行）；超时 30s 无字节即视为失败并切下一源 |
| `installer.ts` | sha256 校验 → 解压 → `expected_layout` 探针 → LICENSE 扫描 | 解压用 `yauzl`（zip）；**拒绝路径穿越**（`..`/绝对路径条目一律拒收） |
| `store.ts` | `userData/components-state.json`：`{id: {version, installedAt, dir, license}}` | 与磁盘**双向核对**：状态说有但目录没了 → 回退 `not_installed` |
| `preload` | 白名单暴露 §5 通道 | 渲染进程**不得**直接拿 `fs`/`net` |

**落点**：组件装在 `app.getPath('userData')/components/<id>/`，**绝不**写入主安装目录（免 UAC / 只读权限问题）。

## 5 · IPC 契约（前端 ↔ 主进程）

| 通道 | 方向 | 请求 | 响应 / 事件 |
|---|---|---|---|
| `components:list` | 渲→主 | — | `{components: [{id, display_name, version, installed_version?, state, size_bytes, license, reason?}]}` |
| `components:install` | 渲→主 | `{id, source?: 'primary'\|'github'\|'manual', localPath?: string}` | `{ok, state}`；`manual` 必带 `localPath` |
| `components:progress` | 主→渲（事件） | — | `{id, state, percent, received_bytes, total_bytes?, speed_bps, eta_s, reason?}`，**throttle 200ms** |
| `components:pause` / `components:resume` | 渲→主 | `{id}` | `{ok, state}` |
| `components:cancel` | 渲→主 | `{id}` | `{ok, state}`（顺带删 `.part`） |
| `components:uninstall` | 渲→主 | `{id}` | `{ok, state}` |
| `components:importLocal` | 渲→主 | `{id, filePath}` | `{ok, state}`（等价 `install` + `source:'manual'`） |
| `components:openFolder` | 渲→主 | `{id}` | `{ok}`（打开 `components/<id>/`，排障用） |

### 5.1 错误码（渲染层据此出文案，不要自己拼字符串）

| code | 含义 | 用户可见文案（建议） |
|---|---|---|
| `E_NO_SOURCE` | 所有源不可达 | 「网络不可用：已尝试自建源与 GitHub，可改用『我有文件』」 |
| `E_SHA_MISMATCH` | 校验失败 | 「文件校验未通过（可能下载不完整），请重试或换源」 |
| `E_LAYOUT_MISSING` | 探针缺条目 | 「压缩包结构不符：缺少 `<path>`，请确认下载的是 NEKO 组件包」 |
| `E_UNZIP` | 解压失败 | 「解压失败：<原因>」（附「打开日志」） |
| `E_LICENSE_MISSING` | 缺 LICENSE | 弹窗：「组件缺少许可证文件，已停止安装」 |
| `E_DISK_FULL` | 磁盘/配额不足 | 「磁盘空间不足（组件上限 2 GiB），请先清理」 |
| `E_BUSY` | 已有任务在跑 | 「另一个组件正在安装，请稍候」 |

## 7 · 验收硬线（WO-254 实现时逐项打钩，本单不出代码）

| # | 项 | 判据 |
|---|---|---|
| 1 | 多源回退 | primary 404 → github → manual 三跳可走通（可用本地 http 桩伪造 404） |
| 2 | 断点续传 | 中断后恢复，从 `received_bytes` 续，**不从头下**（比对服务器 Range 请求日志） |
| 3 | sha256 强校验 | 不通过直接 `corrupted`（`E_SHA_MISMATCH`），**不进入解压** |
| 4 | 探针 | 缺 `expected_layout` 任一条 ⇒ `corrupted` 且 reason 指名缺失路径 |
| 5 | 状态可观察 | 每步都有 `components:progress` + `appendBackendLog`，事件序号单调无跳变 |
| 6 | 许可 | 解压后无 `LICENSE` ⇒ `E_LICENSE_MISSING` 弹窗，**不静默继续** |
| 7 | 手动导入 | 本地 zip 走完整状态机（含损坏文件检测） |
| 8 | 不内嵌主包 | 安装后主安装目录**零新增**；全部落在 `userData/components/<id>/` |
| 9 | 卸载干净 | 删 `<id>/` + store 条目；重装后 SHA 与首装一致（无残留污染） |
| 10 | 磁盘上限 | 伪造到 ≥2 GiB ⇒ 拒绝新下载并提示清理 |
