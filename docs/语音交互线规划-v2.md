# 语音交互线规划 v2 — 三档 VAD/ASR 矩阵

> 沈遥 · 2026-10-09 · 依据：GLM 最后一夜扫货语音维度丰收（15+ 活跃项目）+ voice_mcp 适配器群现状
> v1（口头约定）升级：从"找一个 VAD"升级为"三档矩阵，按端分工"

## 三档矩阵（同一套打断感知接口，三种实现档位）

| 档 | 项目 | ⭐/许可 | 端 | 场景 |
|---|---|---|---|---|
| 云端流式 | **WhisperLiveKit** | 11120 / Apache-2.0 | 天选7/云服 | 完整对话：流式ASR+说话人分离+VAD，陆墨语音前端候选 |
| 嵌入式实时 | **sherpa-ncnn** | 1789 / Apache-2.0 | ESP32-S3/手机 | IC-705 移动核心：离线 ASR+VAD，next-gen Kaldi 全平台 |
| 纯轻量 | **auditok** | 862 / MIT | 任何 Python | 最小依赖兜底：纯 stdlib 音频分段+VAD |

算法参考：whisper_streaming（3673★ MIT）的 LocalAgreement-2——低延迟流式转写为何可行，读它就够。

## 路线

### 第一步 · 打断感知 PoC（P1，等工单227后）
- 用 auditok（零依赖）给 voice 线加"用户说话时拒绝切态"卫兵——参考 cascade 的物理事实优先模式
- 验收：TTS 播放中检测到人声 → 静音/让权，日志留痕

### 第二步 · WhisperLiveKit 勘察工单（P1）
- 浅 clone 定接口：与现有 voice_mcp 适配器的对接层设计
- 说话人分离是多人场景（宿舍/实验室）的刚需，重点勘察其 diarization 延迟

### 第三步 · 移动核心集成（P2，等硬件线）
- sherpa-ncnn 编 ESP32-S3 侧 demo——语音唤醒词+简单指令（"读频率""切换波段"）
- 与 rsba1 语音遥控链路汇合：语音→MCP→CI-V

## 明确不做
- 自训 VAD 模型（生态够用，别造轮子）
- 实时翻译线（WhisperLiveKit 有但非需求）

## 与其他线钩子
- open-webui（自部署波2）如果开语音模式，与本线接口对齐
- 龙雀移动节点若加语音（远期），sherpa-ncnn 是唯一能塞进 ESP32 的档位
