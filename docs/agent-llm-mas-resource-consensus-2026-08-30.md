## 一、问题陈述

多 Agent 系统要达成共识，必须**交换信息**，而信息交换消耗 token/带宽/时间。但"多快达成共识"与"花多少资源"是一对矛盾——现有框架要么只顾收敛速度、要么只顾省 token，缺少**有理论保证的权衡**。

LLM-MAS（2608.25099）首次把 LLM 多 Agent 共识建模为**离散时间切换系统**，并导出 **token-速度权衡证书**；其"共识-资源安全集"框架可泛化到任意 Agent 协调。

## 二、框架设计

### 2.1 资源模型
- 每个 Agent 的资源预算：token 预算、通信带宽、计算时延。
- 共识过程建模为离散时间切换系统：每个时刻 Agent 决定"交换多少信息、多快更新"。
- 状态 = 各 Agent 的意见/信念分布；控制 = 通信量 / 更新步长。

### 2.2 共识协议（资源感知）
- **共识-资源安全集**：把"token 预算"和"收敛速度"编码为安全集约束——在任何时刻，共识更新不得违反资源约束，也不得导致发散。
- **token-速度权衡**：在安全集内，动态选择"多花 token 换快收敛"还是"省 token 换慢收敛"，由任务对时延的敏感度决定。
- **切换拓扑**：通信拓扑可切换（部分 Agent 离线/受限），协议保证在切换下仍收敛。

### 2.3 控制理论背书
- 用 Lyapunov / 切换系统稳定性证明共识收敛；
- token-速度权衡证书给出"给定预算，最快多快能收敛"的保证。

## 三、框架文档要点（交付结构）

1. **资源模型**：Agent 资源预算（token/带宽/时延）形式化定义。
2. **共识协议**：共识-资源安全集 + token-速度权衡 + 切换拓扑下的更新规则。
3. **理论保证**：收敛性 + 权衡证书。
4. **落地路径**：应用到分布式 SDR 感知网络（多 ESP32+SDR 节点协调，见 digest 授粉点 ②）。
