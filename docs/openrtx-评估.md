# OpenRTX 评估（W71-10）

> 上游：mirrors/openrtx（Gitee，4★，C/C++）｜ <https://gitee.com/mirrors/openrtx>（上游真身在 GitHub openrtx-dev）
> 许可：GPL-3.0（仅参考设计）

## 1. 项目定位

开源**数字业余无线电固件**——替代 DMR / D-STAR / System Fusion 等私有数字模式固件，跑在业余电台
硬件（如 Tytera MD-380/MD-UV380 等）上，实现开放的 DMR 协议栈。

## 2. 架构拆解

- **分层协议栈**：射频前端 → 基带（DMR 调制解调）→ 协议层（呼叫/注册/数据）→ 用户界面。
- **硬件抽象层（HAL）**：跨电台平台的可移植抽象（屏幕/按键/RF 芯片）。
- **RTOS + 实时调度**：语音实时性要求下的任务调度。

## 3. 与本仓对照

| 维度 | OpenRTX | 本仓 |
|---|---|---|
| 数字模式 | DMR 等私有协议开源实现 | 泉盛 UV-K6 + 业余数字模式方向 |

**「数字 vs 模拟」边界结论（验收项）**：数字模式（DMR）带来清晰语音 + 更多数据能力，但协议栈复杂度高、
依赖特定硬件；模拟（FM）简单成熟。**OpenRTX 的价值在「开源数字模式协议栈」参考，UV-K6 是否支持需
核对芯片（UV-K6 为模拟为主，数字需硬件支持）**，不能直接照搬。

## 4. 可落地借鉴点（≥3）

1. **数字模式协议栈分层**：射频→基带→协议→UI 的分层，借鉴给业余数字模式立项的架构设计。
2. **硬件抽象层（HAL）**：跨电台平台的可移植抽象，借鉴给多型号电台固件（含 UV-K6）的移植层。
3. **实时语音任务调度**：RTOS 下语音低延迟调度，借鉴给对讲/语音相关模块。

## 5. 许可裁定

GPL-3.0——**只参考设计不融合**；协议栈分层与 HAL 思想可借鉴，代码不并入（GPL 传染）。

## 6. 结论

设计参考级。建议：仅登记；业余数字模式立项前先核对 UV-K6 硬件能力（数字模式需射频/基带芯片支持），
OpenRTX 作协议栈架构参考。
