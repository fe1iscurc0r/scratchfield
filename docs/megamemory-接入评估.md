# MegaMemory 项目级语义搜索接入评估（W99-04 · Lumo TS 侧候选）

> 2026-09-08 · 上游：0xK3vin/MegaMemory（MIT，★541，TypeScript，项目级语义搜索 + web 扩展）

## 一、架构拆解

- 索引：项目文件 → 向量化索引（项目级语义搜索，TS 生态）。
- 检索：语义查询 → 相关代码片段。
- 扩展：web 扩展界面（浏览器内搜索项目）。
- 形态：TS 库/服务（Lumo 前端同栈）。

## 二、与本仓关系判定（memory_maas / memclaw）

| 维度 | memory_maas（已有） | memclaw（已有） | MegaMemory |
|------|--------------------|-----------------|-----------|
| 对象 | typed 记忆实体（decision/insight…） | 代码库记忆 | 项目文件语义索引 |
| 检索 | 混合检索（向量+图谱） | 代码检索 | 文件级语义检索 |
| 语义搜索 | ✅ 已覆盖 | ✅ 部分 | 重叠 |
| TS 生态 | Python | — | ✅ TS |

**判定：冲突为主、局部补充**——「语义检索」维度与 memory_maas 混合检索重叠；
其增量仅在「Lumo TS 前端直连的项目文件索引」细分位，价值不足以引入整套 TS 依赖。

## 三、接入方案（若接入）

- 落点：Lumo TS 侧独立服务（不并主仓 Python 记忆栈）。
- 步骤：npm 安装 → 索引目标项目 → 前端接入检索 API。
- 工作量：1~2 天（TS 构建 + 前端对接），超过「≤1 天」门槛。

## 四、结论

**不接入（冲突为主，仅参考）**：语义检索与 memory_maas 重叠；TS 服务引入双栈维护成本。
- 保留：若未来 Lumo 前端需「浏览器内项目文件语义搜索」细分能力，再单独立项。
- 本工单按方案交付，不落地代码。
