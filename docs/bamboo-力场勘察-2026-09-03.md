## 〇、一句话定位

BAMBOO 是字节 AI 团队的 AI-driven 分子力场（equivariant GNN 路线），专为**电解质模拟**设计（电化学精度/效率见长），与 deepmd-kit 同类但电解质专项。对陆墨线的价值点在于：电解质/电化学体系是生物质能源材料与电池材料的关键场景，而通用力场（deepmd-kit/SevenNet）在此专项上未必有针对性调优。

## 二、三条接入路径评估

1. **直接用作电解质模拟后端（外部进程隔离）**——把 BAMBOO 作为独立进程/服务调用（subprocess/REST），陆墨线只通过 API 传结构、收能量/力。价值最高、风险可控，但需承受 GPL-2.0 的进程级隔离约束（见第四节）。**结论：可行，但必须进程隔离。**

2. **参考架构自建轻量力场**——只读其 equivariant GNN 设计思想（消息传递/等变特征），用独立代码重写一个轻量力场，进 Apache/MIT 模块。无传染风险，但工程量最大、精度需自己调。**结论：中期方向，非本批落地。**

3. **仅作论文/知识储备**——登记为待评估候选，不接入。零风险，但对材料线无直接产出。**结论：保底选项，与 1/2 并行。**

## 三、GPL-2.0 传染性分析 + 隔离方案

- **传染性**：GPL-2.0 是 copyleft——任何「链接/合并/派生」GPL-2.0 代码的作品，分发时必须整体以 GPL-2.0 开源。且 **GPL-2.0-only 与 GPL-3.0/AGPL-3.0 是不同世代，不兼容**（不能合并成单一作品）。
- **对主仓的后果**：主仓是 AGPL-3.0，AGPL-3.0 可吞 GPL-3.0，但**不能直接吞 GPL-2.0-only**。因此 BAMBOO 代码绝不能 import/复制进主仓或 Apache/MIT 模块。
- **隔离方案（三条）**：
  1. **进程隔离**：BAMBOO 独立进程运行，主仓通过 subprocess/REST 传参调用——保持「mere aggregation（简单聚合）」边界，不构成派生作品。
  2. **接口层隔离**：只在主仓写一个「力场调用适配器」（纯协议，不含 BAMBOO 代码），GPL 代码永远在适配器之外。
  3. **数据/模型隔离**：BAMBOO 的预训练权重属其自身，不随主仓分发；主仓只分发「调用脚本 + 使用说明」。
