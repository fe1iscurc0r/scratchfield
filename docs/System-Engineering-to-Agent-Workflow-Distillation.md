# 系统工程 → Agent 工作流蒸馏

> 来源：系统工程学课程 7 章 40 节 + 现有 skill 库 182 个盘点
> 蒸馏：2026-08-12
> 目的：把系统工程从"思维体操"落成 agent 系统的四维操作准则

---

## 一、内核提纯：四个原则

7 章内容归根结底是四个不变的原则。这是母体，其余全是投影。

| # | 原则 | 系统工程的表述 | 一句话 |
|---|------|--------------|--------|
| P1 | **关系 > 元素** | 整体性、相关性 | 系统的灵魂是关系，不是元素；元素可换，关系才定义系统 |
| P2 | **层次性** | 系统分解为子系统，也被更大系统包含 | 任何系统都可分层，关键是选对抽象层操作 |
| P3 | **边界** | 系统边界、开闭系统 | 划清边界是分析的第一刀，边界错，后面全错 |
| P4 | **目的性 + 适应性** | 目标协调、环境适应 | 系统有目的，多目标需协调；适应变化才能生存 |

---

## 二、四维映射：16 条操作准则

四个原则 × 四个子系统 = 16 条可直接执行的操作准则。

### 维度 1：记忆（Memory）

| 原则 | 操作准则 | 现状 |
|------|---------|------|
| P1 关系>元素 | **记关系，不记事实**。记忆应是图结构，不是扁平列表。孤立条目是死元素，关联才有涌现（推理） | 现有 memory 工具是扁平的 declarative 条目，缺图结构 |
| P2 层次性 | **分层记忆**：工作记忆（会话上下文）/ 会话记忆（session_search）/ 长期记忆（memory）。不同层不同生命周期、不同访问成本 | 已有三层，但分层标准靠自觉，未固化 |
| P3 边界 | **记忆范围界定**：该记的记，不该记的不记。不存任务进度、易失信息——存了就是污染 | memory 工具原则已隐含，但未系统化 |
| P4 目的性+适应性 | **面向用途存储 + 遗忘机制**：存什么取决于"未来什么场景会用到"；不相关信息应衰减，遗忘是适应性不是缺陷 | 缺遗忘/衰减机制 |

**结论**：记忆层的最大缺口是 **P1（图结构）+ P4（遗忘衰减）**。这正是 GitHub 上 engram/mentedb/kektordb 在做的事——记忆是图不是表，有时间衰减和矛盾检测。

### 维度 2：效率 / 省 token

| 原则 | 操作准则 | 现状 |
|------|---------|------|
| P1 关系>元素 | **压缩 = 保留关系、丢弃冗余元素**。token 大部分是修饰性冗余，真正承载推理的是"论点间的关系"。压缩目标是关系保真 + 元素降噪 | headroom 已做，但目标是"删字数"还是"保关系"未明确 |
| P2 层次性 | **在语义层压缩**，不在字符层。摘要（语义）> 截断（字符）。双层管线 L1提事实/L2推理 就是层次性 | hermes-dual-pipeline 已体现 |
| P3 边界 | **省 token 第一刀是划边界**：什么根本不进上下文。把无关工具输出挡在边界外，比压缩它更省 | 缺"上下文边界"的显式规则 |
| P4 目的性 | **面向推理取舍**：这个 token 对当前推理有没有用？不是所有 token 平等，有些在"关键路径"上 | 缺 |

**结论**：省 token 的最大缺口是 **P3（先划边界再压缩）**。压缩是治标，边界是治本——大部分 token 浪费发生在"不该进的东西进来了"。

### 维度 3：计划（Planning）

| 原则 | 操作准则 | 现状 |
|------|---------|------|
| P1 关系>元素 | **先定依赖，再排任务**。关键路径（CPM）决定总工期，优化关键路径才有效。任务的价值由它在上游/下游的依赖决定 | kanban-orchestrator 有分解，但缺关键路径识别 |
| P2 层次性 | **三维建模**：霍尔三维结构 = 时间维（阶段）× 逻辑维（步骤）× 知识维（领域）。不是一维任务列表 | plan/writing-plans 是一维，缺三维 |
| P3 边界 | **先定义问题，再求解**。软系统方法论七步法处理"不良结构问题"——问题本身都不清楚时，先 rich picture 再根定义 | plan 缺"问题是否良结构"的前置判断 |
| P4 目的性 | **目标对齐优先于任务拆分**。多目标冲突时，先协调目标再排任务 | 缺 |

**结论**：计划层的最大缺口是 **P2（三维建模）+ P3（不良结构问题前置判断）**。现有 plan 是一维任务列表，系统工程给的是"阶段×步骤×领域"的立体模型 + 先辨问题类型的门槛。

### 维度 4：协调（Orchestration）

| 原则 | 操作准则 | 现状 |
|------|---------|------|
| P1 关系>元素 | **先定接口，再定实现**。多 agent 协调靠接口契约，不靠共享状态。接口清晰，各 agent 独立演化 | multi-system-integration/Lumo-Bus 已体现 |
| P2 层次性 | **分层协调**：决策层/执行层分离，跨层调用有明确通道。职责单一、可独立替换 | hermes-three-layer-deploy 已体现 |
| P3 边界 | **职责边界**：每个 agent 只做边界内的事，越界即失控。蜜罐层/执行层/决策层职责隔离 | 已有，但边界随任务膨胀会模糊 |
| P4 目的性 | **目标对齐 + 综合集成**：人机结合（人定方向、机执行），多 agent 目标冲突时从系统整体找折中 | 已有（用户定方向+执行侧写码+实验田维护者review） |

**结论**：协调层四原则基本都有落地，最成熟。真正要补的是 **P3 职责边界的动态维护**——边界会随任务膨胀而模糊，需要显式的"越界检测"。

## 三、动力学层：让系统「活着」的五个概念

> 第二节是结构层（怎么切分静态系统）。系统论更深的内核在动力学层——系统怎么随时间演化、怎么维持稳定、怎么涌现出设计者没预料到的东西。

### 核心洞察：结构 → 行为 → 功能，三者脱节

- **结构**：元素和关系（静态，可设计）
- **行为**：结构在时间上的展开（动态，难预测）
- **功能**：系统对外的价值（涌现，不可控）

改了 prompt（结构），输出（行为）可能完全出乎意料——非线性。
设计了多 agent 协同（结构），会涌现出没预料到的行为（功能）。
**这就是「控制即毁灭」的理论基础：复杂系统不可控，只能引导。**

### 五个概念 × 对 agent 的启示

| 概念 | 系统论表述 | 对 agent 的启示 | 落地点 |
|------|-----------|----------------|--------|
| **反馈** | 负反馈=稳态，正反馈=失控 | 负反馈=自纠错；正反馈=幻觉放大、错误累积 | 质量反馈回路（缺） |
| **涌现** | 整体 > 部分之和 | 多 agent 的价值在涌现，风险也在涌现 | 涌现可观测性（缺） |
| **熵增** | 封闭系统走向混乱 | 不维护就退化：记忆污染、skill 过时、代码屎山 | 定期蒸馏清理（部分） |
| **稳态** | 扰动后回平衡 | 容错 + 自愈 + 降级 | API 降级 L1（已做） |
| **自组织** | 自发形成结构 | 让系统自己长结构，别全人肉设计 | skill 自进化（缺） |

### 最反直觉的两条

1. **遗忘是适应性**（P4 延续）：记忆系统要活得久，必须会遗忘。熵增的反面是持续投入能量维持低熵——这就是为什么 skill 不维护会变负债，memory 不整理会变污染。

2. **涌现不可控**：你无法「设计」涌现，只能设计「让好的涌现更容易发生」的条件。控制论（cybernetics）的结论——复杂系统只能引导，不能控制。这与「连接即正义，控制即毁灭」同源。

## 四、缺口汇总

| 维度 | 最成熟原则 | 最大缺口 |
|------|----------|---------|
| 记忆 | P2 分层 | P1 图结构 + P4 遗忘衰减 |
| 省 token | P2 层次压缩 | P3 先划边界再压缩 |
| 计划 | P1 依赖（部分） | P2 三维建模 + P3 问题类型判断 |
| 协调 | P1/P2 接口分层 | P3 职责边界动态维护 |

## 四、落地路径

### 近期（直接可做）

1. **`system-thinking` 母 skill**：承载四原则内核，作为启动任何复杂任务的前置过滤器。内容是一组触发问题：
   ```
   1. 边界：包含什么？排除什么？环境是什么？
   2. 层次：在哪个抽象层操作？上下移一层的代价？
   3. 关系：关键接口/依赖是什么？换掉某元素，系统还成立吗？
   4. 涌现：整体目标是什么？哪几个元素协同才产生它？
   5. 目的：有哪些目标？冲突吗？折中点在哪？
   ```

2. **记忆图结构**：评估 engram/mentedb 接入，把 memory 从扁平条目升级为图结构 + 遗忘衰减。

3. **上下文边界规则**：给 headroom/context_compressor 加"边界前置"——先判断什么不进上下文，再压缩进来的。

### 中期（选做）

4. **计划三维建模**：把 plan skill 从一维升级为「阶段×步骤×领域」+ 关键路径识别。

5. **职责边界监控**：给多 agent 体系加"越界检测"——哪个 agent 在膨胀边界。
