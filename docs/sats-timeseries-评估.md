# K22 SATS 时序基础模型评估

## 0. 结论速览

SATS 的时序基础模型通过两点拿到「效率 +65.6%」：

1. **多尺度 patch token**：把时序切成不同长度的 patch（短 patch 捕捉细节、长 patch 捕捉趋势），作为不同尺度的 token；
2. **token 对齐 + 混合掩码**：跨尺度对齐 token（让不同尺度的 token 指向同一时间区间），并用混合掩码（随机掩码 + 跨尺度一致性掩码）做自监督预训练。

对 rf_brain 频谱时序（频谱事件序列、信道占用/状态序列）的启示：频谱事件天然多尺度——**突发干扰是短尺度、信道占用的昼夜/业务趋势是长尺度**。现有单一窗长的时序特征会顾此失彼，多尺度 patch 直接对症。

## 1. 方法拆解

| 环节 | 做法 | 对应频谱场景 |
|---|---|---|
| 多尺度 patch | 同一序列按多个 patch 长度切分，各自成 token | 突发（短窗）/趋势（长窗） |
| token 对齐 | 不同尺度的 token 对齐到同一时间区间，跨尺度可交互 | 干扰事件 ↔ 信道状态对齐 |
| 混合掩码 | 随机掩码 + 跨尺度一致性掩码，预训练表征 | 从掩码频谱重建完整事件流 |
| 效率来源 | 多尺度对齐减少冗余 patch，混合掩码提升预训练样本效率 | 少训练、少推理开销 |

## 2. 对 rf_brain 频谱时序的适配评估

- **适配度：高**。频谱事件/信道状态是典型多尺度时序（ms 级突发 vs 小时级趋势），且标签稀疏，自监督预训练收益大。
- **落点**：`mcpserver/rf_brain/spectrum_events.py` / `scanner.py` 的时序特征层，可替换为多尺度 patch 表征。
- **约束**：端侧（ESP32）需控制 patch 尺度的 token 数与注意力开销，可配合 K18 的 Relation Mixer 做局部混合。

## 3. 落地建议（≥3）

1. **多尺度 patch 特征层**：rf_brain 频谱时序特征改用「短(ms)/中(s)/长(min)」三尺度 patch + 对齐，作为下游（异常检测、占用预测）的统一输入。
2. **混合掩码自监督预训练**：用「随机掩码 + 跨尺度一致性掩码」在无标签频谱历史上预训练，再微调到异常检测/事件分类，缓解频谱标签稀疏。
3. **效率预算表**：按 SATS 的 65.6% 效率口径，在 rf_brain 上做 patch 尺度/掩码率的消融，量化「训练样本数/推理 FLOPs」的节省，作为端侧部署的依据。
