> 日期：2026-08-30

## 一、问题陈述

LLM 生成代码后，最常见的验证方式是**采样验证**：跑几个测试用例，通过了就认为代码正确。论文（2608.17956）证明这是危险的——它给出了精确的数学因子 **`(1-r)^N`**：

- 若某条规则在采样中出现概率为 r（"被省略的模式"），跑 N 个采样用例后**漏检该规则的概率是 (1-r)^N**。
- 关键案例：GPT-5.x 能修复省略的 **1D 夹具**（该规则在采样中易被触发），但在 **2D 区域上没有任何 artifact 能恢复该规则（0/156）**——因为该规则在采样里几乎不出现，采样验证永远测不到。

结论：**"采样验证通过"只认证了样本一致性，不等于代码真的正确**。对任何基于代码生成的 Agent（软件工程、自动化设计、SDR 物理层代码）都是必须上护栏的理由。

## 二、护栏设计：物理规则恢复检查

核心思路：**用"物理规则的可恢复性"作为采样验证的补充护栏**，专门拦截"采样里测不到、但物理上必须成立"的约束。

### 2.1 危险因子量化
对每个待验证规则 R，估计它在测试采样中出现的概率 r，计算漏检因子 `(1-r)^N`：
- 若 `(1-r)^N` 高于阈值（即漏检概率高），说明**该规则在采样里是"稀有模式"**，常规采样验证不可信，必须强制触发规则恢复检查。

### 2.2 规则恢复检查器（Guardrail Module）
- 维护一份**物理/领域不变量清单**（例如 2D 区域的面积守恒、边界连续性、物理单位一致性、不可穿越约束等）。
- 对生成的代码产物，用**结构化检查**（而非采样）逐条验证不变量：
  - 静态检查：代码/产物是否显式实现了该不变量；
  - 语义检查：产物在代表性极端输入下是否违反不变量（构造性反例搜索，而非随机采样）。

### 2.3 危险案例警告
当 `(1-r)^N` 高且规则恢复检查失败时，输出**明确警告**：
```
[GUARDRAIL] 规则「2D 区域不可恢复规则」漏检因子 (1-r)^N = 0.99（危险）
            → 采样验证未覆盖该规则，且恢复检查失败。
            → 阻止交付，需人工/构造性修复。
```

## 三、护栏模块骨架

```python
from dataclasses import dataclass

@dataclass
class Rule:
    name: str
    occurrence_prob: float   # r：规则在采样中被触发的概率
    checker: callable        # 结构化/构造性检查函数

def guardrail(rules, artifact, N):
    issues = []
    for r in rules:
        miss = (1 - r.occurrence_prob) ** N    # 漏检因子
        if miss > THRESHOLD:                    # 稀有模式，采样不可信
            ok = r.checker(artifact)
            if not ok:
                issues.append(f"[GUARDRAIL] {r.name} 漏检因子={miss:.3f}(危险) → 恢复检查失败")
    return issues  # 非空则阻止交付
```

## 四、危险案例测试

| 案例 | 规则 | 采样结果 | 护栏结果 |
|---|---|---|---|
| 2D 区域不可恢复规则（论文 0/156） | 面积/边界连续性 | 采样全通过（假阴性） | 漏检因子高 + 检查失败 → 拦截 |
| 1D 夹具省略 | 可被采样触发的规则 | 采样能触发 | 漏检因子低 → 采样验证可信 |
| 单位/量纲不一致 | 物理单位一致性 | 采样测不到 | 构造性检查失败 → 拦截 |

**验收判据**：护栏能拦截"采样全通过但物理上错误"的案例（尤其是 2D 区域类稀有规则），同时不误伤采样可信的常规案例。
