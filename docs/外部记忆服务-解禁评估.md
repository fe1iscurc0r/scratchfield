## 一、对照矩阵（能力 vs 已有记忆栈）

| 服务 | 核心能力 | 与现有栈重叠 | 补缺价值 | 结论 |
|------|---------|-------------|---------|------|
| **mentedb**（Apache-2.0，Rust） | 写入期智能：质量过滤/去重/矛盾检测/实体图谱，32 工具 | 🔴 高重叠：实体图谱≈summer_memory 五元组；质量过滤≈SPEC-03 lifecycle 置信度+compaction_v2 摘要门控 | 低（理念已吸收，再装一套记忆引擎是重复造轮子） | **不启用**。参考其"写入期智能"理念即可（SPEC-03 已落地等价物） |
| **arcrift**（MIT，SQLite+Ollama） | 编程跨会话记忆：捕获对话→知识图谱→按需注入 | 🟡 部分重叠：summer_memory 是通用记忆；arcrift 专攻"编程/开发会话"场景 | 中-高：scratchpad 缺"编程上下文记忆"专用层；Hermes 会话记忆不跨项目 | **暂缓启用**：需 node 构建 server.js + Ollama（云服有 Ollama v0.5.7，node 可用）；但价值需真机场景验证（用户日常写码时才有收益）。列为 P2 观察项 |
| **swarmvault**（MIT，Node≥24） | LLM Wiki + 知识图谱 + RAG | 🟡 与 graphify（W-03，智能体B在做）+ RAG 重叠 | 低 | **不启用**。W-03 graphify 已覆盖知识图谱方向 |
| **toolbox-postgres**（Apache-2.0） | PostgreSQL 查询 MCP | 🟢 无重叠（我们没有 PG 数据底座） | 取决于 W-09：若 academic 数据落 PG 则启用 | **P3 待命**：W-09 落地后按需启用 |
| **apify**（MIT，托管） | 网页抓取/搜索/8000+ Actor | 🟡 与已有 spiderfoot/shodan bridge 部分重叠（情报侧） | 中（通用网页抓取是日常高频） | **暂缓**：需 APIFY_TOKEN（付费），个人用途性价比低 |
| **hamlog**（自研桥） | QSO/QSL 日志桥 | 🟢 无重叠（自研独有） | 高（业余无线电刚需） | **启用候选**：真机（天选7 HamLog）在场时启用 |
| **llm4decompile**（自研桥） | 本地反编译 MCP | 🟢 无重叠 | 高（逆向 RS-BA1 主用） | **启用候选**：云服装 GGUF 模型后启用（需 ~1GB 模型下载） |

## 二、结论

1. **本轮不启用任何外部记忆服务**——mentedb/swarmvault 与现有栈重复，arcrift 价值待真机验证
2. **两个自研桥（hamlog/llm4decompile）是启用候选**，但它们不是"外部服务"，等真机/模型就绪
3. **arcrift 列为观察项**：用户日常写码场景出现"编程上下文丢失"痛点时，先于启用做概念验证
4. 原则保持：**每加一个外部服务都在扩大信任面/攻击面**，宁可少而精
