## 二、核心数据结构共鸣（附源行号）

1. **注册即台账首条目**：源在 `bootstrap.go:60-68` 构造 BootstrapRequest 并发送至 `DeviceHubServer:DeviceHubPort`；本探针的 `MockDeviceHub.upsert` 把注册条目写成台账记录（device_id/status/bootstrap_at），与 W102-07 台账 schema 的 registered_at/status 字段一一呼应。
2. **心跳载荷 = 固定状态字段集**：源 checkIn（`api.go:121`）周期性上报并从 hub 拉取 agent 元数据；本探针心跳固定 `{cpu_percent, mem_percent, status, ts}` 四字段，中心侧更新 `last_seen/status`——与台账「最后交互」列同构。
3. **清单/命令分通道落账**：源把清单分成 system/ports/docker 多类（`inventory.go:63-130`）；本探针单类 `facts` dict + 命令记录 `last_cmd`，为台账的能力/配置字段留了语义位。

## 三、难度 × 收益

- 难度：★★☆（本地字典模拟 hub，约 100 行 + 3 测试）
- 收益：★★★（台账「设备主动上报」机制从无到有：ESP32 网关/树莓派可复用本骨架自报身份与状态）

## 四、结论与接入建议（≥3）

1. **ESP32 网关 / 树莓派部署形态**：本探针语义可直接译成 MicroPython（ESP32，心跳 60s）或树莓派 systemd 服务（Python，附加 system inventory）；设备 ID 用 flash 唯一 ID/机器序列号派生，替换 `_derive_fingerprint` 占位。
2. **与台账 schema 对齐**：心跳四字段进 `devices` 表（cpu/mem/status/last_seen），见 W102-07 schema 草案，两文件字段名保持一致。
3. **bootstrap 守备语义保留**：生产实现必须在缺密钥/缺服务器 CA 时报错不静默（对照 bootstrap.go:53）——本探针已把该语义写成测试硬线。
4. **canonical/iot-agent 参考边界**：其 snap 自升级/断言体系可参考设计，不可抄代码（GPL-3.0）——本批仅记录概念，不落地。
