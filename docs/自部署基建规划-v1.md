# 自部署基建规划 v1 — 从"工具散装"到"态势一屏"

> 沈遥 · 2026-10-09 · 依据：跨社区扫货核验（docs/pollination/batches/GitHub扫货-GLM最后一夜-2026-10-09.md + 本轮 24 候选 gh api 实测）
> 目标机：天选7 Pro（RTX5060 8GB / 1TB，主存储）+ 云服 43.155.165.80（前哨站，只放轻服务）

## 为什么现在做

三条已有主线都缺"基建层"：语音线缺统一门面、传感器线缺中枢与可视化、告警线缺独立探针。这些恰好是自部署社区最成熟的部分——高星、许可干净、Docker 一键，不需要自研。

## 分四波（每波独立可用，不互相阻塞）

### 波1 · 告警升级（云服，~30 分钟）
- **ntfy**（35k★ Apache-2.0）：单二进制，推送第三通道。手机装 app 订阅 topic，cron 告警从"微信4附件截断"解放
- **Uptime Kuma**（92k★ MIT）：拨测云服全线（frp/桥/qqbot/weixin/cron/http_share:18188），状态页外发
- 验收：拔掉桥进程 → 30s 内 ntfy 推送到手机 + Kuma 状态页变红

### 波2 · 本地模型门面（天选7，~1 小时）
- **open-webui**（154k★，自定义BSD型，自部署无碍）：接 Ollama v0.5.7（云服）+ 天选7本地模型双后端
- 价值：手机/平板浏览器直接用本地模型；多模型路由对照（与陆墨 llm_router 互为参照）
- 验收：手机浏览器出模型对话；切换后端不掉线

### 波3 · 定位与时序（云服+天选7）
- **Traccar**（7.9k★ Apache-2.0）：GY-NEO6M 的服务端。龙雀移动节点 GPS 回传 → web 地图/轨迹/geofence 现成
- **InfluxDB + Grafana**（MIT/AGPL）：rf_brain 频谱数据、LoRa RSSI/SNR、通联日志的时序库+面板
- 验收：NEO6M 模块发一条 NMEA → Traccar 地图出点；rtl_fm 采集 10 分钟 → Grafana 出频谱瀑布图

### 波4 · 照片与存档（天选7，较重）
- **Immich**（116k★ AGPL，自部署无风险）：手机自动备份→1TB，AI 人脸/场景搜索跑 5060
- **ArchiveBox**（29k★ MIT）：扫货报告引用页面防失效存档
- 验收：手机拍 3 张照 → Immich 自动入库且能按场景搜；存档箱回放出 30 天前的引用页

## 明确不做
- nocodb（自定义许可+价值重叠）、Gogs/gitea（已有双远端）、vaultwarden（暂无需求）、Nextcloud（重且与 http_share+1TB 直连重叠）

## 与主线的钩子
- ntfy topic 命名纳入现有告警语义（bridge/fmd/cron 三类）
- Grafana 面板数据源对齐 rf_brain 输出格式（先定 ndjson schema，工单227 任务二产出的观测日志格式直接复用）
- Traccar 设备 ID 与龙雀节点编号同源（W79 线命名规范）
