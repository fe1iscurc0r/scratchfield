## 〇、先纠正工单的一个说法

工单称 RASPA3 为「Fortran 重件」——**实测不成立**：RASPA3（3.1.0）是 RASPA 的
**C++ 重写**（`src/raspakit/`、`src/symmetrykit/`、`src/foundationkit/` 三个 C++ 库，
`json.ixx` 为 C++20 module）。**Fortran 属于 RASPA 2.x 老代码**。这反而降低了接入
难度（C++ 生态比 Fortran 友好），但「重件」结论不变（构建链要求新）。

## 一、构建体系（实测 `CMakeLists.txt`）

```cmake
cmake_minimum_required(VERSION 4.3.0)     # ⚠️ CMake 4.3+（2026 年新发布，要求很激进）
project(raspa3 VERSION 3.1.0 LANGUAGES CXX)
```

- **C++20 module**（`src/foundationkit/json.ixx`——ixx 即 MSVC 的 module 接口单元）
  → 需要**最新编译器**（MSVC 2022 17.10+/Clang 16+，且 CMake≥4.3）
- 模块化结构：`app/`、`benchmarks/`、`data/`、`docs/`、`examples/`、`packaging/`
  各自带 CMakeLists（**分层清晰，可只构建主程序**）
- 云服勿编译结论维持：CMake 4.3 + C++20 modules 的工具链要求高，编译验证需专门环境

## 二、GCMC 输入文件 schema（实测 `examples/advanced/1_mc_gibbs_co2/`）

**RASPA3 用 JSON 输入（对比 RASPA2.x 的 def 文本格式——现代化重写的一部分）**，
一个模拟目录 = **三个 JSON 协同**（三段式确认）：

| 文件 | 角色 | 关键字段（实测摘录） |
|---|---|---|
| `simulation.json` | 模拟控制 | `SimulationType: MonteCarlo`；`NumberOf{Initialization,Equilibration,Production}Cycles`；`Systems[]`（Box: BoxLengths/ExternalTemperature/ChargeMethod: Ewald/GibbsVolumeMoveProbability）；`Components[]`（Name + 各类 Move 概率 + `CreateNumberOfMolecules`） |
| `force_field.json` | 力场 | `MixingRule: Lorentz-Berthelot`；`TruncationMethod: shifted`；`CutOffVDW: 12.0`；`CutOffCoulomb: auto`；`PseudoAtoms[]`（name/element/mass/charge/**source 引用文献**） |
| `<分子>.json`（如 `CO2.json`） | 分子定义 | 分子构型与原子类型引用 |

示例场景：Gibbs 系综 CO2 吸附（双 Box + CFCMC 概率 + Widom + 热力学积分）。

## 三、与 gRASPA（卷79 立项）的接口差异表

| 维度 | RASPA3（本报告） | gRASPA（卷79 立项，100★ MIT） |
|---|---|---|
| 定位 | **CPU 正统**：Amsterdam/Eindhoven/Delft/Northwestern 合作开发（2022–2026 活跃） | **GPU 加速**：RASPA 的 CUDA 重实现 |
| 输入格式 | **JSON 三段式**（simulation/force_field/molecule） | 兼容 RASPA 2.x 输入（文本 def） |
| 语言/构建 | C++20（modules）+ CMake ≥4.3 | CUDA C++ |
| 采纳建议 | 轮25 已定「CPU 正统 + GPU 加速」双引擎——**两者输入不互通**，双引擎各自的 wrapper 需分开做 | |

## 四、木质素碳力场定制入口（实测）

入口 = `force_field.json` 的两处：

1. **`PseudoAtoms[]`**：每个伪原子 `{name, element, mass, charge, source}`——
   木质素碳的 bead/原子类型在此**增补**（`source` 字段强制写文献出处——力场溯源纪律内建）
2. **`MixingRule` / `CutOff*`**：交叉作用规则与截断——木质素碳特有的
   sp²/sp³ 混合位点的 LJ 参数经 Lorentz-Berthelot 组合，无需改代码

配套的分子定义（`<分子>.json`）与框架（framework）结构化输入均在 `data/molecules/`、
`data/forcefields/` 有内置样例（实测 `data/molecules/example_definitions/co2.json` 等 6 个）。

**与 gRASPA 的分工**：若做木质素碳力场，建议在 RASPA3（CPU）侧定制并验证，
验证后的力场 JSON 可同时供 gRASPA（GPU）做大规模筛分——**力场 JSON 是双引擎的
通用交换格式候选**（gRASPA 若支持 JSON 输入则可复用；否则需转译层）。
