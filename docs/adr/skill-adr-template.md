# Skill ADR 模板 · 2026-09-02

> 授粉自 mattpocock/skills（245k★ MIT）：用 ADR 记录 skill 架构决策，演进留痕。
> 使用时机：新增/重构/合并/废弃一个 skill，或 skill 与外部系统（插件分发/配置依赖）交互方式变化时。
> 文件命名：`<序号>-<简述>.md`，放 `docs/adr/`。

## 模板

```markdown
# [决策标题]

日期: YYYY-MM-DD
状态: 提议 / 已接受 / 已替代 / 已废弃

## 背景

[为什么做这个决策——现状、痛点、触发因素。一句话说清"不改会怎样"]

## 决策

[选择什么，一句话。拒绝什么，一句话。]

## 硬依赖 vs 软依赖（mattpocock 授粉点）

- **硬依赖**：没有 X 输出就是错的，不是模糊。skill 必须显式写"如果未提供 X，先运行 <setup>"。
- **软依赖**：没有 X 只是输出不够精准，skill 仍可用。只做模糊引用，不写强指针。

拆分目的：软依赖 skill 保持 token 轻量，不把 setup 指针复制到不承重的地方。

## 备选方案

[试过/考虑过但否掉的，及理由——防止后人重复试错]

## 后果

[正面：得到了什么；负面：代价/约束。]

## 验证

[怎么确认决策有效——grep/测试/行为断言，写成可执行不变量]
```

## 示例（简化自 mattpocock 0001）

```markdown
# 显式 setup 指针只给硬依赖 skill

日期: 2026-09-02
状态: 已接受

## 背景
skill 依赖每仓配置（issue tracker、标签词表），没有配置时部分 skill 输出错误。

## 决策
拆硬/软依赖：硬依赖 skill（发布到 tracker 的）显式写 setup 指针；
软依赖 skill（只用于润色输出的）只模糊引用词表。

## 硬依赖 vs 软依赖
- 硬：to-tickets / to-spec / triage —— 没有映射输出就错
- 软：diagnose / tdd —— 没有词表仍能用，只是不够锐利

## 后果
正面：软依赖 skill 保持 token 轻量。负面：需要维护依赖分类。

## 验证
grep -c "run.*setup" <硬依赖 skill>  # 硬依赖必有 setup 指针
grep -c "setup" <软依赖 skill>       # 软依赖无 setup 指针
```

## 使用规则

1. **写 skill 改动前先写 ADR**（或改动后立即补）——ADR 是留痕，不是事后补作业
2. 一个 ADR 一个决策，不攒批
3. 被替代的 ADR 标 `已替代` 并链接新 ADR，不删除（历史是资产）
4. 验证项必须可执行（grep/assert），不写"看起来对"
