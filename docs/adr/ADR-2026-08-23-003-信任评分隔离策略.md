# ADR-2026-08-23-003 · 信任评分隔离策略

> 日期：2026-08-23 ｜ 决策人：沈遥（Hermes） ｜ 状态：已采纳

## 背景

盲区 ②-1 认知免疫层：入库代码/文档自动信任分（来源历史/签名/改动血统），低信任进隔离区。与供应链铁律（外来文件默认不信任，审查后再接入）对齐。

## 决策

1. **独立 trust_layer 模块**（`mcpserver/trust_layer.py`）：`TrustScorer` 评分器，纯 stdlib。
2. **四维评分**：来源历史（可信源 +1 / 黑名单 -2 / 未知 0）+ 签名（+1）+ 改动血统（可信 +1 / 未知 -1）+ review（+1）。
3. **阈值**：`>=2` 信任，`<=1` 低信任 → 自动进隔离区（quarantine）。
4. **评分表落盘**：`trust_scores.json`（运行时数据，gitignore，可回溯）。
5. **注册门禁**：`mcp_registry._trust_gate_registration()`——仅当 manifest 显式携带 source/lineage 信任元数据时评估；存量 manifest 无元数据直接放行（**默认不改变现有行为**）。
6. **HTTP 契约**：`POST /trust/assess` + `GET /trust/status`（评分表 + 隔离区清单）。

## 后果

- 带信任元数据的 manifest 低信任 → 注册被拦截并进隔离区，LLM 看不到不可信工具。
- 存量 manifest 零影响，兼容现有注册路径。
- 后续可在适配层/外部服务接入处复用 `get_trust_scorer()`，同一信任表全系统共享。
