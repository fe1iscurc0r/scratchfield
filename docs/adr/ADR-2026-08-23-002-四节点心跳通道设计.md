# ADR-2026-08-23-002 · 四节点心跳通道设计

> 日期：2026-08-23 ｜ 决策人：沈遥（Hermes） ｜ 状态：已采纳

## 背景

盲区 ①-1 战情面板：需要四节点（云服/Kali/K40/天选7）状态可见——算力余量 / API余额 / 队列深度 / 频谱占用 / 安全告警。字据要求「EventBus 之外新增 heartbeat 通道」。

## 决策

1. **独立 heartbeat 模块**（`mcpserver/heartbeat.py`）：不依赖 EventBus，纯 stdlib 内存表。
2. **固定节点名单**：`cloud / kali / k40 / tianxuan7`，未知节点上报拒绝（防伪冒）。
3. **HTTP 契约**：`POST /heartbeat/report`（节点上报）+ `GET /heartbeat/status`（战情总览）+ `GET /heartbeat/nodes/{node}`（单点查询）。
4. **过期判定**：`HEARTBEAT_STALE_SECONDS=90`，超时未上报标记 stale/失联。
5. **单例访问**：`get_heartbeat_board()`，与 mcp_manager 单例模式一致。

## 后果

- 节点侧任意语言一行 POST 即可接入，无 SDK 依赖。
- 状态查询聚合 alive/stale 统计，战情面板前端可直接消费。
- 后续如需持久化历史，可在 `report()` 内追加时间序列存储，接口不变。
