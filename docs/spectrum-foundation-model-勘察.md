# 频谱基础模型 · 勘察报告（Channel2World 路线）

> 来源工单：R02 · 分组 group1-无线电
> 参考 digest：[digest-g8-1b-2026-08-30.md](../paper-round2-2026-08-30/digests/digest-g8-1b-2026-08-30.md)（Channel2World = arXiv 2608.17544v1）
> 日期：2026-08-30

---

## 1. 结论先行

Channel2World 的"大规模预训练 + 冻结编码器微调"范式**在射频/频谱域可落地，且与 rf_brain 现有组件互补而非冲突**。推荐走"频谱掩码预测"作为 P0 预训练任务，因为：

- 它与 Channel2World 的"上下文-查询预测"同构（都是"从可见局部推缺失局部"）；
- 数据最容易获得（任意频谱帧/瀑布图即可，无需标签）；
- 冻结编码器后可直接服务 rf_brain 的三个既有痛点：信号分类、干扰检测、异常发现。

**一句话推荐**：先用合成 IQ + 轻量 autoencoder 跑通"预训练→冻结→微调"闭环（P0），再逐步替换为真实 SDR 录制数据。

---

## 2. Channel2World 要点提取

| 维度 | Channel2World 做法 | 对频谱域的迁移 |
|---|---|---|
| 预训练数据 | 26,000 个射线追踪场景 | SDR 录制 / 频谱仿真 / 瀑布图存档 |
| 预训练任务 | 上下文-查询预测（环境嵌入） | 频谱掩码预测 / 下一帧预测 / 对比学习 |
| 表征对象 | 无线环境级（非单链路） | 频谱环境级（跨频段、跨时间） |
| 下游用法 | 冻结编码器 + 即插即用 | 冻结编码器 + 分类/检测头微调 |
| 泛化能力 | 零样本跨部署 | 零样本跨设备/跨频段 |

核心思想：**不针对单一任务从头训练，而是让编码器在大量无标签频谱上学会"环境表示"，下游任务只训一个小头。** 这正好回避 rf_brain 当前"每种调制/协议各训各的"的碎片化问题。

---

## 3. rf_brain 现状对比

| rf_brain 现有组件 | 定位 | 与基础模型的关系 |
|---|---|---|
| `spectrum.py`（FFT/瀑布图） | 纯计算，无学习 | 是基础模型的**数据来源**（频谱帧生产者） |
| `feature_extractor.py` | 手工特征（SNR/平坦度/符号率） | 是基础模型要**替代/增强**的手工先验 |
| `rule_engine.py` + `decision_layer.py` | 规则预筛 + 解调决策 | 是基础模型可服务的**下游任务**之一 |
| `demod_ref.py` | 玩具级解调器 | 可作为微调评估基准 |
| `schemas.py`（FeatureVector/Decision） | 接口协议 | 冻结编码器输出可**编码进 FeatureVector** |

结论：现有表征是**手工特征 + 规则**，泛化弱、协议相关；基础模型提供**学习到的、协议无关的环境表征**，二者可并存（规则仍做安全兜底）。

## 4. 可行性分析

- **可行性：高（P0 可跑通）**。频谱是结构化序列/图像，天然适配 mask/重建类自监督；合成数据可无限生成。
- **主要风险**：
  1. **真实数据域漂移**——合成 IQ 与真机 SDR 的分布差异会导致冻结编码器迁移打折，需逐步引入真机数据。
  2. **计算预算**——rf_brain 面向边缘/实时，大模型不可行；P0 必须控制在百 KB～数 MB 参数。
  3. **缺乏大算力**——本仓库在 ESP32/嵌入式定位，预训练需在 PC/服务器完成，节点只跑冻结推理（这与 Channel2World 的"冻结编码器"思路一致）。

---

## 5. 数据源（3 个候选）

| 数据源 | 规模可达性 | 优点 | 缺点 |
|---|---|---|---|
| **A. 频谱仿真（合成 IQ→FFT）** | 无限 | 标签可控、可复现、零硬件 | 域漂移最大 |
| **B. SDR 真机录制（RTL-SDR/IC-705/esp32）** | 中 | 真实分布、贴近部署 | 采集/标注成本高、需硬件 |
| **C. 公开频谱数据集 + 瀑布图存档** | 大 | 现成、多样 | 质量参差、频段碎片 |

推荐路线：**A 起步跑通闭环 → 混入 B 做域对齐 → C 扩充多样性**。

---

## 6. 模型规模（预算）

- 编码器：2–4 层 CNN/Transformer-lite，参数量 **≤ 1M**（约 4 MB fp32，int8 后 ≤ 1 MB，可上 ESP32-S3）。
- 预训练：PC 上完成，无边缘约束。
- 推理：冻结编码器 + 单层线性/MLP 头，节点内存占用 ≤ 200 KB。

---

## 7. 三个候选预训练任务

### 任务 1：频谱掩码预测（首选）
把一段频谱/瀑布图随机遮蔽（按频率段或时间块），让模型从可见部分重建被遮蔽部分。
- **优点**：与 Channel2World 上下文-查询预测同构；无需标签；直接产出"环境级"表示。
- **下游**：信号分类、干扰检测、异常发现。

### 任务 2：下一帧频谱预测
给定过去 K 帧频谱，预测下一帧（时序因果）。
- **优点**：学到时间动态，服务 R01 事件缓存、R24 资源分配的"预测式扫描"。
- **下游**：频谱占用预测、动态频谱接入（R06）。

### 任务 3：对比学习表征
对同一频谱做增强（加噪/频移/掩码）视为正样本对，不同频谱为负样本，学不变表示。
- **优点**：鲁棒、协议无关。
- **下游**：低信噪比识别（R28）、跨设备泛化。

---

## 8. 微调场景

1. **信号分类**（调制/协议识别）——冻结编码器 + 分类头。
2. **干扰检测**（区分真实信号 vs 干扰/伪影）——二分类头，服务 R03 RFI 缓解。
3. **异常发现**（未知信号/新干扰源）——重建误差作异常分，服务 R23 安全审计。
4. **频谱修复**（稀疏采样补全）——服务 R27 无线电地图修复、R34 EM 孪生。

---

## 9. P0 最小原型方案（可落地）

**目标**：证明"预训练→冻结→微调"闭环在频谱域有效，且优于"随机初始化直接微调"。

**步骤**：
1. 用 numpy/轻量框架（无重型 DL 依赖）合成多样调制（BPSK/QPSK/GFSK/OOK + 多径 + 噪声）→ 生成 FFT 频谱帧（复用 `spectrum.compute_spectrum`）。
2. 建一个 2–3 层小编码器 + 重建头的**掩码自编码器**，在无标签频谱上预训练（掩码重建）。
3. 冻结编码器，接线性分类头，在下游"调制分类"任务微调。
4. 对比指标：冻结微调 vs 随机初始化微调的分类准确率、训练样本需求。

**验收口径**：冻结编码器在小样本下游任务上 ≥ 随机初始化基线；原型代码可跑、可复现。

**产物位置建议**：`mcpserver/rf_brain/prototypes/spectrum_foundation_model_p0.py`（原型）+ 本勘察文档。
