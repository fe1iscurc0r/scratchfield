## 一、问题陈述

工具增强 LLM 的一个默认假设是"工具调用比参数记忆更可靠"。MemToC（2608.26295）用 6,504 个评估 episode 推翻了它：

- 当**工具返回与模型自身记忆冲突**时，模型**仅 6.5–17.1%** 的情形保留正确记忆；
- 而**86–93%** 的情形遵循正确工具。

这组数字的解读是：**工具返回强烈主导模型**——模型在不该听工具的时候（工具返回错误/过时/被污染，而自身记忆正确）也会盲从工具。且这种偏向**没有任何跨模型排序在三种指令措辞变体下保持稳定**，说明仲裁机制本身是未解决的开放问题，不能靠"换更强模型"或"换个提示词"来消除。

## 二、根因分析

1. **位置与格式偏见**：工具返回作为"外部事实"进入上下文，天然比模型内部记忆获得更高的注意力权重。
2. **缺少可信度信号**：模型没有机制区分"工具结果可信"与"工具结果可疑"，只能默认采信。
3. **记忆无显式对抗**：参数记忆是隐式的，无法在上下文中"站出来"反驳工具返回。

## 三、仲裁方案设计

核心目标：**在"工具返回"与"内部记忆"冲突时，动态决定该信谁，提升正确记忆保留率。**

### 3.1 双通道显式化
- 把内部记忆**显式化**为结构化断言：`memory_claim = {事实, 置信度, 来源, 时间}`。
- 把工具返回**结构化**为：`tool_result = {事实, 置信度, 来源, 时间}`。
- 两者进入同一个仲裁器，而不是让模型隐式权衡。

### 3.2 冲突检测
- 对 memory_claim 与 tool_result 做语义/结构化比对，识别冲突（同一对象的不同取值）。

### 3.3 仲裁信号（可信度打分）
对冲突双方计算可信度分，而非简单"工具优先"：
- **来源可信度**：工具是否为受信源、记忆来源的可靠性。
- **新鲜度**：时间戳越新越可信（但需警惕工具返回的"过时缓存"）。
- **一致性**：与环境中其他已确认事实的交叉验证。
- **模型自身置信度**：模型对 memory_claim 的激活强度（可作为弱信号，不可单独依赖）。

### 3.4 仲裁决策
```
score_memory = f(来源可信度, 新鲜度, 一致性, 置信度)
score_tool   = f(来源可信度, 新鲜度, 一致性)
if |score_memory - score_tool| > 阈值:
    信高分者
else:
    触发验证（再查一次工具/请求确认），而非默认采信工具
```

关键变化：**默认从"信工具"改为"信分数更高者"，平局时验证而非盲从。**

## 四、原型骨架

```python
@dataclass
class Claim:
    fact: Any
    confidence: float
    source: str          # "memory" | "tool:<name>"
    timestamp: float

def arbitrate(memory: Claim, tool: Claim, env_facts: list, tau=0.2):
    sm = score(memory, env_facts)
    st = score(tool, env_facts)
    if abs(sm - st) > tau:
        return "memory" if sm > st else "tool"
    return "verify"       # 平局 → 触发验证，而非盲从工具

def score(c: Claim, env_facts):
    return (
        0.35 * source_trust(c.source) +
        0.25 * freshness(c.timestamp) +
        0.30 * consistency(c.fact, env_facts) +
        0.10 * c.confidence
    )
```

## 五、保留率对比实验设计

复用 MemToC 场景（6,504 episodes）或自建冲突子集，对比：
1. **基线**：默认"工具优先"（对应论文 6.5–17.1% 保留正确记忆）。
2. **本方案**：结构化双通道 + 仲裁打分 + 平局验证。

**指标**：正确记忆保留率、正确工具遵循率、总体任务成功率。
**验收目标**：正确记忆保留率相对基线显著提升，同时正确工具遵循率不下降（即"该听工具时仍听工具"）。
