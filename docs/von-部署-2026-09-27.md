# Von 决策模型部署指引（Y7000P 实机 · 2026-09-27）

> 本文档对应 **卷164：Von 决策模型接入——判决书自动打标层**。
> Von 是**外部推理服务**，与 Ollama 同等地位：apiserver 不负责拉起它，
> 只通过 HTTP 调用。离线时打标功能降级禁用，不影响其他功能。

## 0. 选型背景（已定案，不要重新选型）

| 项 | 值 |
| --- | --- |
| 仓库 | https://github.com/wfzyx/von |
| 许可 | Apache-2.0 |
| 规模 | 395M 参数 / 约 1.5GB 权重 |
| 协议 | `/v1/systemone`（与 TypeSafe **Jev 云 API 协议兼容**） |

**战略备份位**：Jev 1.13 宏准确率 96.6% vs Von 72.0%。因协议兼容，
将来切到 Jev 云只需改 `von.endpoint` + 鉴权头，**零代码改动**。

> 工单明确：不要换模型、不要引入 GLiNER2 / Qwen 微调等其他候选。

## 1. 硬件与后端选择（关键：显存零占用）

本机为 **联想拯救者 Y7000P（RTX 5060 8GB）**，同时要跑 **LawLLM-7B**。
Von 支持 CUDA / ROCm / MPS / **OpenVINO（Intel NPU/CPU）** / 多线程 CPU。

**结论：Von 走 OpenVINO（NPU/CPU），不占 5060 显存**，8GB 显存留给 LawLLM-7B。

| 后端 | 显存占用 | 建议 |
| --- | --- | --- |
| OpenVINO（Intel NPU） | 0 | ✅ 首选（若有 Intel NPU） |
| OpenVINO（Intel CPU） | 0 | ✅ 次选，纯 CPU 推理 |
| 多线程 CPU | 0 | ✅ 兜底 |
| CUDA | 占 5060 显存 | ❌ 不用（留给 LawLLM-7B） |

## 3. 启动与验证

### 3.1 启动服务

```bash
# 指定 OpenVINO/CPU 后端与端口（默认 8001）
.venv-von/Scripts/von.exe serve --port 8001 --backend openvino
```

启动后验证：

```bash
curl http://127.0.0.1:8001/v1/systemone/health
# 或
curl http://127.0.0.1:8001/
```

### 3.2 验证打标链路

```bash
# 本机 apiserver 运行中
curl http://127.0.0.1:<apiserver端口>/api/domains/law/von-status
# 期望：{"success":true,"enabled":true,"alive":true,"breaker":"closed",...}
```

前端「设置页」会显示 **Von 在线/离线徽章**；离线时打标按钮置灰，
提示「启动 von serve 后可用」。

## 4. apiserver 侧配置

`config.json`（或 `system/config.py` 默认值）中：

```json
{
  "von": {
    "enabled": true,
    "endpoint": "http://127.0.0.1:8001",
    "timeout": 10.0,
    "breaker_threshold": 5,
    "breaker_cooldown": 60.0
  }
}
```

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 关闭后打标功能整体禁用（不发起任何请求） |
| `endpoint` | `http://127.0.0.1:8001` | Von 服务地址（切 Jev 云只改这里） |
| `timeout` | `10.0` | 单问题超时（秒） |
| `breaker_threshold` | `5` | 连续失败多少次后熔断 |
| `breaker_cooldown` | `60.0` | 熔断冷却时长（秒），冷却后半开探测 |

## 5. 断路器行为（无需人工干预）

```
closed ──连续失败 5 次──▶ open ──冷却 60s──▶ half_open ──探测成功──▶ closed
                                                     └──探测失败──▶ open
```

- **open 期间**：所有打标请求**快速失败**，不打到 Von（保护自身与下游）；
- **half_open**：放行一次真实请求探测；成功即恢复，失败重新熔断；
- 熔断状态可通过 `GET /api/domains/law/von-status` 的 `breaker` 字段观察。

## 6. 开机自启（Windows 任务计划程序）

推荐 **登录时触发**（而非开机触发，避免服务先于用户环境就绪）：

1. `Win + R` → `taskschd.msc` → 「创建任务」
2. **常规**：勾选「不管用户是否登录都要运行」按需（一般选「只在用户登录时运行」）
3. **触发器** → 新建 → 开始任务：**登录时**
4. **操作** → 新建 → 启动程序：
   - 程序：`C:\path\to\.venv-von\Scripts\von.exe`
   - 参数：`serve --port 8001 --backend openvino`
   - 起始于：`C:\path\to\von`
5. **条件**：可取消「只有在计算机使用交流电源时才启动」等限制
6. 保存后右键「运行」测试一次

> 命令行建（需管理员）：

```powershell
$action = New-ScheduledTaskAction -Execute "C:\path\to\.venv-von\Scripts\von.exe" `
  -Argument "serve --port 8001 --backend openvino" -WorkingDirectory "C:\path\to\von"
$trigger = New-ScheduledTaskTrigger -AtLogOn
Register-ScheduledTask -TaskName "VonServe" -Action $action -Trigger $trigger
```

## 7. 内存/显存占用参考

| 组件 | 目标设备 | 占用 |
| --- | --- | --- |
| Von（OpenVINO/CPU） | Intel NPU 或 CPU | RAM 约 1.5–2GB；**显存 0** |
| LawLLM-7B | RTX 5060 | 显存约 6–7GB |

两者互不争抢 5060 显存——这是选 OpenVINO 后端的核心原因。

## 8. 故障排查

| 现象 | 排查 |
| --- | --- |
| `von-status` 显示 `alive=false` | Von 未启动 / 端口不符 / 防火墙拦截 |
| `breaker=open` | 连续失败 5 次触发；确认 Von 恢复后等待冷却（60s）自动半开 |
| 打标全部进 `_queue/` | 案由等 choice 置信 < 0.6 → 属正常低置信分流，需人工复核 |
| 喂料过长 | 已按 4000 字符预算截断，`tag_confidence.truncated=true` 可查 |
