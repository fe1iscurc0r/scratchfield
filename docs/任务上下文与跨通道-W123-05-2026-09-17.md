# 任务级上下文 + 跨通道继续（卷123 W123-05 · 2026-09-17）

长任务不能靠「一个越来越大的对话」撑着，任务也不能锁死在某个客户端里。本项做两件事：
**任务级上下文**（goal 摘要 + 当前步上下文 + 关键结果，全历史压缩）与**跨通道继续**
（QQ 开的任务微信接着干）。

## 任务级上下文

### 每步注入什么

`task_flow.task_context_prompt(session_id)` 注入 system 层（并入 `messages[0]`，
沿用卷121 的 relay 教训：末尾独立 system 会被上游拼进 user 消息而被判注入）：

```
任务 <id>｜目标：…｜状态：running｜模式：explore｜进度：1/3
  [done] s1 探查：读 utils.py
  [pending] s2 实现：改 utils.py
本步相关文件（先读再改）：utils.py, tests/test_utils.py
上一步结果：理解摘要：utils.py 只有 slugify 雏形，tests 有 2 条用例
完成该步后请用 [TASK] 段报告：{"op":"step","task_id":…,"step_id":"s2",…}
```

「相关文件」来自任务 `file_refs`（步骤结果里出现的 `.py` 路径会自动并入），
「上一步结果」取轨迹里最近一条有 step_id 的结论。

### 压缩边界 = 步骤边界

`task_flow.step_boundary_compact(messages, session_id)`：某步完成后把更早的工具结果消息
**收敛成一条「已完成步骤 + 关键结果」**（保留首条 system、最近 6 条消息、助手文字说明），
返回收敛条数；loop 会发 `context_compacted` 事件（`reason=step_boundary`）。

规则：**全历史压缩，任务级三件套不压** ——

| 保留 | 来源 |
| --- | --- |
| goal 摘要 | task_store.goal（权威源，压缩不碰） |
| 当前步上下文 | 步骤清单 + file_refs + 上一步结果 |
| 关键结果 | 各已完成步骤的 `result_ref`（`key_results()`，最多 5 条） |

压缩只动 `messages`（LLM 窗口），任务状态永远以 SQLite 为准，查得到就不算丢。

## 跨通道继续

任务表新增 `user_id` 列（老库自动 `ALTER TABLE` 补列，不重建），建任务时由
`bind_task_owner()` 绑当前登录用户（`naga_auth.get_user_info().username`）。

| 场景 | 行为 |
| --- | --- |
| 同会话 | `task:list` / `task:continue` 照旧 |
| 同用户、跨通道（`cross_channel_shared=true`，默认） | 可见并可继续；回复里标注「来自会话 xxx」 |
| 同用户、跨通道但开关关掉 | 按通道隔离，别的通道看不到 |
| 不同用户 | **不可见**（`find_visible_task` 直接 None，防越权） |

`task:list` **不再回落到全局任务列表**——那个回落会绕过所有隔离判断（实测抓到并修掉）。

## 与调度器联动（可选）

`task_flow.register_scheduler_advice(bus)` 挂到卷120 W120-02 的 `SCHEDULER_TICK`：
`task_flow.idle_advance=true` 时，每次发号检查「进行中/blocked/paused 且超过
`idle_minutes`（默认 30）没动」的任务，打一条提示（含任务 id、目标、下一步），
**只提示不自动推进**（默认 `idle_advance=false`，不挂）。

```python
# README 示例：空闲期提醒
from apiserver.task_flow import scheduler_tick_advice
print(scheduler_tick_advice(minutes=30))
# 有 1 个任务空闲超过 30 分钟：
# - `abc…` [running] 给 calc.py 加 divide｜下一步 s2 实现：改 utils.py
# 可 `task:continue <task_id>` 接着推进。
```

## 配置（`config.json` 的 `task_flow` 段新增）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `cross_channel_shared` | `true` | 同用户跨通道任务可见；false 按通道隔离 |
| `idle_advance` | `false` | 空闲任务提示挂到调度发号器 |
| `idle_minutes` | `30` | 多久没动算空闲 |
