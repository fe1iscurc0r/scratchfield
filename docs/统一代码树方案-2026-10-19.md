# 统一代码树方案（治"三棵树混跑"）

> 背景：2026-10-18 一天内出现"PrimeVue 许可报错 / 设置页空白 / NEKO 起不来"等看似无关的问题，
> 追根都是**版本矩阵混乱**：后端、NEKO、桌宠、前端分别来自三棵不同的树。
> 本文给出可在任意机器复现的统一方案。

## 一、资产分层（先认清什么该进 git）

| 类 | 内容 | 体积 | 处理方式 |
|---|---|---|---|
| **A 代码** | `f63788cb` 起的仓库内容 | ~700 MB(.git 计) | **git 管理**，唯一基线 |
| **B 用户数据** | `carpet/`（Live2D/VRM/卡面/avatar_tools） | **82 MB** | 部分已入库（`card_faces/YUI.*` 被跟踪）⇒ **迁出仓库**，用配置指向外部路径 |
| **C 私有依赖** | `NEKO/N.E.K.O/deps/*.whl`（如 `pyncm_async`） | 数十 KB | **不入库**，随环境分发（校验 sha256） |
| **D 环境** | `.venv`(2.0G) / `NEKO/N.E.K.O/.venv`(781M) / `frontend/node_modules`(1.3G) / `neko-electron-shell/node_modules`(387M) | **≈4.5 GB** | **一律重建**，绝不复制进仓库；换机时按下方步骤重装 |

> ⚠️ **关键认知**：`NEKO/N.E.K.O` 下那 757 个"未跟踪文件"**不属于 B/C 类**——它们是**新版本 NEKO** 的文件，
> 因为本地树是 10-04 旧提交而被当成未跟踪。统一到 `f63788cb`（NEKO 已同步 `96dd262580`）后**大多不再需要手工携带**。

## 二、迁移步骤（新机器 / 重装都可照抄）

```bash
# 0) 备份用户数据（本机，纯复制，不动仓库）
cp -r "D:/my git/scratchpad/carpet"                 "D:/backup/carpet-2026-10-19"
cp -r "D:/my git/scratchpad/NEKO/N.E.K.O/deps"      "D:/backup/neko-deps-2026-10-19"
cp    "D:/my git/scratchpad/NEKO/N.E.K.O/.venv"     ...  # 可选：3.11 环境，781M，能复用就别重建

# 1) 取唯一基线（不要在脏树上做！）
git worktree add "D:/my git/scratchpad-unified" f63788cb

# 2) 放回用户数据（carpet 不再入库）
cp -r "D:/backup/carpet-2026-10-19" "D:/my git/scratchpad-unified/carpet"

# 3) 重建环境（严禁把 .venv / node_modules 复制进仓库）
cd "D:/my git/scratchpad-unified/frontend" && npm install --ignore-scripts   # ⚠️ 必须带 --ignore-scripts
#    ↑ 否则 electron 的 postinstall 会下载 214MB 二进制，网络失败会让整次安装回滚

# NEKO 侧：硬要求 Python ==3.11.*（3.12 会被 pip 拒绝）
#   优先复用现有 NEKO/.venv（3.11.15，soxr/portalocker 齐全），否则：
cd "D:/my git/scratchpad-unified/NEKO/N.E.K.O" && pip install -r requirements.txt
#    ↑ 必须在 **该目录** 内执行：requirements 用相对 cwd 路径 + 私有 wheel deps/*.whl

# 4) 起服务（一键脚本，四端同属一个父任务）
bash _start_all.sh
```

## 四、必须固化的六条纪律（都是踩过的坑）

1. **NEKO 用 3.11**：`n-e-k-o` 钉 `==3.11.*`，用本机 uv 的 `cpython-3.11.15`；
2. **`npm install` 必带 `--ignore-scripts`**：否则 electron 下载失败导致整体回滚；
3. **`pip install -r` 必须在 `NEKO/N.E.K.O` 目录内**：相对路径 + 私有 wheel；
4. **electron 启动必须三个参数**：`--disable-gpu --no-sandbox --disable-software-rasterizer`（缺一个就 GPU 崩）；
5. **必须用托管后台起服务**（`run_in_background`）：`(cmd &)` 起的进程随 shell 退出被杀；
6. **脏树禁止 stash / clean**：本地树有 757 个未跟踪文件是运行时的一部分（历史上已因 stash 弄坏过一次）。

## 五、尚未解决 / 待办

- **端口暴露不一致**：`8000`/`48911` 绑 `127.0.0.1`，`8001`/`8003` 绑 `0.0.0.0` ⇒ 需统一或引入 `BIND_HOST`；
- **`8004` NagaMemory** 前后端都有配置但**无服务**（静默降级）⇒ 启动时探活并告警；
- **前端 14 处硬编码 host:port** ⇒ 收敛到单一 `API_BASE`；
- **四套 skill 目录** ⇒ 在 docs 明确唯一权威源。
