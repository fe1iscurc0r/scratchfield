## 一、项目定位

高性能代码库记忆 MCP：把代码库索引成**持久知识图谱**，供 Agent 查询代码结构/依赖/符号关系。C 实现（比 Python 快），41754★（高热度）。

## 二、架构拆解

- 索引：解析代码（AST/符号/依赖）→ 构建知识图谱（节点=符号/文件，边=调用/依赖/继承）。
- 查询：MCP 接口，Agent 按需查询图谱（而非全量读代码）。
- 持久化：图谱落盘，增量更新。

## 四、接入 vs 不接入结论

**结论：不整体接入（本仓已有 graphify/repowiki 覆盖此赛道），但借鉴其「C 实现性能」与「增量更新」两点。**

- 理由：功能与本仓 graphify（代码→图谱）+ repowiki 重叠，整体接入属重复造轮子；但 codebase-memory-mcp 的 C 实现性能、增量索引设计、MCP 接口形态值得吸收到 graphify 的性能优化。

## 五、可落地借鉴点（≥3）

1. **C 实现高性能索引**：大代码库索引用 C 提速，graphify 若遇性能瓶颈可参考其「热路径下沉 C」思路。
2. **增量更新**：图谱随代码变更增量更新（非全量重扫），是 graphify 持久化的改进方向。
3. **MCP 接口形态**：把代码图谱查询暴露为 MCP，Agent 按需查（而非全量注入），是代码理解工具的统一接入范式。
