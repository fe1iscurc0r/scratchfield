## 3. 本轮修掉的四个真实缺陷

1. **扇扫计数 off-by-one** — 扫完一轮时多记一次 `moves`，且 `loops_done` 在限次判断之后才自增，
   导致 `loops=2` 实际跑出 8 次移动。修正为：翻卷只做簿记不自增 `moves`；`loops_done` 先自增再判断。

2. **`_last_emit_at` 用 `0.0` 作哨兵** — `0.0` 同时表示"从未发射"和"在 t=0 发射过"，
   吞掉了首个 tick（跟踪节拍少一次、扇扫 dwell 首拍误发）。
   改为 `Optional[float] = None` + `is not None` 判定。
   与既有的看门狗 `0.0` 哨兵属同一类缺陷。

3. **看门狗故障不停自动任务（真实安全漏洞）** — `_on_watchdog_fault` 只置故障位，
   但扇扫循环会在兜底回 HOME 之后立刻再发 `G1`，**主动对抗兜底动作**。
   修正：故障时 `stop_all(FAULT_WATCHDOG)`，并在 `tick_scheduler()` 加故障态短路。

4. **`Tle.parse` 接受倒序 TLE（真实健壮性缺陷）** — 用 `next(...)` 无序找行，
   `L2` 在前、`L1` 在后时不报错，会静默取到错误历元 → 全部跟踪结果错且无从察觉。
   修正：强制 `body[0]` 以 `"1 "` 开头、`body[1]` 以 `"2 "` 开头。

另有 `transport.py` 的建模修正：`SimPTZTransport` 新增 `device=` 参数。
双路仲裁模拟的是**同一条机械的串口 + 无线两条链路**，`enabled`/故障环/当前角度是
**设备上的状态**，不随链路走；两条链路各持一个独立模拟器等于建模成"两台设备"，
`ptz_lora("G28")` 会因"影子设备"未使能而返回 `error:disabled`。
新增 `test_two_links_can_share_one_device_body` 把该决策钉住。

  `lora_remote/` 仅逻辑核对，未接线。

  限位保护目前全靠软件，`error:limit` 依赖配置的 `az_min/az_max/el_min/el_max`。

  但随时间发散——24h 内最佳过境差 350 min / 27.21°。
  `simple` 仅用于离线自测，**不可用于真实指向**；生产必须 `sgp4`。
- **模块重叠**：`mcpserver/antenna_rotator`（早期草稿）与
  `mcpserver/ptz_service`（工单指定）功能有部分重叠，建议后续合并到后者。
