## 2. 授粉点 A：Runtime-Independent Persistent Agents（2609.00546）

**原文要义**：把 Agent 的 **身份/记忆/代码** 与 **model/harness/服务器** 解耦——连续性基座 P_t（身份+记忆流，跨重启/跨宿主持存）+ 部署绑定 E_t（当前装在哪个 model/harness 上）。
状态迁移：P_t 不变，E_t 可换 → 「同一灵魂，换身体」。

**对 T 线的映射**：
- 知识底座 = 连续性基座 P_t 的本地承载（记忆流 + 身份锚）
- 天选7 NEKO 桌宠 / 云服 Hermes / 冥王峡谷 NagaAgent = 三个可互换的 E_t
- 落地物：知识底座 schema 里加「identity 层（不可迁移，只读锚）+ deployment 层（可迁移，热插拔）」两段式结构，而非一个平铺的知识库

**给 T 线 7 单的直接提示**：T 线若只做「知识入库/检索」，会漏掉「身份/记忆流与宿主解耦」这一层——建议第 1 单（底库结构）即纳入 identity/deployment 两段式划分。

## 3. 授粉点 B：Control-Data 流分离（2609.00621）

**原文要义**：prompt 优化（动内容）不得腐蚀执行协议（路由/终止信号）——控制流与数据流物理分文件/分通道，防止「调 prompt 时把协议弄坏」。

**对 T 线的映射**：
- 知识底座的数据文件（语料/记忆/入库内容）= 数据流，可频繁增删改
- 底座的路由/准入/幂等/终止协议（MCP 接入清单 docs/SPEC-16） = 控制流，只读受版本控制
- 落地物：目录两级拆分——`data/`（内容层，git 正常跟踪）+ `protocol/`（协议层，git 保护/变更需评审）
- 与既有铁律同源：外来文件默认不信任 → 协议层变更视为 schema 变更，不随数据批量提交
