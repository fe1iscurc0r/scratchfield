# 设备台账 Schema 草案（SQLite 轻量版 · 卷102 W102-07 核心交付）

- 日期：2026-09-11 · 分支：trae/agent-102
- 定位：万物互联三件套之「一本台账」——设备身份/能力/安全/状态的单一事实来源，**不是控制台**（控制面走 Hermes 决策层）
- 字段来源：本批六个探针的落地字段全数对齐（FDO 凭证 / qbee 心跳 / iotgateway 换算表 / SDR topic / 自愈决策 / mesh 路由）

## 一、表结构（SQLite DDL 草案）

```sql
CREATE TABLE devices (
    id            TEXT PRIMARY KEY,              -- 设备唯一 ID（FDO device_id / qbee 派生指纹）
    name          TEXT NOT NULL,                 -- 人类可读名（如 "433网关-A"）
    protocol      TEXT NOT NULL,                 -- modbus-rtu / dlt645 / SDR / LoRa433 / mqtt ...
    capabilities  TEXT NOT NULL DEFAULT '{}',    -- JSON：能力清单（字段换算表/频段/通道，iotgateway fields 三元组）
    security_level INTEGER NOT NULL DEFAULT 1,   -- 1=公开读 2=本地可信 3=敏感（FDO 上船阶段挂钩）
    onboard_stage TEXT NOT NULL DEFAULT 'manual',-- manufacturer/initialized/rendezvous/onboarded（fdo_probe.FdoStage）
    voucher_serial TEXT,                         -- FDO 所有权凭证序列号（无凭证设备为 NULL）
    network       TEXT NOT NULL DEFAULT '',      -- 网络位置：IP/mesh 节点号/LoRa 地址
    status        TEXT NOT NULL DEFAULT 'registered', -- qbee 心跳 status：ok/unhealthy/offline
    last_seen_at  INTEGER,                       -- 心跳 ts（device_agent_probe 最后交互）
    registered_at INTEGER NOT NULL,              -- 入账时间（bootstrap_at）
    agent_version TEXT                          -- 设备端 agent 版本（OTA 决策依据）
);

CREATE TABLE device_metrics (            -- 心跳/自愈事件的时序留痕（决策层收割源）
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    device_id  TEXT NOT NULL REFERENCES devices(id),
    ts         INTEGER NOT NULL,
    cpu_percent REAL, mem_percent REAL,
    status     TEXT,
    restart_count INTEGER DEFAULT 0,     -- edge_selfheal_probe 恢复计数
    decision   TEXT                      -- RecoveryDecision JSON：check/action/ts
);
CREATE INDEX idx_metrics_device_ts ON device_metrics(device_id, ts);

CREATE TABLE bus_topic_map (             -- 遥测总线 topic 白名单（sdr_mqtt/iotgateway 规范落账）
    device_id  TEXT NOT NULL REFERENCES devices(id),
    topic      TEXT NOT NULL,            -- gateway/{id}/data、sdr/meter/{id}/state、sdr/spectrum/{band}/state
    direction  TEXT NOT NULL CHECK (direction IN ('up','down','meta')),
    UNIQUE(device_id, topic)
);
```

## 二、与三个「落位」的呼应

| 字段/表 | 来源工单 | 呼应点 |
|---|---|---|
| `id` + `onboard_stage` + `voucher_serial` | W102-01 FDO | 设备身份层：注册记录即所有权凭证的结构投影 |
| `capabilities`（换算表 JSON） | W102-03 iotgateway | 协议终结层：台账持有「协议翻译字典」，网关随配置拉取 |
| `bus_topic_map` | W102-03/04 | 遥测总线数据层：topic 白名单制——新设备上总线先过此表 |
| `status/last_seen_at/registered_at` | W102-02 qbee | 设备主动上报层：心跳四字段直写本表 |
| `device_metrics.decision` | W102-05 sentinel | 决策层收割：边缘恢复决策上行后进时序表 |
| `network`（mesh 节点号） | W102-06 lora-mesh | 组网拓扑登记：静态路由表同步来源 |

## 三、「一本台账不是控制台」的边界

1. 台账只回答「有什么、在哪、什么状态」；任何下行控制指令必须经决策层（Hermes）复核后签发——下行命令记录单独审计（`bus_topic_map.direction='down'` 仅白名单）。
2. 写并发极低：只允许设备 agent 更新自身行（device_id 自证）；安全等级 3 的设备字段变更需要双写确认。
3. 不存密钥明文：voucher 存序列号与状态，密钥材料留在设备与所有者侧（FDO 语义守恒）。
