# 光谱材料数据线规划 v1 — 从"读文献"到"吃仪器数据"

> 沈遥 · 2026-10-09 · 依据：扫货金果 pybaselines/RamanSPy/py-wdf-reader（守卫全PASS）+ raman_utils 既有懒加载线 + 邵组方向（木质素NPs→水凝胶/太阳能蒸发）

## 线的定位

材料科研线至今以文献流为主（digest/授粉/工单）。但科研的真正数据源是**仪器输出文件**——拉曼光谱仪（Renishaw wdf）、FTIR、UV-Vis。谁先把"仪器文件→结构化数据→模型可消费"的管道打通，材料 Agent 才算落地。

## 三阶段

### 阶段1 · 文件直读层（P0，可立即开工单）
- **py-wdf-reader**（49★ MIT）：Renishaw wdf 只读解析——进实验室拿到的原始数据第一步
- 工单化：`tools/spectra_io.py` 统一入口（wdf/csv/spa/jdx 嗅探分发）→ MCP 化挂 material_science registry
- 验收：真实 wdf 文件读出谱线数组+元数据；无文件时用合成数据测试

### 阶段2 · 预处理管道（P1）
- **pybaselines**（195★ BSD-3）：ALS/airPLS 等 20+ 基线校正
- **RamanSPy**（195★ BSD-3）：就是 tools/raman_utils.py 懒加载的本体——从懒加载升级为显式依赖+预处理管道（基线/平滑/归一化/峰对齐）
- 验收：一条噪声谱进 → 校正后谱出，每步参数留痕（可复现）

### 阶段3 · 谱学→结构闭环（P2，等阶段1/2沉淀后）
- 谱图 embedding（复用工单227 FRPN 双通道思路：局部峰特征 × 全局谱形）
- 检索应用：新样品谱 → 历史库最相似工艺条件 → 反馈合成参数建议
- 这一步对接邵组真实数据后再细化，不预先设计

## 风险与边界
- wdf 是 Renishaw 私有格式——py-wdf-reader 是只读解析，合规
- 实验室数据可能涉密：**脱敏管道先行**（文件名/操作者字段剥离，呼应 rsba1 隐私清障教训）
- pybaselines/RamanSPy 均 BSD，融合无碍

## 与其他线的钩子
- 227 任务三 polymer_embedder 的向量输出可直接吃本线谱图
- Grafana（自部署规划波3）可做谱线时序监控（反应过程原位监测的远程查看）
