# Facet 槽位 · 设计稿 · 2026-09-29

> **缘起**：`docs/包描述与协商层-勘察-2026-09-29.md` §四登记的设计缺口——
> 「一个包含多面能力、宿主只激活所需」的机制无处安放；机械操控要的是
> 状态卡片 / 控制面板，而域包的扩展点只有 ELN 表单字段。
>
> **本文定位**：**设计稿，不含实现**。给 schema 契约、激活语义、安全边界与分期。
> 后续实现卷以本文为准绳；若实现时推翻本文某条，须回来改本文并注明原因
> （对齐「文档漂移零容忍」纪律）。

---

## 一、结论（先给判断）

1. **Facet = 能力包对宿主声明的「可激活面」**。一个 agent-manifest 可声明多个
   facet（面板、会话服务……），宿主按自身形态与装配策略决定激活哪些。
   dsh 的对应思想（headless 只激活所需 facet、禁用即 GC）被采纳为**激活语义**，
   其 TS 元协议实现不引（既有结论不变）。
2. **manifest 只声明「要什么面」，不携带 UI 代码**。前端面板组件由前端自己的
   注册表按名字解析——manifest 引用未注册的组件名时，面板降级为
   「该能力未提供本机面板」提示，**不静默、不崩**。
3. **数据通道不新增**。面板数据一律走既有 MCP 工具面（`handle_handoff` 分发），
   轮询或手动刷新；不做 WebSocket 推送、不做第二条控制通道。
4. **与装配策略同源联动**：agent 在装配层 `enabled=false` 或 `available=false`
   → 其 facet 一并不激活。tier=offensive 的控制类动作在面板层额外收敛
   （见 §四）。

## 二、Schema 契约（agent-manifest.json 增量块）

```jsonc
// 新增可选顶层块；无此块 = 该能力无面板面（现状行为，零迁移成本）
"facets": {
  "panel": {
    "kind": "status-card",            // status-card | control-panel
    "component": "RotatorStatusCard", // 前端注册表解析名（见 §三）
    "title": "天线云台",              // 面板标题（缺省用 displayName）
    "poll": {                         // 可选；不配 = 仅手动刷新
      "tool": "rotator_status",       // 数据工具（走 handle_handoff，单一入口）
      "interval_ms": 1000,            // 最小 250，宿主可强制抬低
    },
    "actions": [                      // 可选；control-panel 建议声明
      { "tool": "rotator_move", "confirm": true, "label": "转动" },
      { "tool": "rotator_estop", "label": "急停", "always_available": true }
    ]
  }
}
```

约束（校验脚本 `check_classification.py` 后续可加规则，本稿先登记）：

| 规则 | 理由 |
|---|---|
| `poll.tool` / `actions[].tool` 必须出现在同 manifest 的 `tools[].name` 或该 agent 已登记工具中 | 面板不是旁路，必须走已声明工具面 |
| `interval_ms >= 250` | 防轮询风暴 |
| `kind=control-panel` 必须声明 `actions` | 名不副实的面板不如不声明 |
| `always_available: true` 仅允许用于「降低风险」的动作（如急停） | 闸门不得挡安全路径，见 §四.3 |

## 三、前端组件注册表（宿主侧唯一改动点）

```ts
// frontend/src/components/facets/registry.ts
const FACET_COMPONENTS: Record<string, Component> = {
  RotatorStatusCard: defineAsyncComponent(() => import('./RotatorStatusCard.vue')),
  // 未注册的名字 → 渲染 FacetPlaceholder（降级提示，非静默）
}
```

- SkillView（或后续仪表区）新增「面板」渲染位：遍历**已启用且可用** agent 的
  `facets.panel`，按注册表解析组件。
- 注册表命中 → 渲染；未命中 → `FacetPlaceholder`（显示能力名 + 「本机未提供该面板组件」）。
  这与整条总线的「不静默降级」纪律一致。
- 组件 props 契约（最小面）：

```ts
interface FacetPanelProps {
  agentName: string          // 'ptz_service'
  panel: FacetPanelSpec      // manifest 的 facets.panel 原样
  invoke: (tool: string, params: Record<string, unknown>) => Promise<Record<string, unknown>>
  // invoke 即 handle_handoff 的前端封装——面板不直接接触传输层
}
```

## 四、激活语义与安全边界

1. **激活条件（与装配策略同源，单一判定）**：
   `GET /mcp/services` 返回的该 agent `enabled === true && available === true`
   → 面板激活。宿主**不需要**自己再实现第二套判定；`GET /mcp/assembly` 的
   逐 agent 摘要可复用于「为什么没激活」的提示（disabled_reason / unavailable_reason）。
2. **headless 自然无面板**：apiserver / 冻结后端不含前端运行时，panel facet
   无宿主即不激活——不需要额外开关，结构上天然满足「只激活所需」。
3. **offensive 双闸门在面板层的落法**：
   - 装配层关（disable_tiers / override）→ 面板整体不激活（§四.1）。
   - 入口闸门关（`*_ENABLE_INVOKE` 未设）→ 工具自身返回闸门错误；
     面板对**控制类** action 展示「闸门未开启」的明确提示；
     **`always_available` 动作（急停类）不隐藏**——关闭路径不得被闸门挡住，
     这是安全件的例外原则，与卷130「E-STOP 任何通道都不得降级」同源。
4. **confirm 前端落实**：`actions[].confirm` 由宿主渲染确认弹窗；
   后端不依赖它做安全（后端安全在 capability 的 safety 层，如 SafetyGovernor）。

## 六、明确不做

- **不在 manifest 里写模板/DSL 渲染 UI**——UI 组件归前端注册表，manifest 只引用名字。
  在 JSON 里造 UI 描述语言等于发明第二套前端框架，收益负。
- **不做 WebSocket 推送通道**——状态刷新用轮询（interval_ms 有下限），
  传输层扩编的复杂度当前不值。
- **不做跨 agent 面板编排**——一个 panel facet 只服务一个 agent 的工具面；
  跨能力编排是任务编排层（卷130 批架构）的领地。
