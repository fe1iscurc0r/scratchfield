# S19 Groundhog MoE 位翻转攻击面

> 来源：digest-g2-4 2608.25276v1（Groundhog Bit-Flip Attack：翻转 MoE 路由层不到 4 个专家比特使输出膨胀 5912%）
> 交付：攻击面分析报告（本文档）。无攻击代码。

## 1. 攻击原理

MoE（Mixture-of-Experts）在**路由层**存有决定"每个 token 走哪个专家"的权重。Groundhog 证明：只需翻转路由层**不到 4 个专家比特**，就能把 token 路由到错误的高幅值专家，使模型输出范数**膨胀 5912%**。这是针对 MoE 架构特有的**可用性攻击**（让输出崩溃/变垃圾），而非机密性窃取。

## 2. 攻击链拆解

1. **获取权重写入能力**：攻击者通过 RowHammer / 电压毛刺 / 辐射（硬件位翻转）、篡改 checkpoint、或恶意量化/格式转换，获得对路由层权重比特的翻转能力。
2. **定位路由比特**：路由层权重是低维（专家数 × hidden），攻击者只需扫描/定位少数关键比特（原文 <4 比特即足够）。
3. **翻转 → 错误路由**：翻转后 router 把 token 送进错误的专家（往往是激活范数异常大的专家）。
4. **输出膨胀 → 可用性崩溃**：输出 logits/隐层范数暴涨 → NaN、越界、下游崩溃，或生成垃圾。

## 3. 对本地部署 LLM / NEKO 的威胁面

NEKO 本地部署 LLM（可能含 MoE 架构），权重驻留 RAM / 磁盘 checkpoint / 嵌入式加速器。攻击面：

- **内存攻击面**：MoE 路由张量驻留普通 DRAM（无 ECC 或 ECC 未覆盖），RowHammer 可达。
- **供应链攻击面**：预训练 checkpoint 被篡改后分发，审计只看功能、不看比特完整性。
- **加速器攻击面**：FPGA/嵌入式 MoE 加速器上路由权重被故障注入。

## 4. 防御建议（≥3）

1. **路由权重完整性保护**：对 MoE 路由层张量单独做哈希/签名校验 + ECC 内存（路由层权重小，校验开销可忽略）。
2. **运行时输出范数监测与剪裁**：监控每层输出范数/路由熵，异常即告警 + 剪裁 + 降级（failover 到非 MoE 路径）。
3. **路由一致性校验**：运行时对 router 输出做校验和 / 冗余路由表决（TMR），检测单比特翻转。
4. **checkpoint 签名校验**：加载权重时校验 HMAC/签名，阻断被篡改 checkpoint 进入（对齐 `mcpserver/trust_layer.py` 的 signature 维度）。
5. **硬件层防护**：ECC DRAM、RowHammer 缓解（TRR），路由权重放片上 SRAM 或受保护存储。
