# 频谱制图 SPEC — 轮23 授粉点②：在线频谱制图 → IC-705 + SDR 组网

> 来源：卷151 任务C（2026-09-23 晨增量轮授粉点）· 落盘：砚 · 状态：**SPEC（未开工，无可执行代码）**

## 1. 要解决的问题

单点频谱只给出「我在这里听到什么」；**频谱占用图**要回答「一片区域里，谁在哪个频点、什么时候占用」。
做法上分三段：**分布式采样 → 回传聚合 → 稀疏重建出占用图**（不是把每台机器的 FFT 直接拼起来）。

## 2. 节点形态（三类角色）

| 角色 | 硬件 | 职责 | 本仓已有对应 |
|---|---|---|---|
| 主台 | IC-705（经 rsba1-core 远程控制） | 窄带精确测量、模式/带宽可编程、可作为"真值"标定节点 | `vendor/rsba1-core`、`apiserver/routes/radio.py` |
| 从节点 | SDR（工单原文写 **K40**，见 §6 未决项） | 宽带粗测、长时间驻留、多个静态布点 | `mcpserver/rf_brain/`（含 `sdrtrunk_bridge/`、`spectrum_arbitration.py`） |
| 回传节点 | ESP32-S3 + SX1278 LoRa | 无网环境下的低带宽回传（占用统计量，非原始 IQ） | `hardware/antenna-rotator/lora_bridge/`、`lora_remote/` |

**带宽现实**：LoRa 的有效载荷只够传**统计量**（每频段占用率/最大功率/时间片标签），原始频谱必须留在节点本地或走 Wi-Fi/以太网。这条决定了 §3 的数据模型。

## 3. 数据模型（回传量）

每个采样时刻，节点上报一条**占用摘要**（不是 FFT 数组）：

```json
{
  "node_id": "sdr-a3",
  "t_start": "2026-09-23T02:00:00+08:00",
  "t_span_s": 60,
  "bin_hz": 25000,
  "f_start_mhz": 144.0,
  "occupancy": [0.02, 0.31, 0.0, "..."]   // 每 bin 占用率 0..1
  "peak_dbm": [-113.2, -87.4, null, "..."],
  "method": "energy-threshold",
  "threshold_db": -95.0
}
```

- 稀疏重建的输入 = 这些摘要组成的矩阵 **M[节点 × 频段]（按时间片切分）**；
- 空缺处（节点未覆盖/未开机）就是要**补**出来的部分 —— 这才是"稀疏"的来源。

## 4. 稀疏重建（方法选型）

| 方法 | 适用 | 备注 |
|---|---|---|
| 矩阵补全（低秩 MC） | 节点少、占用模式随时间慢变 | 起步首选，纯 numpy 可实现，可离线跑 |
| 压缩感知（CS） | 频谱占用天然稀疏（少量频点被占） | 需选取稀疏基；本仓已有 `mcpserver/rf_brain/conformal_*`、`sparse*` 系资产可复用 |
| 插值 + 地形/距离加权 | 只做空间维度补点时 | 最简；作为基线对照，用来证明 MC/CS 的增益 |

**判定标准**：以主台 IC-705 的实测占用为**真值**，比较补全前后的占用图误差（逐 bin 占用率 MAE），并给出置信区间 —— 不做这一步就只是"画得好看"。

## 5. 与本仓既有设施的接口

| 已有模块 | 用途 |
|---|---|
| `mcpserver/rf_brain/amateur_bands.py` | 频段白名单，重建结果先过白名单再解释 |
| `mcpserver/rf_brain/spectrum_arbitration.py` | 多节点/多任务的频谱使用仲裁（避免自己人互相干扰） |
| `mcpserver/rf_brain/state_readback.py` | 状态回读口径，节点健康度判据来源 |
| `hardware/antenna-rotator/lora_bridge/` | LoRa 帧编解码与串口 REPL（回传层可复用其编解码范式） |
| `frontend/src/components/SpectrumPanel.vue`（v3） | 单机频谱/瀑布显示；占用图是**跨节点**视图，需新画法（表格/热力图） |

## 6. 未决项（不许含糊过去）

1. **「K40」语义未确认** —— 已做两次检索（中文"K40 SDR 接收机"、英文 `"K40" SDR board spectrum sampling`），
   **未识别到任何对应的 SDR/RF 采样设备**；命中的是无关物：Redmi K40（手机）、R&S FSV-K40（相噪测量选件）、
   Keysight 346C K40（噪声源）、**NXP Kinetis K40 / KwikStik-K40（M4 MCU 评估板）**。
   两种可能：① 工单作者指某块 **Kinetis K40 MCU 节点**（那就不是 SDR，只能做低带宽采样/回传）；
   ② 型号笔误。**需人工确认型号并给出来源链接**，确认前从节点只写「SDR（型号待定）」。
   可用替代候选（均为真实存在、公开可查）：RTL-SDR（入门宽带）、HackRF One（半双工宽带）、
   LimeSDR（收发）、SoftRock-40（40m 单频段、IQ 输出到声卡 —— 与 IC-705 的 40m 线最贴）。
2. **时间同步**：多节点占用图要求时钟对齐；LoRa 回传无 GPS 时需本仓 NEO6M 或 NTP —— 未定。
3. **样本数与重建质量的关系**：需要几次实测才能给出"最少几个节点"的结论，本 SPEC 不预设数字。

## 7. 落地步骤（建议顺序）

1. 单节点占用摘要生成器（跑在 SDR 侧，输出 §3 JSON）—— 可先在 PC + 现有 SDR 上验证
2. 采集 3 天摘要数据（多频段、多时段），拿 IC-705 做真值抽检
3. 离线跑 MC/CS 重建 + 误差评估（纯 Python，本机可做）
4. 占用图前端视图（热力图/表格），接 `SpectrumPanel` 之外的独立组件
5. 多节点 LoRa 回传联调（依赖硬件到位，见 `hardware/antenna-rotator/README.md` 的 LoRa 既有工作）

## 8. 验收（本 SPEC 的）

- [ ] 占用摘要生成器输出与 §3 模型一致（有样例 JSON 落盘）
- [ ] 重建误差有数字（MAE + 置信区间），并与插值基线对比
- [ ] 至少一条"IC-705 真值 vs 重建"的对照记录
