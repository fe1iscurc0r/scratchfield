## 1 · ⚠️ schema 冲突与调和（本文件最重要的一段）

WO-252 §2 的 `neko` 条目与 WO-253 §2.2 的 `ollama` 条目在**结构上不一致**：

| 字段 | WO-252（neko） | WO-253（ollama） | 冲突 |
|---|---|---|---|
| `platforms` | **数组** `["win32","darwin","linux"]` | **对象** `{win32:{url,…}, darwin:{…}}` | ❌ 类型不同 |
| 下载源 | `urls[]`（含 `mirror` 枚举与回退序） | 藏在 `platforms{}` 里，**无 mirror 概念** | ❌ 回退策略不可表达 |
| `sha256` | 必填 | **未给出** | ❌ 校验硬线（252 §7-3）无法执行 |
| 安装类型 | `extract_zip` | `extract_zip` / `guided_install` 两种 | ✅ 兼容，需枚举扩展 |

### 1.1 裁决（本 SPEC 采用，实现期不得各自为政）

**统一为 `platforms[]` 数组 + `urls[]`（带 `platform` 维度）**，理由：
- 回退语义（primary → github → manual）只在 `urls[]` 里表达得清；塞进 `platforms{}` 会让
  「同平台多源」无法表达 —— 而**多源回退是 252 §7-1 的验收硬线**；
- 数组形式天然支持"一个源服务所有平台"（如自建 CDN 用同一套路径模板）。

**`urls[]` 扩展两个可选字段**：

```jsonc
{ "url": "…", "mirror": "primary|github|manual",
  "platform": "win32",            // 可选；缺省 = 该 url 适用于 platforms[] 全部
  "size_bytes": 209715200 }
```

**`platforms{}` 仅在 `install_type == "guided_install"` 时以 `install_hint{}` 出现**（按平台给命令），
不再承载下载地址。

**`install_type` 枚举**：`extract_zip`（解压即用）/ `guided_install`（引导用户跑命令）/
`installer`（未来：跑安装器）。

## 3 · IPC 扩展（在 WO-252 §5 基线上新增）

| 通道 | 方向 | 请求 | 响应 / 事件 |
|---|---|---|---|
| `components:execHint` | 渲→主 | `{id, action: 'install_hint'\|'open_repo'\|'docs'}` | `{ok, opened?: string}`；**不发命令**，只打开终端/浏览器/文档；真正执行必须走 §3.1 |
| `components:runInstallHint` | 渲→主 | `{id, command}` | `{ok, exitCode, stdout, stderr}` —— **必须**带用户显式确认（见 §3.1） |
| `ollama:list` | 渲→主 | — | `[{name, size_bytes, modified, license?}]`（来自 `ollama list --json` 包装） |
| `ollama:pull` | 渲→主 | `{name}` | 事件流 `{name, status, completed, total, percent}`，**throttle 500ms**（工单 §4-5） |
| `ollama:rm` | 渲→主 | `{name}` | `{ok}` |
| `ollama:diskUsage` | 渲→主 | — | `{models_bytes, limit_bytes, over_limit}` |

### 3.1 「不静默跑命令」的机械保证（工单 §1.3 / §4-2 的硬线）

- 渲染进程**不得**直接 `exec`；只能调 `components:runInstallHint`；
- 主进程在执行前必须：① 弹出**逐字展示命令**的确认框；② 该命令必须**命中该组件 `install_hint` 的白名单**
  （逐字符比对，防止前端被注入任意命令）；③ Windows 交由 UAC 提权，主进程不自行提权；
- 拒绝执行时返回 `{ok:false, reason:'declined'}`，**不抛异常**。

## 4 · 错误码扩展（接 WO-252 §5.1）

| code | 含义 | 文案建议 |
|---|---|---|
| `E_HINT_DECLINED` | 用户拒绝执行引导命令 | 「已取消（未做任何更改）」 |
| `E_HINT_NOT_ALLOWED` | 命令不在白名单 | 「命令未通过校验，已阻止执行」 |
| `E_OLLAMA_ABSENT` | 未安装 / 不在 PATH | 「未检测到 Ollama，请先下载安装」 |
| `E_OLLAMA_SERVE_DOWN` | 已装但服务未起 | 「Ollama 服务未运行：请执行 `ollama serve`」 |
| `E_MODEL_DISK_LIMIT` | 模型总占超阈值 | 「模型占用已达上限（{limit}），请先删除不用的模型」 |
| `E_MODEL_LICENSE_DECLINED` | 用户拒绝该模型许可 | 「已取消拉取」 |

## 5 · GPL / 许可边界的可机械校验规则

工单 §4-7 要求「HamLog 任何路径都绝不出现在主包内」。写成可脚本化检查（实现单与 CI 共用）：

1. **打包产物扫描**：解包 `resources/` 后，`**/*hamlog*`（大小写不敏感）命中数必须为 **0**；
2. **清单自证**：`components.json` 中 `license` 含 `GPL` 的条目必须 `forbidden_in_package: true`；
3. **许可落地**：`extract_zip` 类组件解压后必须能读到 `LICENSE*`；`guided_install` 类（HamLog）
   在组件中心卡片上必须显示 `license_caveat` 原文；
4. **模型许可**：`model_catalog` 里 `license_requires_confirm: true` 的模型，`ollama:pull` 前必须
   弹窗（缺 `license` 字段视为 `unknown` ⇒ **同样弹窗**，不许默认放行）。

## 6 · 验收 8 项 → 本清单下的可判定改写

| # | 工单原文 | 本 SPEC 的判定口径 |
|---|---|---|
| 1 | HamLog 检测可靠 | `post_install_check[platform]` 退出码 0 ⇒ `installed`；非 0 ⇒ `failed` 且带 stderr 首行 |
| 2 | 引导不静默跑命令 | 未调 `components:runInstallHint` 即执行 ⇒ 视为缺陷；白名单外命令必 `E_HINT_NOT_ALLOWED` |
| 3 | Ollama 检测跨平台 | 三平台 `detect` 顺序：`ollama`（PATH）→ win `%LOCALAPPDATA%\Programs\Ollama\` / mac `/Applications/Ollama.app` / linux `/usr/local/bin/ollama` |
| 4 | 下载多源 | 按 `urls[]` 中 `platform` 匹配项的 `mirror` 序回退（primary→github→manual） |
| 5 | 模型列表实时 | `ollama:pull` 事件 throttle **500ms**、`percent` 单调不减、结束时必发 `status:"success"` 或错误码 |
| 6 | 磁盘上限 | `ollama:diskUsage.over_limit` ⇒ 拒绝 `ollama:pull`（`E_MODEL_DISK_LIMIT`），阈值取用户设置（默认 50 GiB） |
| 7 | GPL 边界 | §5 的四条机械校验全过 |
| 8 | 模型选择尊重许可 | §5-4 的弹窗规则 |
