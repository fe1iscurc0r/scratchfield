# 记忆混合调研报告 · mem0 / mempalace / cozo / summer_memory 对照

> 日期 2026-08-22 深夜 | 模式：gh API 直读 + 代码实测 | 状态：✅ 完成
> 关联：SPEC-05 五维记忆融合方案

## 一、结论先行

- **融合方式**：RRF（Reciprocal Rank Fusion）替代字符串拼接，5 路信号统一排序
- **索引层**：借鉴 mempalace AAAK 索引卡，新增 `index_cards` 表
- **时间维度**：借鉴 mem0 Temporal Reasoning，五元组 t 字段参与加权
- **存储远期**：cozo 三合一候选（MPL-2.0，与 Apache 兼容，可直接嵌）
- **不整包抄**：三个参考项目各取所需，主链路仍是 summer_memory

## 二、mem0（Apache-2.0）深挖

### 2.1 Multi-signal retrieval（核心机制）
- 语义向量 + BM25 关键词 + 实体匹配 **三路并行打分**，融合后排序
- 实体匹配不是简单字符串：记忆项经实体抽取，查询时做实体级对齐
- NLP 增强需 `pip install mem0ai[nlp]` + spacy 模型

### 2.2 Temporal Reasoning
- 时间感知检索：同一实体不同日期的实例，按"当前/过去/未来"语境选对的那个
- 例：问"当前项目进度"→ 取最近记忆；问"去年做过什么"→ 取当时快照

### 2.3 对 summer_memory 的启示
1. 我们的 P1 GRAG 五元组 = 实体匹配的超级形态（带关系），不需要再抽实体
2. 缺的是"分数统一"——GRAG 命中 + 向量分数 + 关键词命中必须进同一个排序器
3. 时间字段 t 现在只记录不参与排序，是浪费

## 三、mempalace（MIT）深挖

### 3.1 宫殿分层结构
- wings（人/项目）→ rooms（主题）→ closets（压缩索引）→ drawers（原文）
- 检索先定位 wing/room（粗），再看 closet 索引卡（中），最后进 drawer（精）

### 3.2 AAAK 索引卡（核心）
- 名字/词/概念 → AI 可读简写，索引卡指向原文位置
- 作用：长会话主题漂移时，"扫一眼卡片就知道哪段记忆在哪"

### 3.3 后台静默写入
- v4 教训：hooks 前台写 = $1.13/会话 token 消耗
- 改后台 subagent 处理：会话摘要 → 记忆库，不进 chat token

### 3.4 对 summer_memory 的启示
- 加 `index_cards` 表 = 轻量版 AAAK：主题/实体 → 卡片 → 关联五元组 ID
- 写卡走后台异步，不占主对话

## 四、cozo（MPL-2.0）深挖

### 4.1 定位
- 关系 + 图 + 向量三合一嵌入式数据库，Datalog 查询语言，事务性
- 一个库装下：关系记忆、知识图谱、向量检索——终结三套分家

### 4.2 许可结论（已核实）
- MPL-2.0 = 文件级 copyleft：改过的 MPL 文件必须开源，链接/调用不传染
- 与 Apache-2.0（NEKO/scratchpad）组合完全合法
- 修正：之前"MPL 与 AGPL 不兼容需桥接"说法错误，MPL 与 GPL/AGPL 均兼容（§3.3 secondary license）

### 4.3 落地时机
- Phase6（远期）：主链路稳定后试点；当前 Neo4j + SQLite 不拆
- 架构仍走 sidecar 端口挂载（铁律：NEKO 冻结）
