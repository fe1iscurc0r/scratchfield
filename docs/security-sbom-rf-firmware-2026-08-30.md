## 一、问题陈述

SBOM 研究已覆盖 npm/PyPI 包投毒，但 **SDR/无线固件供应链尚属空白**：OpenHDRadio、GNU Radio 模块、ESP32 射频固件等，缺乏信任依赖清单。恶意 RF 固件刷入（如 LTE/5G 小站固件、LoRa 节点固件）无法被系统审计。硬件 hacking 竞赛也揭示 SoC 验证环节的薄弱。

## 二、SBOM 生成设计

为 RF 固件建立**逐环节信任依赖清单**，覆盖 SDR pipeline：

| 环节 | SBOM 项 |
|---|---|
| 天线 / RF 前端 | 硬件型号、驱动固件版本、供应商 |
| 基带 | 基带库、DSP 依赖 |
| 协议栈 | 协议实现库、版本、来源 |
| 第三方依赖 | GNU Radio 模块 / 开源库 / 固件 SDK |
| 许可 & 漏洞 | 许可证、关联 CVE |

### 生成流程
```
固件/依赖清单扫描
  → 逐环节信任依赖建模
  → 关联漏洞库（CVE）
  → 生成 SBOM（含许可 + 漏洞 + 来源）
```

## 三、审计

对现有固件跑 SBOM 生成，输出**风险项**：
- 未声明依赖、隐式依赖；
- 已知 CVE 的第三方库；
- 来源不可追溯的固件模块；
- 许可冲突。
