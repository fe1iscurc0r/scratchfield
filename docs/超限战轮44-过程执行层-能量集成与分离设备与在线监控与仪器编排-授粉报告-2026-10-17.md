## §2 · 最值钱的授粉点（数据结构共鸣）

### A. `openapi-to-sila2`：**工具协议 ↔ 仪器协议，是同一个东西**

SiLA 2 的 Feature Definition 只有四种原语：`Command` / `Property` / `ObservableProperty` / `Parameter`（带数据类型与约束）。对照 Hermes 的工具契约：`tool name` / `params schema` / `returns` / 订阅流。

| SiLA 2 | Hermes 工具层 | 落点 |
|---|---|---|
| Command（有副作用，长任务带回执） | tool call | `mcpserver/sila2_gateway/` 的 dispatch |
| Property（只读查询） | 只读 tool | 设备状态 → `get_status` |
| ObservableProperty（推送） | SSE / 订阅 / cron 轮询 | 频谱扫描流、传感器读数流 |
| Parameter + 数据类型约束 | JSON Schema | 参数校验复用 |

**为什么值钱**：我们手上有 IC-705（hamlib/rigctld）、ESP32-S3 传感器阵列、SDR（SoapySDR）、以及一堆 HTTP 设备。过去每接一个设备写一套 MCP handler；`openapi-to-sila2` 的路子反过来——**设备 API 一次描述，同时暴露成「仪器标准接口」和「agent 工具」**。实验室侧（WEI / atlas / Robochem）认 SiLA2 就能直接编排我们的设备，不需要为 Hermes 写适配层。

这是本轮唯一一处「同一份 schema 同时讨好两个生态」的结构，属 Tier 1。

### B. `pyspc` 的判据表 → 替掉「拍脑袋硬阈值」

现状：守卫是 `星数偏差 >25% → FAIL`、cron 失败就失败——**单点阈值，对漂移瞎**。
SPC 给的是 8 条经典判据（连续 7 点同侧 / 连续 6 点单调 / 2σ 外连续 2 点 / 3σ 外 1 点…），对「慢慢跑偏」比「突然爆表」敏感得多。

- 数据结构同构：`(timestamp, value)` 序列 + 中心线 + 控制限 ↔ 我们的 cron run log JSONL、每轮 star 快照、每轮守卫 WARN 数。
- 落点：`scripts/anti_hallucination_guard.py` 增一层「基线漂移」判据；cron 健康度加 XmR 图（单值-移动极差），**不引入依赖**——判据本身是十行算术。
- 顺手收益：把「本轮 FAIL=0」从结论变成可审计的控制图事实。

### C. `atlas` 的混合参数空间 → 扫货/调度的采集函数

这轮真正的发现不是「又找到一个 BO 库」，是 atlas 支持的**参数空间形状**跟我们面对的问题一模一样：

| atlas 能力 | 我们的对应物 |
|---|---|
| categorical（分类参数） | 扫货角度 / 融合层级（MCP/Skill/耦合/参考） |
| discrete + 混合 | star 区间、候选条数配额 |
| noisy（输入与输出都带噪） | star 会灌水、badge 会撒谎（screenpipe 教训） |
| multi-objective | 价值密度 × 落地难度 |
| multi-fidelity | Discovery-Only 打分（便宜）vs 拉包实测（贵） |
| 已知 + 未知约束 | 许可兼容 / archived / 平台 |
| 搜索空间扩张收缩 | 「这轮扫太窄了」的自动纠正 |

落点用法要克制：**只做「下一轮扫什么角度」的只读建议**，不进决策链、不改流程（旁路铁律）。它给的是 EI/UCB 排序，最终拍板还是人。
附带授粉：IC-705 的天线/匹配网络调谐就是典型 categorical+noisy 多目标问题，atlas 原生支持——这是「实验室 BO」跨到「射频工作台」的一条短路。

### D. 附赠（Tier 3，写着玩但方法真）：夹点 = 最紧的那个约束

pinch 的复合曲线求的是「温差最小的那一点」——最小公用工程量的位置。同构到资源面：API 余额 / 磁盘 / 时间三个累积曲线叠一起，「夹点」就是**最紧的那个约束**（今天磁盘 91% 就是夹点）。不做实现，但当预算告警的表述框架挺好用。
