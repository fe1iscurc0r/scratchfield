# 领域包指南（Domain Pack）

> 卷162 交付 · 让「学科 / 职业工作流」成为声明式配置，核心代码零改动即可新增领域。
>
> 相关代码：`apiserver/domain_pack.py`（加载器）、`apiserver/routes/domains.py`
> （HTTP 端点）、`frontend/src/utils/domainPacks.ts`（前端消费）。
> 相关目录：`domains/`（各领域包）。

---

## 1. 什么是领域包

一个**领域包**是 `domains/<name>/` 下的一个目录，至少包含一个 `pack.yaml`。
它声明该领域的三类信息：

| 声明块 | 作用 | 消费方 |
| --- | --- | --- |
| `eln.fields` | ELN 实验/案例记录的表单字段与 frontmatter 字段 | 前端 `ElnView`、后端 `routes/eln.py` |
| `papers.id_fields` | 文献 / 判例 / 法规的主键字段 | 后端 `routes/papers.py` |
| `source_presets` | 数据来源预设（含版权 / 授权标注） | 前端来源选择、后端入库标注 |
| `tagging.questions` | 打标蓝图问题（卷164 消费） | 打标层 |

此外，包目录下可放**可选代码插件**（如 `importers/`、`eln_templates/`），
实现领域专属的抓取 / 模板逻辑。

**核心设计原则**：核心代码中**不出现**任何 `if domain == "law"` 之类的分支。
所有领域差异都落在 `pack.yaml` 与包内插件里。

---

## 2. 目录结构

```
domains/
  default/                 # 材料科研（默认包，行为等价于改造前）
    pack.yaml
  law/                     # 法学（首个真实领域包）
    pack.yaml
    eln_templates/         # 案例笔记模板
      case-note.md
    importers/             # 数据导入器（本包：法规/判例）
      flk.py
```

- 包目录名**必须**与 `pack.yaml` 里的 `name` 一致，否则加载器拒绝该包。
- 以 `.` 或 `_` 开头的目录会被跳过（预留临时 / 私有目录）。

## 3. pack.yaml 全字段说明

```yaml
# ── 顶层标识 ────────────────────────────────────────────────
name: law                     # 必填。须与目录名一致（domains/law → law）
label: 法学                    # 必填。界面展示名（领域切换器用它）
description: 法学判例与法规工作流  # 可选。一句话说明

# ── ELN 表单 / frontmatter 字段 ──────────────────────────────
eln:
  fields:                     # 有序列表，顺序即字段展示顺序
    - key: topic              # 必填。字段键名（写入 frontmatter 与 API 请求体）
      type: text              # 必填。text | textarea | list | date
      label: 案件名称 *        # 可选。界面 label，缺省用 key
      required: true          # 可选，默认 false。前端提交时校验非空
      show_in_form: true      # 可选，默认 true。见下文「表单 vs frontmatter」

# ── 文献 / 判例主键 ──────────────────────────────────────────
papers:
  id_fields: [flk_id, case_no]  # 必填（若声明 papers 块）。不得为空列表
                                # default: [doi, arxiv_id]

# ── 数据来源预设 ─────────────────────────────────────────────
source_presets:
  - key: pkulaw               # 必填。预设键名
    label: 北大法宝（个人订阅）  # 可选。展示名
    license_note: 个人订阅使用，勿再分发  # 可选。版权 / 授权说明

# ── 打标蓝图（卷164 消费；本卷仅提供结构） ────────────────────
tagging:
  questions:
    - key: 案由分类            # 必填。问题名
      type: choice            # 必填。boolean | choice | score
      options: [合同纠纷, 侵权责任纠纷]  # choice 必填，且不得为空
```

### 字段类型（`eln.fields[].type`）

| type | 前端控件 | 说明 |
| --- | --- | --- |
| `text` | 单行输入框 | 短文本 |
| `textarea` | 多行文本域（`rows=2`） | 长文本 |
| `list` | 多行文本域（`rows=2`） | 多值，按行拆分 |
| `date` | 日期选择器 | `YYYY-MM-DD` |

### 表单 vs frontmatter：`show_in_form` 的意义

字段有两套「顺序语义」，在某些包中二者**刻意不同**：

- **前端表单顺序**：`eln.fields` 的声明顺序（自上而下的控件顺序）。
- **后端 frontmatter 顺序**：导出 Markdown 时 frontmatter 的字段顺序。

`default` 包就是这种情况——改造前它的前端表单不渲染 `attachments`，但导出的
frontmatter 含 `attachments`，且二者字段顺序不同。为了在**不改动页面一个像素**
的前提下保留这一历史行为：

- `default` 的 `eln.fields` 精确复刻改造前 `ElnView.vue` 的手写表单（顺序、label、
  控件类型），并把 `attachments` 标为 `show_in_form: false`。
- `default` 的 **frontmatter 顺序**由 `apiserver/domain_pack.py::_LEGACY_ELN_FIELDS`
  快照保证（`date` 在前、含 `attachments`），不读 `pack.yaml` 的顺序。

新领域包通常无需关心这个区分，让表单顺序与 frontmatter 顺序一致即可
（此时**不要**使用 `show_in_form: false`）。

### ELN 首字段约定

后端 `ElnRecordIn.topic` 是**必填**字段（决定记录文件名）。
因此**每个包的 `eln.fields` 首个字段的 `key` 必须是 `topic`**（`label` 可领域化，
如 law 包写作「案件名称 *」）。不遵守会导致该包创建的记录被后端拒绝。

## 4. 新增领域三步走

以新增「医学」领域包为例：

### 第一步：建目录与 pack.yaml

```bash
mkdir -p domains/medicine
```

`domains/medicine/pack.yaml`：

```yaml
name: medicine
label: 医学
description: 临床病例与循证医学工作流

eln:
  fields:
    - key: topic
      type: text
      label: 病例标题 *
      required: true
    - key: date
      type: date
      label: 记录日期
    - key: chief_complaint
      type: textarea
      label: 主诉
    - key: diagnosis
      type: textarea
      label: 诊断
    - key: treatment
      type: textarea
      label: 治疗方案
    - key: references
      type: list
      label: 参考文献

papers:
  id_fields: [pmid, doi]

source_presets:
  - key: pubmed
    label: PubMed
    license_note: 美国国家医学图书馆开放接口
```

### 第二步（可选）：加代码插件

若需要领域专属模板或导入器，在包内建子目录：

```
domains/medicine/
  pack.yaml
  eln_templates/
    case-note.md          # 记录模板（可复用 _templates_dir() 机制）
  importers/
    pubmed.py             # 数据导入器骨架
```

导入器应遵循 `domains/law/importers/flk.py` 的骨架约定：定义
`load_*_list()` / `parse_*_payload()` / `fetch_*()`，并显式声明抓取间隔常量。
**反爬 / 频控策略不在领域包机制范围内**，由各导入器自行负责（卷163 处理）。

### 第三步：重启（或热加载）即生效

- 后端：领域包在启动时扫描，缓存于 `lru_cache`。改完 `pack.yaml` 后重启
  apiserver 即生效；测试 / 开发可用 `domain_pack.reload_packs()` 热加载。
- 前端：`GET /api/domains` 返回最新 schema；领域路由在应用启动时动态注册。

无需修改任何核心代码。

## 5. HTTP 接口

### `GET /api/domains`

返回全部领域包及其 schema。

```json
{
  "ok": true,
  "default": "default",
  "domains": [
    {
      "name": "default",
      "label": "材料科研",
      "description": "材料科研工作流（默认包，行为等价于改造前）",
      "eln": {
        "fields": [
          { "key": "topic", "type": "text", "label": "课题 *", "required": true, "show_in_form": true }
        ],
        "form_fields": [
          { "key": "topic", "type": "text", "label": "课题 *", "required": true, "show_in_form": true }
        ]
      },
      "papers": { "id_fields": ["doi", "arxiv_id"] },
      "source_presets": [],
      "tagging": { "questions": [] }
    }
  ],
  "warnings": []
}
```

- `eln.fields`：**全部**字段（含不进表单的）。
- `eln.form_fields`：仅 `show_in_form != false` 的字段，前端表单消费这个。
- `warnings`：加载失败被跳过的包会在启动日志记 warning（不炸启动）。

### `GET /api/domains/{name}`

返回单个领域包；不存在返回 404。

### 其它接口的领域参数

- `POST /api/papers/import?domain=law`：按该包 `papers.id_fields` 读写主键。
- ELN 接口：记录写入时若带 `_pack` 字段，则按其 pack 的 `eln.fields` 生成
  frontmatter；未带则按 `default`。

## 6. 容错与降级

领域包机制的容错是**刻意设计**的：领域功能不可用**不应影响核心功能**。

| 故障 | 行为 |
| --- | --- |
| `domains/` 目录不存在 | 记 warning，包列表为空，ELN/Papers 回退到改造前硬编码字段 |
| 某个 `pack.yaml` YAML 语法错误 | 跳过该包（warning），其它包正常加载，启动不失败 |
| 某个包缺 `name` / `label` / `name` 与目录名不一致 | 跳过该包（warning） |
| 前端 `GET /api/domains` 请求失败 | `domainPacks.ts` 返回空列表并记录错误；`ElnView` 回退到内置字段快照 |
| `papers.id_fields` 为空列表 | 该包加载失败（warning），回退 default |

---

## 7. 回归红线（default 包）

`default` 包代表**改造前的行为快照**，是本机制的回归基准：

1. `domains/default/pack.yaml` 的 `eln.fields` 必须与改造前 `ElnView.vue` 的表单
   逐字段一致（顺序 / label / 控件类型）。
2. `apiserver/domain_pack.py::_LEGACY_ELN_FIELDS` 必须与改造前 `eln.py` 的
   `_FRONTMATTER_FIELDS` 逐字段一致（顺序敏感）。
3. `domains/default/pack.yaml` 的 `papers.id_fields` 必须为 `[doi, arxiv_id]`。

上述三条由 `tests/test_domain_pack.py` 断言。修改 `default` 包前**务必**先确认
不会导致现有页面发生任何变化。

## 9. 打标蓝图（AI 自动分类，卷164）

领域包可以声明一组「打标问题」，让判例/文献入库后由 **Von 决策模型**自动分类，
人工只复核低置信项。蓝图写在 `pack.yaml` 的 `tagging.questions`，**不写死在代码**。

### 9.1 schema

```yaml
tagging:
  questions:
    - key: 案由分类            # 标签键（写入 papers.tags 的前缀）
      type: choice            # boolean | choice | score
      options:                # choice 必填、非空
        - 合同纠纷
        - 侵权责任纠纷
    - key: 是否指导性案例
      type: boolean           # 无 options
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `key` | 是 | 标签键。落库为 `{key}:{value}`，如 `案由分类:合同纠纷` |
| `type` | 是 | 仅支持 `boolean` / `choice` / `score` 三种（与 Von 协议一致） |
| `options` | choice 必填 | 候选值列表，非空；模型返回值不在其中即判为无效 |

规则：
- `choice` 缺少 `options` → 该问题在加载时被丢弃（warning），不影响其它问题；
- `type` 不在白名单 → 同上；
- 整个 `tagging` 段缺失 → 该包不支持打标（`tagging_questions` 为空），
  核心 papers 功能不受影响。

### 9.2 喂料策略（重要）

Von 是 **8k 上下文的 encoder**，判决书全文塞不下。因此打标**只用结构化字段**
拼接喂料，而非整篇正文：

1. 【当事人】段
2. 【基本信息】案由 + 法院 + 程序
3. 【诉讼请求】段（定位「诉讼请求 / 诉称 / 请求判令」等锚点）
4. 【本院认为】段（裁判要旨，定位「本院认为 / 本院经审理认为」）

总预算 `MAX_CONTEXT_CHARS = 4000`（≈4000 汉字），**超长截断不抛异常**。

### 9.3 落库与低置信分流

| 输出 | 位置 | 说明 |
| --- | --- | --- |
| AI 标签 | `papers.tags` | **JSON 数组**，如 `["案由分类:合同纠纷","审理程序:二审"]` |
| 置信明细 | `papers.tag_confidence` | JSON：`{questions:{...}, low_confidence:{...}, threshold, ...}` |
| 低置信项 | `_queue/*__tag__*.json` | choice 类置信 < 0.6 的标签**不入库**，进队列待人工复核 |

> **注意**：`papers.tags` 从卷164 起**专供 AI 标签**。卷163 的规则抽取字段
> （法院/程序/案由）改落 `papers.notes`，避免两种语义挤同一列、破坏 JSON 数组契约。

人工复核确认后，置信度改记 `1.0(人工)`（`source="人工"`），并从队列移除该条目。

### 9.4 端点

| 端点 | 作用 |
| --- | --- |
| `POST /api/domains/law/import-cases`（`auto_tag=true`） | 入库后自动打标（Von 离线静默跳过） |
| `POST /api/domains/law/tag-pending` / `tag-cases` | 手动批量为无标签判例打标 |
| `GET  /api/domains/law/tag-pending-preview` | 预览待打标数量（进度条用） |
| `GET  /api/domains/law/tag-queue` | 查看低置信待复核队列 |
| `POST /api/domains/law/tag-confirm` | 人工确认/改选标签 |
| `GET  /api/domains/law/von-status` | Von 在线/离线状态（前端徽章） |

### 9.5 Von 部署与开机自启

Von 是**外部服务**（与 Ollama 同等地位），apiserver **不负责拉起**。
启动时探活，离线则打标功能降级禁用、前端按钮置灰，**不炸服务**。

Windows 开机自启用「任务计划程序」（触发器=登录时，操作=启动 `von serve`），
详见 `docs/von-部署-2026-09-27.md`。
