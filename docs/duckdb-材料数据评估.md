# WO-09: duckdb 材料数据评估报告

> 日期：2026-08-22 晚 | 委托：沈遥自做 | 状态：✅ 完成
> 环境：云服, duckdb 1.5.5, 模拟材料数据 100k 行 + 实验数据 50k 行

## 一、基准测试结果

| 场景 | duckdb | SQLite | 加速比 |
|------|--------|--------|--------|
| 加载 100k 行 | 81.3ms | 79.7ms | 1.0x（平） |
| 单表分组查询（3次均值） | 5.4ms | 12.2ms | **2.2x** |
| 双表 JOIN（3次均值） | 11.7ms | 64.6ms | **5.5x** |
| CSV 直查（零加载） | 74.0ms | 不支持 | — |

## 二、关键能力对比

| 能力 | duckdb | SQLite（现有 RAG） |
|------|--------|-------------------|
| CSV/Parquet/JSON 直查 | ✅ 原生（read_csv 免加载） | ❌ 需先导入 |
| 列式存储压缩 | ✅ | ❌ 行式 |
| 分析型聚合/窗口函数 | ✅ 强 | ⚠️ 一般 |
| 跨文件 JOIN | ✅ | ❌ |
| 全文检索 FTS | ⚠️ 弱（需扩展） | ✅ FTS5（RAG 在用） |
| 嵌入/向量 | ✅ vss 扩展（alpha） | ⚠️ 手动 |
| Python 生态 | ✅ pandas/arrow 无缝 | ✅ 标准 |
| 部署体积 | ~60MB 二进制 | 标准库自带 |

## 三、适用边界结论

**何时该用 duckdb（材料数据分析场景）**：
1. **CSV/Excel 批量分析**——BOM 表、实验数据、MAT 数据直查，免导入，快 5 倍
2. **多表 join 分析**——材料×实验×文献元数据联合查询
3. **分析型报表**——聚合/窗口/透视
4. **内存不够的大文件**——列式压缩 + 外部扫描，1GB CSV 也不怕

**何时不该切（保持 SQLite）**：
1. **RAG 检索主链路**——FTS5 全文检索 + bge-small-zh 向量，duckdb FTS 弱
2. **高频小写入**——对话记忆/会话日志，SQLite 事务快而稳
3. **单文件部署**——SQLite 一个文件走天下，duckdb 多文件/多依赖

## 四、建议落地形态

```
SQLite（现状，保留）          duckdb（新增，旁路）
├── RAG 检索主链路            ├── 材料数据批量分析
├── 记忆/会话存储             ├── CSV 直查工作台
└── FTS5 全文索引             └── 跨表 join 报表
```

- **不破坏现有 RAG 链路**（旁路评估原则 ✅）
