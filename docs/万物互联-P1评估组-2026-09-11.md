## 二、逐候选评估

### 1. AutomationPanda/device-registry-fastapi —— 台账 API 骨架

- **定位**：用 FastAPI 实现的设备注册表服务（`app/main.py:36` 起 FastAPI "Device Registry Service"），CRUD + 分层异常（`app/exceptions.py:16-26` Unauthorized/Forbidden/NotFound 三档）。
- **架构**：Pydantic schema（创建/更新/读出分离）+ 路由分层 + 内存/可替换存储后端——教科书级 FastAPI 工程样板。
- **对照**：本批 W102-07 schema 草案是数据层；此候选是 API 层。两件直接拼合即为台账服务。
- **借鉴点（≥3）**：1) 创建/更新/读出三种 Pydantic schema 分离（防越权字段写入）；2) 分层异常统一转 HTTP 码；3) 「registry 不含控制面」的端点边界设计。
- **许可裁定**：MIT，可借鉴融合。**P1-1。**

### 2. malcolmseyd/natpunch-go —— Wireguard NAT 穿透

- **定位**：Go 实现的 WireGuard NAT 穿透套件（282★）：噪声协议握手 + 抗重放窗口（`antireplay/window.go:42 Reset / :51 Check`）+ 客户端认证加密（`client/auth/auth.go:28 NewCipherState`）。
- **架构**：无中心直连——两端经 STUN/信号交换后直连，WireGuard 隧道承载业务流。
- **对照**：现有桥接栈（frp/Tailscale/Cloudflare）是「有中心转发」；natpunch 方案是「打洞后直连」——低时延/高带宽场景（SDR 频谱流）的第二通道候选。
- **借鉴点（≥3）**：1) 抗重放滑动窗口（`window.go:51`）——探针/命令信道的重放防护可直接借用设计；2) 握手即认证 → 直连隧道两步走；3) Go 单二进制+内嵌配置的部署形态。
- **许可裁定**：MIT，可借鉴；Rust/Go 二进进制不 vendor 原则下，只提炼协议设计（对账 W102 通用约束第 3 条）。**P1-2。**

### 3. pirate/mesh-networking —— Python 组网积木

- **定位**：可插拔通信后端（TCP/UDP/串口/web）的 Python mesh 网络积木集（358★），示例驱动（`examples/butterfly_network.py`、`examples/lan_chat.py`）。
- **架构**：后端接口抽象 + 节点发现 + 消息路由的轻量库，适合实验室拓扑快速搭网。
- **对照**：W102-06 lora-mesh 探针是固件层协议模拟；本候选是同语义的 Python 实验沙盒——组网算法（发现/洪泛/选路）可先在沙盒验证再下沉固件。
- **借鉴点（≥3）**：1) 「后端 = 接口」抽象（同一组网逻辑换物理介质）；2) 示例即测试的契约风格；3) 节点发现包格式的轻量化设计。
- **许可裁定**：MIT，可借鉴。**P1-3。**

### 4. libremesh/lime-packages —— OpenWrt mesh（AGPL）

- **定位**：基于 OpenWrt 的 LibreMesh 包集（338★）：开箱即用社区 mesh 固件生态。
- **架构**：OpenWrt 包集合（LuCI 集成/自动配置/漫游），整套路由固件方案。
- **对照**：本栈自建设备层，不走整机固件路线；价值在配置模型（自动 IP/2.4G+5G 同网/一键入网）的设计参考。
- **借鉴点（≥3）**：1) 「上电即组网」的零配置哲学（新设备接入成本最低）；2) 双频同网+漫游的拓扑设计；3) 社区网格的频道/功率治理约定。
- **许可裁定**：AGPL-3.0——**只参考设计不融合**；任何代码/配置混入受传染（本栈不可接受），落实为「设计要点清单」即可。**P1-4。**
