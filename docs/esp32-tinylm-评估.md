# W70-03 · esp32-tinylm 评估（ESP32 端侧小模型）

> 2026-09-02 · 第二十四期三榜单扫描批 · 勘察/评估（不写实现）
> 上游：Unt1l1f1nd/esp32-tinylm（HF，MIT，dl=435，likes=1，pipeline=text-generation）

## 一、项目定位

面向 ESP32 的 tiny LLM（文本生成），目标是「单片机端侧跑语言模型」——极低内存/算力的解码器模型，用于离线问答/指令/关键词等轻量文本任务。属于「端侧小语言模型」的探索性项目（likes=1，成熟度低，诚实标注）。

## 二、架构拆解

- 极小参数 Transformer 解码器（或 RNN/状态空间变体），参数量压缩到 ESP32 可承载（推测百 K~数 M 级，需按模型卡核实）。
- 量化 + 稀疏 + 流水线推理，面向 ESP32 双核 240MHz + PSRAM。
- 输出：文本生成（补全/极简问答），非实时语音。

## 三、与本仓对照

| 维度 | xiaozhi-esp32（W68-01） | esp32-tinylm |
|------|------------------------|--------------|
| 架构 | 端侧唤醒 + 云端 LLM | 端侧 tiny LLM 全离线 |
| 能力 | 语音交互（云侧智能） | 极简文本生成（端侧智能） |
| 算力 | 云算力 | 单片机算力 |
| 许可 | （已有） | MIT（可借鉴） |

结论：**互补**——xiaozhi 走「端侧唤醒 + 云侧推理」，esp32-tinylm 走「端侧全离线」，前者要网络、后者能力弱但离线可用。

## 四、可落地借鉴点（≥3）

1. **端侧 tiny LLM 的量化/裁剪技术**：把模型压到 ESP32 可跑的参数/内存预算，可借鉴到 NEKO 的端侧语音/文本兜底。
2. **「端侧能跑 vs 云侧」边界判定**：tiny LLM 只能做补全/关键词/极简 QA，复杂推理必须上云——为 NEKO 的「何时端侧、何时云侧」路由提供参考阈值。
3. **离线兜底范式**：断网时端侧 tiny LLM 保底，与 kokoro-onnx（离线 TTS）+ 端侧唤醒形成「全离线 NEKO」拼图。

## 五、端侧能跑 vs 云侧边界结论 + 许可裁定

- **边界**：ESP32 端侧 tiny LLM 只能跑「补全/关键词/模板问答」级任务，毫秒级延迟可接受；生成式长文/多步推理/知识问答不可行，须云侧。
- 许可：**MIT，可借鉴代码**（成熟度低，直接接入价值有限，参考其量化/裁剪思路为主）。
