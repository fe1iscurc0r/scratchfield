## 一、CAAL 工具发现机制拆解

n8n workflow 扫描 → 提取 workflow 的输入/输出 schema → 注册为 MCP 工具 → 调用时路由到对应 workflow 执行。核心三段：**发现 → 注册 → 调用**。

## 二、映射到 Lumo 总线（源→目标→方式→收益）

| 源组件（CAAL） | 目标模块（Lumo） | 授粉方式 | 收益 |
|---------------|-----------------|---------|------|
| n8n workflow 扫描 | mcpserver 工具注册层 | 动态扫描 + 注册协议 | 新增工具零手动接入 |
| 工具描述 schema 提取 | agent-manifest.json 工具清单 | schema 标准化 | 工具描述统一可检索 |
| 调用路由到 workflow | mcpserver 工具分发 | 路由层抽象 | 新工具热插拔 |

## 三、核心数据结构共鸣

- **工具清单**：名称/描述/入参 schema/出参 schema 的统一化。
- **热插拔生命周期**：发现 → 注册 → 启用/禁用 → 注销。

## 四、落地分三步

1. **静态注册改动态扫描**：工具注册层从「硬编码列表」改为「扫描目录/注册表」。
2. **工具描述 schema 统一**：统一入参/出参 schema 字段。
3. **调用路由层抽象**：注册表只存「路由信息」，调用时动态分发。

## 五、结论

**接入（分步）**：三步落地（见上）渐进式改造 mcpserver 注册层，不照搬 n8n；机制借鉴（动态发现/热插拔）价值高。
