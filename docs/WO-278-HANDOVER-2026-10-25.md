## 3. 关键设计决策（以及为什么）

### 3.1 为什么不用「替换全局」而用「暴露工厂」

`contextBridge.exposeInMainWorld(name, value)` 只能**新增**一个命名空间属性。
它**不能**：
- 顶替页面已有的全局构造器（`window.WebSocket = WSProxy`）
- 传递类实例（结构化克隆：函数能过，实例/原型过不去）
- 承载赋值语义（`sock.onopen = fn` 写了也没人收到）

⇒ 唯一出路：**让页面主动从 bridge 拿东西**，然后由页面自己把语义补齐。

### 3.2 为什么中间要加一层 `ws-adapter.js`

原方案要改 `app-websocket.js` 的 `1 处创建 + 4 处 onX= + 32 处 readyState = 37 处`。
加了适配器之后：**只改建连接那 1 处**，其余 36 处调用一个字都不用动。

适配器要补的两处语义（**这两条都有单测守**）：

| 原生语义 | 桥工厂给的 | 适配器补法 |
|---|---|---|
| `sock.readyState` 跟着事件变 | `getReadyState()` 函数（读属性=快照） | 事件驱动维护本地状态 + getter |
| `sock.onopen = fn` 生效 | 不支持赋值 | setter 映射到 `addEventListener` |

### 3.3 为什么 pet 窗建议**不迁**（这是决策，不是偷懒）

实测 `preload-pet.js`（5524 行）读 **23 个页面全局、205 处**（2026-10-25 重测。口径：
`grep -oE 'window\.[A-Za-z_$][A-Za-z0-9_$]*'` 后去掉 `window.X = …` 赋值形式，
再去掉 preload 自己注入的 4 个全局 `nekoSubtitleWindow` / `__forwardSubtitleRenderStateToWindow`
/ `__nekoPetInteracting__` / `nekoActivitySignal`）：

| 全局 | 引用 | 它是什么 |
|---|---:|---|
| `window.mmdManager` | **43** | MMD 渲染器**实例** |
| `window.vrmManager` | **43** | VRM 3D 模型管理器**实例** |
| `window.live2dManager` | **35** | Live2D 管理器**实例** |
| `window.Jukebox` | 21 | 点歌台控制器 |
| `window.lanlan_config` | 12 | 页面配置 |
| 其余 18 个 | 51 | DragHelpers / appState / 截图能力 / 字幕状态… |

`mmdManager` / `vrmManager` / `live2dManager` 都是**活的类实例**（`static/app/app-character.js` 里
`new` 出来的单例，带 WebGL / 3D 上下文），contextBridge 传不过去。
要迁只能把这 121 处实例调用（43 + 43 + 35）**搬进页面**——那不是"迁移 preload"，是**改架构**（5524 行拆分）。
**结论**：拿主窗稳定性换一个配置项，不划算；登记为「已知且已论证的例外」，另立重构单。

## 6. 环境坑（**先读这节，能省你两小时**）

> 这些坑我**已经踩过一遍**，其中前三个我自己的技能 `~/.workbuddy/skills/lumo-stack-startup/SKILL.md`
> 里早有记载（坑二/坑三/坑四），我还是又踩了一次。**动手前先翻那个 SKILL.md。**

### 6.1 Electron 起不来的三个坑

| 坑 | 症状 | 解法 |
|---|---|---|
| **`ELECTRON_RUN_AS_NODE=1`** | 主进程 `require('electron').app` 是 `undefined`，启动即崩（`Cannot read properties of undefined (reading 'setPath')`） | 启动子进程前 `env.pop('ELECTRON_RUN_AS_NODE')`（**WorkBuddy 自己是 Electron 应用，会注入它**） |
| **GPU 进程连崩** | `GPU process exited unexpectedly: exit_code=-1073741819` ×6 → `FATAL: GPU process isn't usable. Goodbye.`；**单加 `--disable-gpu` 无效** | 必须再加 **`--no-sandbox`** |
| **CDP 握手 403** | `Rejected an incoming WebSocket connection from http://127.0.0.1:9222` | `--remote-allow-origins=*` |

另：**Windows 控制台是 GBK**，脚本用 `stdout=PIPE` 会崩解码线程、管道不再排空 ⇒ 子进程写满缓冲就卡死
（表现成"等不到 CDP"）。一律**输出落二进制日志文件**。

### 6.2 NEKO 后端起不来：safe-delete 守卫

NEKO 启动链会用 **node 子进程**做日志清理，被 WorkBuddy 的 safe-delete 守卫拦（>50 文件/回合）
→ launcher 判失败并**回滚退出**。启动前必须清：

```
NODE_OPTIONS
CODEBUDDY_SAFE_DELETE_BULK_GUARD
CODEBUDDY_SAFE_DELETE_BULK_STATE_DIR
CODEBUDDY_SAFE_DELETE_REPORT_PATH
```

### 6.3 本仓（`scratchpad-unified`）后端的两个额外问题

| 现象 | 根因 | 状态 |
|---|---|---|
| `FATAL: lifecycle.py local-patch missing (0/4 expected)` | **上游同步把 `launcher_core/lifecycle.py` 里 4 处 lumo 补丁覆盖了**；`scripts/neko_launcher_wrapper.py` 是 fail-fast 的 | ❌ **待修（真回归）** |
| 用**系统** python 跑上游 `launcher.py`：立刻失败 | `launcher_core/bootstrap.py` 的 `_maybe_reexec_into_project_venv` 用 `os.execv(target, [target] + sys.argv)`；项目路径含空格（`D:\my git …`）时 argv 被拼坏 | ✅ **绕法**：直接用项目 venv 的解释器启动（`NEKO/N.E.K.O/.venv/Scripts/python.exe launcher.py`），48911/48915 实测持续 200 |
| 日志末尾 `EmbeddingWorker ... model_file_missing` | 嵌入模型缺失，该 worker 退出 | ⚠️ **主服务不跟着退**（早前「20 秒自退」是误读） |

另：代码根已从 `D:\my git\scratchpad` 变成 **`D:\my git\scratchpad-unified`**（老路径只剩 `carpet/ docs/ research/`）。

### 6.4 `HTTP_PROXY` 会让本地探测撒谎 ⚠️

会话环境带 `HTTP_PROXY=http://127.0.0.1:63457`。用 `urllib` 探测 `localhost:48911` 会**走代理**，代理回 **502**。

| 观测 | 真实含义 |
|---|---|
| `502` | **代理在中间**，不能作为"后端挂了"的证据 |
| `WinError 10061` | 真没起（必须禁代理才看得到） |
| `200` | 真活着 |

**判据**：探测本地端口必须 `urllib.request.build_opener(ProxyHandler({}))`。
（Node 的 `http` 不走代理 ⇒ 应用自己 `waitForServerReady` 报的"请求错误"是**真连不上**。）

## 9. 术语与坐标

| 词 | 含义 |
|---|---|
| 桥（bridge） | `contextBridge`，隔离世界的 preload 与页面之间唯一的合法通道 |
| 构造器替换 | `window.WebSocket = WSProxy` 这类"顶替页面全局"的手法，**桥做不到** |
| 反向读 | preload **读页面定义的全局**（`window.mmdManager`），**桥也做不到** |
| 双向耦合矩阵 | `docs/WO-278-contextbridge-migration.md` §0.2，按「写→页面 / 读←页面」统计每个 preload |

**关键坐标**：

