## 一、筛选原则

| 维度 | 标准 |
|------|------|
| **可本地跑** | 不依赖外部 API，Windows x64 / Python 3.11+，最好纯 CPU 或 8GB 显存可跑 |
| **可改造** | MIT/Apache-2.0/BSD 许可，代码结构清晰，Python 优先 |
| **旧靶子成立** | 之前有一版工具/方法，但因模型能力不足效果差；新 VLM/LLM 出来后可以翻盘 |
| **新模型有意义** | 新模型（VLM 看图、LLM 推理、ML 预测）带来的提升不是修修补补，是质的飞跃 |
| **可嵌入生态** | 改完后能封装为 MCP adapter 或 Skill，直接喂给陆墨/Hermes |

## 三、靶子 A：论文实验参数自动提取器

### 3.1 旧靶子

```
PDF 论文 → Tesseract OCR 扫描 → 半页乱码 → 手动复制到 Excel
                                    ↑
                              表格错位、公式变乱码、图片完全丢失
```

### 3.2 新模型降维

```
PDF 论文 → Vision LLM 逐页"看懂" → 结构化 JSON → SQLite 数据库
              ↑
        olmOCR (AllenAI, Apache-2.0) / Qwen3-VL / MiniCPM-V
        不是"识别字符"，是"理解内容"——表格、图表、公式全保留
```

### 3.3 改造方案

```
┌─────────────────────────────────────────────────────────────┐
│  输入：一篇木质素水凝胶论文 PDF                                │
│                                                              │
│  ┌──────────────────┐                                        │
│  │  olmOCR /        │  VLM 逐页解析                           │
│  │  MiniCPM-V       │  保留表格结构、识别实验参数上下文         │
│  └────────┬─────────┘                                        │
│           ↓                                                  │
│  ┌──────────────────┐                                        │
│  │  参数提取模块     │  LLM 从 Markdown 中提取结构化字段        │
│  │  (Llama 3.2)     │  前驱体 | 浓度 | 交联方式 | 力学性能...  │
│  └────────┬─────────┘                                        │
│           ↓                                                  │
│  ┌──────────────────┐                                        │
│  │  SQLite 数据库    │  papers.db                             │
│  │                  │  experiments 表                         │
│  └────────┬─────────┘                                        │
│           ↓                                                  │
│  ┌──────────────────┐                                        │
│  │  MCP adapter     │  陆墨：帮我查这 50 篇论文里 KOH 活化     │
│  │  paper_miner     │  温度超过 800°C 的有哪些？               │
│  └──────────────────┘                                        │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 技术栈

| 组件 | 选型 | 许可 | 理由 |
|------|------|------|------|
| PDF 解析 | [olmOCR](https://github.com/allenai/olmocr) | Apache-2.0 | SOTA PDF→Markdown，支持表格/公式/图注 |
| 本地 VLM | MiniCPM-V-2.6（8B，可 CPU 跑）或 Qwen3-VL-8B | Apache-2.0 | 8GB 显存可跑，中文理解好 |
| 参数提取 | Llama 3.2 3B / Qwen2.5 7B | Apache-2.0 | 轻量，纯文本推理，从 Markdown 提取 JSON |
| 数据库 | SQLite（Python stdlib） | Public Domain | 零依赖 |
| 嵌入 | MCP adapter + 陆墨 tool | — | 和 headroom/vulnclaw 同模式 |

### 3.5 你的即时收益

- 5 篇锚点综述 PDF → 自动提取实验参数 → 写综述 Section 4"构效关系"时有数据对比表
- 后续文献读得越多，数据库越厚，综述越有底气
- 最终可以挂到陆墨上：_"陆墨，木质素水凝胶里用戊二醛交联的论文有哪些？压缩模量超过 10 MPa 的有几个？"_

## 四、靶子 B：生物质碳化导电率预测器

### 4.1 旧靶子

```
做碳化实验 → 试 10 组参数 → 测导电率 → 不理想 → 再试 10 组 → ...
                                              ↑
                             纯经验试错，每轮 6-8 小时管式炉
```

### 4.2 新模型降维

```
输入：前驱体来源 + 升温速率 + KOH 比例 + 碳化温度 + 保温时间
  ↓
ML 模型（随机森林/BP 网络/梯度提升）
  ↓
输出：预测导电率 (S/cm) + 比表面积 (m²/g) + 孔隙率 (%) + 置信区间
  ↓
实验设计：模型建议下一批最有信息量的参数组合
```

### 4.3 改造方案

```
┌─────────────────────────────────────────────────────────────┐
│  现有基础：maml (MAterials Machine Learning, BSD-3)          │
│  + pymatgen (材料学数据结构，BSD)                            │
│                                                              │
│  ┌──────────────────┐                                        │
│  │  maml 改造层      │  适配软物质/生物质领域                  │
│  │  - 特征工程       │  前驱体指纹（木质素类型/灰分/分子量）    │
│  │  - 模型选择       │  RandomForest / XGBoost / BP-NN       │
│  │  - 主动学习       │  贝叶斯优化下一组实验参数               │
│  └────────┬─────────┘                                        │
│           ↓                                                  │
│  ┌──────────────────┐                                        │
│  │  数据集构建       │  从已有文献 + 自己实验数据建训练集       │
│  │  carbonization.db │  每行：参数 → 导电率/比表面积/产率      │
│  └────────┬─────────┘                                        │
│           ↓                                                  │
│  ┌──────────────────┐                                        │
│  │  CLI + Web UI    │  python -m biopred "秸秆+KOH 800°C"    │
│  │  biopred         │  → 预测导电率 12.3 S/cm (CI: 8-17)     │
│  └──────────────────┘                                        │
└─────────────────────────────────────────────────────────────┘
```

### 4.4 技术栈

| 组件 | 选型 | 许可 | 理由 |
|------|------|------|------|
| 基础框架 | [maml](https://github.com/materialyzeai/maml) | BSD-3 | 现成的材料 ML 接口，省写脚手架 |
| 数据结构 | [pymatgen](https://github.com/materialsproject/pymatgen) | BSD | 材料数据结构标准（需扩展非晶/软物质） |
| ML 后端 | scikit-learn + XGBoost | BSD/Apache-2.0 | 成熟稳定，CPU 友好 |
| 数据积累 | 文献提取（靶子 A 的输出）+ 自己的实验记录 | — | A + B 联动 |

### 4.5 双学位论文素材

- 这就是标准的"材料+计算机交叉"课题
- 够一篇中文核心 or 普通 SCI
- 和综述不冲突——综述是理论框架，这个是方法落地

## 五、靶子 C：LLM4Decompile MCP 封装

### 5.1 旧靶子

```
二进制 DLL → Ghidra/IDA 反编译 → 伪 C 代码 → 人工逐行读
                                     ↑
                          不可再编译、变量名丢失、控制流混乱
```

### 5.2 新模型降维

```
二进制 DLL → LLM4Decompile → 可再编译的 C 代码
                  ↑
         DeepSeek-Coder 微调、反编译专用 LLM
         可再执行率超 GPT-4o，变量名语义恢复
```

### 5.3 改造方案

```
┌─────────────────────────────────────────────────────────────┐
│  已有：/home/ubuntu/github_haul/mcp/LLM4Decompile.tar.gz     │
│                                                              │
│  ┌──────────────────┐                                        │
│  │  LLM4Decompile    │  解包 → 本地 Python 环境配置            │
│  │  本地化部署       │  测试：输入 test.dll → 输出 test.c     │
│  └────────┬─────────┘                                        │
│           ↓                                                  │
│  ┌──────────────────┐                                        │
│  │  MCP adapter     │  mcpserver/adapters/llm4decompile.py   │
│  │  llm4decompile   │  工具：decompile_binary(path) → C 源码  │
│  └────────┬─────────┘                                        │
│           ↓                                                  │
│  ┌──────────────────┐                                        │
│  │  Trae IDE 调用    │  "帮我把 RemoteUtility.dll 反编译"      │
│  │  → 陆墨 → MCP    │  → 源码倒入 Trae → 开始分析             │
│  └──────────────────┘                                        │
└─────────────────────────────────────────────────────────────┘
```

### 5.4 工期短的理由

- 仓库已有 tar.gz，解包即用
- MCP adapter 框架成熟，照着 vulnclaw/headroom 模板抄
- 核心改动只是：本地路径配置 + 模型下载 + MCP 工具注册

### 5.5 即时应用场景

- **RS-BA1 v2 P3 替代方案**：静态逆向提取 CUDPCtrl2 magic 字节（capstone + pefile 已就位）
- **驱动逆向工具链**：之前讨论的 USB 驱动洁净室方案，LLM4Decompile 直接把反编译质量拉满
- **任何 Windows 闭源二进制分析**：Trae 一键出源码

## 六、靶子 D：论文 PDF → Markdown 知识管线

### 6.1 旧靶子

```
arxiv 下载 PDF → pypdf 提取文本 → 公式乱码、表格错位、图表丢失 → 手动修
```

### 6.2 新模型降维

```
PDF → Docling（IBM, MIT）→ 保留表格/公式/图注结构
    → MarkItDown（微软, MIT）→ 统一 Markdown
    → Obsidian / 向量库 → RAG 可检索
```

### 6.3 改造方案

```
┌─────────────────────────────────────────────────────────────┐
│  papers/input/                                               │
│    ├── review1.pdf                                           │
│    ├── review2.pdf                                           │
│    └── ...                                                   │
│       ↓                                                      │
│  ┌──────────────────┐                                        │
│  │  Docling          │  结构化解析：保留 Tables/Figures/Captions │
│  └────────┬─────────┘                                        │
│           ↓                                                  │
│  ┌──────────────────┐                                        │
│  │  MarkItDown       │  统一输出 Markdown                     │
│  └────────┬─────────┘                                        │
│           ↓                                                  │
│  papers/output/                                              │
│    ├── review1.md     ← 表格完整、公式可读、图片保留原位        │
│    ├── review1_images/                                        │
│    └── ...                                                   │
│       ↓                                                      │
│  ┌──────────────────┐                                        │
│  │  Obsidian Vault   │  直接导入 → 双向链接 → RAG 检索         │
│  │  或向量化入库     │                                        │
│  └──────────────────┘                                        │
└─────────────────────────────────────────────────────────────┘
```

### 6.4 技术栈

| 组件 | 选型 | 许可 |
|------|------|------|
| 结构化解析 | [Docling](https://github.com/DS4SD/docling) | MIT |
| 格式统一 | [MarkItDown](https://github.com/microsoft/markitdown) | MIT |
| 产物格式 | Markdown（Obsidian 兼容） | — |

### 6.5 工期最短

- 两条命令的事，主要工作在路径配置和批量脚本
- 可以和靶子 A 合并——A 是 VLM 精读，D 是批量粗转
- A + D = 完整的"文献摄入管线"
