# SPEC · NEKO 资产管线（PSD → 可动模型，2026-10）

> 工单 263 任务 B。**只写标准流程**，不含实现；桥接工具见 `tools/psd2live-bridge/`。

## 1. 输入规范（PSD 分层命名约定）

| 层名前缀 | 含义 | 必需 |
|---|---|---|
| `#body` | 身体基座 | ✅ |
| `#eyes` / `#eyesL` / `#eyesR` | 眼部（可分左右） | ✅ |
| `#mouth` | 口部 | ✅ |
| `#brow` | 眉 | ✅ |
| `#hair_*` | 头发（`*` 为序号，用于物理分组） | 建议 |
| `#arm_*` / `#leg_*` | 四肢 | 按角色 |
| `_ref` 后缀 | 参考层，不参与绑定 | 可选 |

**规则**：
1. 每个部件层必须是**独立栅格层**，不合并、不用图层组代替；
2. 部件层不得有半透明遮罩外的杂色（会污染网格生成）；
3. 画布尺寸与角色卡 `meta.json` 里的 `canvas` 一致，否则导出失败。

## 2. 导出目标

| 目标 | 说明 | 许可 |
|---|---|---|
| `p2lrt` | 中立运行时模型（本仓默认） | MIT 段 |
| Cubism 目标 | 需 GPL-3.0 段 + Cubism SDK | ❌ 本管线不使用 |

**只走 `p2lrt`**：Cubism 导出目标属 GPL-3.0 且需 Cubism SDK 授权，不在本管线范围内。

## 3. 流程

```
PSD（符合 §1 命名）
  → 层分离与网格预处理（上游 format-model 的输入格式）
  → 中立绑定 IR（JSON）
  → format-compile（MIT 段）编译
  → .p2lrt（runtime/ 播放）
  → 角色卡登记（carpet/N.E.K.O/character_cards/<name>/）
```

## 4. 失败回退到手工绑骨的条件

| # | 条件 | 判定方式 |
|---|---|---|
| 1 | PSD 缺 `#eyes`/`#mouth`/`#brow` 任一必需层 | 脚本前置校验直接拒单 |
| 2 | IR 参数数量 ≠ 角色卡声明的表情数量 | 比对 `meta.json.expressions` 长度 |
| 3 | 同一 PSD 连续两次编译 hash 不同 | `sha256sum` 比对 |
| 4 | 网格自交或权重越界（目视/工具报错） | 工具输出 `warn`/`error` |

任一命中即**退回手工绑骨**，并把该 PSD 记入 `docs/` 的失败样本，供规则迭代。

## 5. 与现有资产的边界

- 现状：`carpet/N.E.K.O/character_cards/` 里的角色卡是**手工绑骨**产物；
- 本管线**不迁移**既有资产，只用于新增角色；
- 既有资产迁移需单独评估（绑定参数是否可逆）。

## 6. 不承诺

- 不承诺一次成型（首次编译后仍需人工检查网格）；
- 不承诺支持 Cubism 导出目标（GPL + SDK 授权双重门槛）。
