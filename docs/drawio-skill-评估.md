# W67-04 · drawio-skill 接入评估（可维护架构图生成）

> 2026-09-02 · 第二十一期 GitHub 新扫货批 · 评估（不写实现）
> 上游：Agents365-ai/drawio-skill（MIT，8932★，2026-03，Python）

## 一、项目定位

从「文本描述 + 真实源文件」生成**可维护的 .drawio 架构图**：引入 Diagram IR（中间表示）+ source-kind 引用，让生成的图可编辑、可回源（每节点标注来源文件/代码位置）。

## 二、架构拆解

- 输入：自然语言 + 源文件（代码/文档/配置）。
- 中间表示：Diagram IR（节点/边/分组/来源引用的结构化 IR）。
- 输出：.drawio XML（可编辑）——比「一次性 SVG」多了可维护 + 可回源能力。

## 三、与本仓对照

| 维度 | 本仓 architecture-diagram skill | drawio-skill |
|------|--------------------------------|-------------|
| 输出 | SVG（暗色，一次性） | .drawio XML（可编辑） |
| 回源 | 无 | source-kind 引用（每节点标来源） |
| 许可 | 本仓 | MIT（可借鉴） |

## 四、可落地借鉴点（≥3）

1. **Diagram IR 中间表示**：节点/边/来源引用的结构化 IR，解耦「语义理解」与「渲染」，可借鉴到本仓架构文档 skill 的生成管线。
2. **source-kind 引用（可回源）**：图节点标注来源文件/代码位置，是「架构图可审计」的关键——本仓 SVG skill 可补此能力。
3. **.drawio 可编辑输出**：生成可维护图（而非一次性图），适配架构文档「随代码演化」的需求。

## 五、是否值得并入架构文档工作流

**结论：值得借鉴（尤其 Diagram IR + source-kind 回源），但不必整体并入**——本仓已有 SVG skill，可把「source-kind 回源 + 可编辑输出」两个点吸收进现有 skill，而非引入 drawio 依赖。

## 六、许可裁定
