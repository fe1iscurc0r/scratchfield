## 2. 各自借鉴点

### Spectrum-Sensing（MIT）
1. **特征四件套**（微分熵/几何功率/Lp-范数/能量）优于纯能量检测的结论与消融表——
   本仓频谱感知/告警门限可加这四特征（计算量小，适合哨兵侧）。
2. **经典 ML 先于深网的对照设计**：低算力设备（ESP32/树莓派）先跑 RF/LR 基线。
3. 真实采集数据集的**场景描述规范**（中心频点/调制/天线/环境）可作本仓自采数据记录模板。

### DroneRF（Apache-2.0，旧）
1. **采集-处理-检测三段式工程结构**（LabVIEW→MATLAB→Python）作为数据集生产线参照。
2. 与 RFUAV 的关系：**DroneRF 旧（2019，4 机型级）vs RFUAV 新（35 机型+raw IQ）**——
   新实验一律用 RFUAV，DroneRF 仅作历史对照与 cite 规范参照。
3. Mendeley 数据集 cite 要求 → 本仓引用外部数据集时的署名清单做法。

### SDR_Hunter（MIT，新，最对口）
1. **双接收机架构**（一路宽扫一路锁定）：本仓若加第二路 SDR/声卡通道，
   照此做「监测不中断 + 命中即锁定」——频谱诊疗主线的直接升级路径。
2. **基线异常检测器**（band baseline → 新信号告警）：防御侧告警的最小可行实现，
   比训练模型轻得多，**建议最先移植**（MIT 可融合）。
3. **合成 mock 设备**：零硬件跑全栈（UI/扫描/DB/跟踪/Web）——与本仓「仿真降级」
   现实完全同构，可借其 mock 接口设计统一 rf_brain 的 sim/real 双源。
4. **91 信号特征库 + 搜索**：识别库内容组织参照（与 W96-01 signals-db 合并设计）。
5. **ATAK/CoT 桥**：态势共享出口；本仓暂无需求，登记不实现。

## 3. DroneRF vs RFUAV 对照说明

- 年代/规模：2019 vs 2024+；机型数 4 级 vs 35；输入：处理后特征 vs raw IQ+谱双形态。
- 许可：Apache-2.0 vs Apache-2.0（均可融合）。
- 结论：**新工作以 RFUAV 为基准**；DroneRF 保留为方法学史对照与 cite 范例。
