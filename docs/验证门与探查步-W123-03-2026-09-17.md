# 探查步骤 + 每轮验证门（卷123 W123-03 · 2026-09-17）

ZCode 的「不 begin large change by immediately editing the first file」+「每轮自动验证 + fail-closed」。
本项把两件事落地：**探查步**（Goal 模式默认第一步）与**验证门**（实现类步骤收尾自动验）。

## 探查步（explore）

- Goal 模式默认模板第一步就是 `explore`：读相关文件/结构 → 输出**理解摘要 + 最小改动路径**
- 步骤收尾时 `finish_step_with_verify` 会从结果文本里挑出 `.py` 路径写进任务 `file_refs`
  （去重保序），后续验证门与任务上下文都用它
- 摘要**必须给**：explore 步收尾时若结果为空，会留一条 `status=warn` 的轨迹
  （「探查步骤未给出理解摘要/最小改动路径」），不静默跳过

## 验证门（`apiserver/task_verify.py`）

触发：`record_step_result` / `[TASK]` 段把 **type=code/test** 的步骤置 done 时，
经 `task_flow.finish_step_with_verify` 先过门（explore/verify 步不过门，避免自证循环）。

| 优先 | 目标选择 | 说明 |
| --- | --- | --- |
| 1 | 受影响的测试文件 | 从 `file_refs` 与步骤文本里挑 `test*.py` / `tests/` 路径 |
| 2 | 语法门 `python -m py_compile <files>` | 没有测试可跑时的最低门槛 |
| 3 | 跳过 | 既无测试也无可编译文件 → 记「跳过」（**不判失败**） |

关键细节：**只验工作区里真实存在的文件**。任务 `file_refs` 里可能有「计划提到、这一步还没写」的
路径——拿它当目标会把「还没轮到写」误判成验证失败（实测踩到，已修）。

### 正交结果字段（对齐 DSH 失败纪律）

```json
{"mode": "pytest|py_compile", "ran": true, "ok": false, "exit_code": 1,
 "passed": 0, "failed": 2, "errors": 0, "skipped": 0,
 "timeout": false, "error": null, "detail": "[失败用例名/输出尾]", "targets": [...],
 "audit_only": false}
```

`timeout / error / exit_code / passed / failed` 分开，不用一个 ok 糊住所有失败形态。

### fail-closed 与重试窗口

| 情形 | 步骤 | 任务 |
| --- | --- | --- |
| 验证通过 | `done`（结果行附 `[验证门 pytest] 通过（…）`） | 全部完成 → `review` |
| 验证失败，**还有**重试额度 | `blocked`（结果行写明失败明细，提示模型照着改） | **保持 `running`**，让模型继续修 |
| 验证失败，额度用尽 | `blocked` | `blocked`（不再往下走，等用户决定） |
| `task_flow.verify_audit_only=true` | 照模型申报落 `done` | 不受影响（只记审计） |

额度 = `task_flow.verify_max_retries`（默认 2），计数落在步骤的 `verify_attempts`；
第 1 次失败后剩余 = `max_retries - (attempts - 1)`。

## 与卷119 工具安全门的关系

| | W119-03 tool_gate | W123-03 verify gate |
| --- | --- | --- |
| 时机 | 工具**执行前**（TOOL_PRE_EXECUTE waterfall） | 步骤**完成后** |
| 内容 | 审计 / 敏感工具 / 熔断 / 写操作确认 | 跑测试或语法门，判成败 |
| 审计通道 | `audit/tool_calls.ndjson`（`phase=pre/post/veto/confirm_gate`） | 同一个文件（`phase=verify_gate`） |

两者是同一条安全体系的两端：门前拦危险工具，门后验实际效果。

## 实测证据

失败→改→复验（`--gate-demo`，直接对真实工作区跑门，不经 LLM）：

```bash
.venv/Scripts/python.exe tools/e2e_task_flow.py --gate-demo --session e2e-gate
```

```
[GATE] s1 状态=done，file_refs=['utils.py', 'tests/test_utils.py']
[GATE] 第一次验证：mode=pytest ok=False passed=0 failed=2 errors=0 exit=1 timeout=False
[GATE] 步骤状态=blocked 任务状态=running retry=True 剩余额度=2
[GATE] 结果行：实现：slugify 保持直接返回 text｜[验证门 pytest] 未通过（exit=1，passed=0 failed=2 …）：
       ['tests/test_utils.py::test_slugify_spaces', 'tests/test_utils.py::test_slugify_lowercases']
[GATE] 第二次验证：mode=pytest ok=True passed=2 failed=0 exit=0
[GATE] 最终：步骤=[('s1','done'),('s2','done')] 任务状态=review
```

目标模式全链路（真实 LLM，`--seed-broken`）：探查 → [PLAN] 4 步 → 确认 → 实现步落盘 →
**每个实现类步骤收尾自动带出 `[验证门 pytest] 通过（exit=0，passed=2 failed=0）`** → 任务 `review`。
