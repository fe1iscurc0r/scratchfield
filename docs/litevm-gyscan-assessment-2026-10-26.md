## 二、LiteVM 评估

### 2.1 三种运行模式

| 模式 | 隔离手段 | 需 root | 需 KVM | 速度 | 隔离强度 |
|---|---|---|---|---|---|
| **proot** | ptrace 拦截 syscall | ❌ | ❌ | 秒级 | 弱（可绕过） |
| **chroot** | Mount/PID/UTS/IPC/Net NS + userns | ✅ | ❌ | 秒级 | 中 |
| **VMM** | Firecracker microVM（真硬件虚拟化） | ❌ | ✅ | 亚秒级 | 强 |

VMM 网络架构：TAP(`litevm-tap0`) + NAT(MASQUERADE) + dnsmasq DHCP，宿主 `172.16.0.1` / guest `172.16.0.x`，
由 systemd 服务 `litevm-network.service` 托管（重启自动恢复）。

镜像管理 `pm` 子命令：`pm list` / `pm download`（交互式）/ `pm make`（debootstrap/pacstrap 现构建）。
支持 Void / Ubuntu / Alpine / Arch / Kali / Debian，源走清华 + 中科大镜像。
另有 i18n（中英自动切，`~/.config/litevm/lang` 覆盖）和 Termux 支持。

### 2.2 实测验证（本机真实执行，非读 README 推断）

**编译**：`go build ./cmd/litevm` 一次通过（Go 1.26.2）→ 19.7 MB 动态链接 ELF，`litevm version 1.2`。

**`--check` 自检**：运行时环境/用户组/CPU架构/32位兼容/内核版本/SELinux/存储/proc 全 ✓；
proot ✓；**KVM ✗、firecracker ✗**（云服为容器化腾讯云实例，无 `/dev/kvm` —— 环境限制，非项目缺陷）。

**proot 模式实跑通过**（Alpine 3.20.3 minirootfs）：

```
uid=0(root) gid=0(root)          ← 容器内是 root
3.20.3                            ← Alpine 自己的版本
/  →  bin dev etc home lib ...    ← 看到的是 rootfs 目录树
宿主 /home → 空                   ← 隔离生效
```

rootfs 内 `/etc/resolv.conf` 含 "Generated by litevm" → 镜像准备管线确认可用。

### 2.3 发现的真问题（可反馈作者，5 条）

| # | 问题 | 位置 | 影响 | 建议 |
|---|---|---|---|---|
| 1 | **proot 版本不兼容** | `internal/proot/proot.go:145`、`alpine-proot.go:98` | 硬编码 `--kill-on-exit`（需 proot ≥5.2.0），Ubuntu 24.04 官方源仅 5.1.0 → 直接报 `unknown option` 退出 | 加 `proot --help \| grep kill-on-exit` 探测，缺失则省略该参数 |
| 2 | **安装脚本未定义变量** | `GYscan_install.sh:29`（GYscan 包内） | `set -euo pipefail` + 未定义 `WEBGUI_SRC` → `unbound variable` 崩 | 补 `WEBGUI_SRC=""` / `WEBGUI_DIR=""` 初始化 |
| 3 | **Linux 包缺 exploitdb** | GYscan v3.7.2 Linux tar.xz | `gyscan/` 下只有 `gyscan` 一个文件，无 `exploitdb/` → 安装脚本第 24 行判定「缺少核心文件」退出 | Linux 侧补 Exploit-DB（`git clone --depth 1` GitHub 镜像），或包内附带 |
| 4 | **seccomp 名不副实** | `internal/security/security.go` `ApplySeccomp()` | 函数名声称 seccomp，实际只设 `PR_SET_NO_NEW_PRIVS`，未装任何过滤器 | 改名或补真实过滤器 |
| 5 | **VMM 未启用 jailer** | `internal/vmm/vmm.go` `buildConfig()` | Firecracker API socket 未走 jailer（`--no-new-idmap` 等），多租户下 socket 权限隔离弱 | VMM 模式加 jailer 参数 |

### 2.4 安全面审查

**✅ 干净**
- 外联全为官方源：Firecracker S3 (`s3.amazonaws.com/spec.ccfc.min`)、清华/中科大/Ubuntu/Debian/Arch/Kali 官方镜像、Firecracker GitHub releases、proot 官方仓。**无可疑域名、无遥测上报**。
- `internal/security/security.go` 硬化真实有效：
  - procfs `hidepid=2` + 对 `kcore`/`kallsyms`/`self/mem`/`self/exe`/`self/mounts` 等 30 个敏感文件用 `tmpfs size=0` 遮蔽
  - `PR_SET_DUMPABLE=0` + yama `ptrace_scope=3`
  - 丢弃 17 个危险 capability（SYS_ADMIN / SYS_MODULE / SYS_RAWIO / SYS_PTRACE / BPF / CHECKPOINT_RESTORE …）
  - `RLIMIT_CORE=0`、栈限 8MB、`PR_SET_NO_NEW_PRIVS`
- shell 路径白名单 `^[a-zA-Z0-9_/\-.]+$` + 显式拒 `..`；`shell -c` 参数过 `isPrintable` 过滤防命令注入。
- chroot 用 `CLONE_NEWNS|NEWPID|NEWUTS|NEWIPC`，可选 `CLONE_NEWUSER`（uid/gid 映射 + `GidMappingsEnableSetgroups=false`）+ `CLONE_NEWNET`；`SecureChroot` 校验 chdir 后 cwd 必须为 `/`。

**🟡 注意**
- `-z alpine` 与普通 proot 参数数组 **diff 完全一致**，Alpine 独有逻辑仅 `fixAlpineRootfs`（修权限所有权）+ 发行版探测。README 称「专属优化」实际收益主要是权限修正，非性能优化。
- `ApplySeccomp` 见问题 #4。
- proot 隔离弱，仅适合非敌对场景；要真隔离用 VMM。

### 2.5 已知排障

**Exploit-DB 获取路径（GYscan 依赖）**
- 官方 GitLab `gitlab.com/exploit-database/...` → **403**
- GitHub tarball `github.com/offensive-security/exploit-database/archive/refs/heads/master.tar.gz` → HTTP 200 但**只拿到 307 字节空壳**（该仓 master 最新 commit 为 "Moving home"，仓库在迁移）
- 可行路径：`git clone --depth 1 https://github.com/offensive-security/exploit-database.git`
- 工具所需结构：`exploitdb/exploits/` + `files_exploits.csv` + `files_shellcodes.csv` + `platforms/`

**proot 5.5.0 源码编译（绕过 apt 的 5.1.0）**
```bash
git clone --depth 1 -b v5.5.0 https://github.com/proot-me/proot.git
cd proot
sudo apt-get install -y libarchive-dev libtalloc-dev libglib2.0-dev pkg-config
make -C src loader.elf loader-m32.elf build.h
make -C src proot          # → src/proot
```
装完把 `src/proot` 放进 PATH 前面，litevm 立即可跑。

## 六、使用建议（将来启用时）

1. **只在 Kali / 隔离环境跑 GYscan** —— 它自带凭据窃取、WebShell 生成、DoS、提权能力，别放云服生产机。
2. LiteVM proot 模式先解决 proot 版本问题（问题 #1），否则起不来。
3. VMM 模式需要宿主有 `/dev/kvm` —— 云服没有，要么换物理机 / 本地，要么用 chroot 模式。
4. Exploit-DB 需自行下载并按 `exploitdb/` 结构放置（见 §2.5）。
5. GYscan 的账号 + 密钥 + 硬件绑定意味着**换机器要重新申请密钥**（终身 1 组），跨机使用前先规划好。
