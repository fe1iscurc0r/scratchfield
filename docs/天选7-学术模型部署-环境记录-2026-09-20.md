**关键决策依据**：chgnet 是编译型包且**只有 cp312 及以下**的 Windows 轮子，

pip 会退化成源码编译并失败。故 venv 用 **Python 3.12.13**（uv 托管的
`cpython-3.12-windows-x86_64-none`）。这正是"装前必查轮子"救回来的一步。


## 六、已知问题（工单要求逐条记录）

### 6.1 ✅ torch 已换成 CUDA 版（初装为 CPU 版，已按用户指示修正）

> **状态更新（2026-09-20 晚）**：已装 `torch 2.14.0+cu130` 并在 RTX 5060 上实跑通过，
> 详见 **§十**。以下保留初装时的记录作备案。

- **初装现象**：`torch 2.14.0+cpu`，`torch.cuda.is_available() == False`；
  CHGNet 启动日志明说 `CHGNet will run on cpu`。
- **根因**：Windows 上 **PyPI 的 `torch` 默认就是 CPU 构建**；CUDA 轮子只在
  PyTorch 官方索引（`https://download.pytorch.org/whl/cu124` 等）分发。
  工单假设"依赖 torch CUDA（5-7GB）"——用 `pip install chgnet mace-torch` 拿不到 CUDA。
- **影响**：五包功能全部可用（验收全过），但**推理跑在 CPU 上**，性能远低于 5060 应有的水平。
- **补救命令**（未执行，留待确认；下载约 2.5GB）：
  ```powershell
  pip install --index-url https://download.pytorch.org/whl/cu124 --force-reinstall torch
  ```
- **为何未直接执行**：工单未明确要求 CUDA 替换步骤，且 2.5GB 重装会改变已验证的环境；
  按"最小改动 + 先报后做"处理。

### 6.2 CHGNet 权重不走下载（所以它无法用来验证缓存重定向）

- **现象**：`CHGNet.load()` 后 D 盘 HF 缓存仍为空、C 盘也没增长。
- **根因**：chgnet 0.4.2 **把预训练权重打包在 pip 包里**——
  `site-packages/chgnet/pretrained/0.3.0/chgnet_0.3.0_e29f68s314m37.pth.tar`（4.6MB）。
  加载即读包内文件，无任何下载。
- **结论**：工单的"下载权重后 C 盘不应增长"用 CHGNet 是**验证不到**的（无下载行为）。
  改用 MACE（走真实下载）复验，见 §四。

### 6.3 MACE 的缓存**不受 HF_HOME 管辖**（必须补 XDG_CACHE_HOME）

- **现象**：首次 `mace_mp()` 把权重写到 `C:\Users\ASUS\.cache\mace`，尽管 HF_HOME 已设 D 盘。
- **根因**：MACE 默认路径走 XDG 缓存约定（`~/.cache/mace`），由 **`XDG_CACHE_HOME`**
  决定，与 huggingface_hub 的 `HF_HOME` 是**两套机制**。
- **修复**：补设 `XDG_CACHE_HOME=D:\ai\cache\xdg` → 复验权重落 `D:\ai\cache\xdg\mace` ✅
- **残留（已处理）**：首次运行（XDG 未设时）在 `C:\Users\ASUS\.cache\mace` 留下 **31.1MB**——
  已按用户"你看着办"处理：经 **sha256 比对确认与 D 盘副本完全一致**（同一哈希）后
  删除 C 盘副本（D 盘副本保留）。`C:\Users\ASUS\.cache\mace` 现已不存在。
  按工单"不动 C 盘"约束**未删除/未移动**，如实登记；如需清理请用户确认后处理。

### 6.4 环境变量为用户级而非机器级

`setx` 不带 `/M` → 只写 `HKCU\Environment`（机器级需管理员）。已实测确认四项均已写入：
```
HF_HOME=D:\ai\cache\huggingface   PIP_CACHE_DIR=D:\ai\cache\pip
TORCH_HOME=D:\ai\cache\torch      XDG_CACHE_HOME=D:\ai\cache\xdg
```
**注意**：`setx` 只对新开的终端生效——**已开的终端需重开**（或在会话内 export）。

### 6.5 unimol-tools 许可标注与工单不符

工单写 MIT，PyPI classifier 实为 **Apache Software License**。
两者都在供应链白名单内（MIT/BSD/Apache-2.0），**不影响合规**，仅记录出入。

## 十、追加：C++ 编译器与 CUDA 版 torch（2026-09-20 晚，按用户指示）

### 10.1 C++ 编译器：MSVC Build Tools 2022 已装

**动机**：本机原本零编译工具链（`cl`/`gcc`/`clang`/`cmake`/`ninja` 全无，
无任何 VS 安装痕迹）——这会让任何需要源码编译的 Python 包直接失败
（本卷的 chgnet 就是靠「选对 Python 3.12 拿预编译轮子」绕过的，
但这不是长久之计）。

**安装（已执行，winget，exit=0）**：
```powershell
winget install --id Microsoft.VisualStudio.2022.BuildTools \
  --accept-package-agreements --accept-source-agreements --disable-interactivity \
  --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

**验证（工具链定位 + 真编译一个 C 扩展）**：
