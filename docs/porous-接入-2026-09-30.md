## 二、A porespy 管线（✅ 跑通）

### API 版本实测（porespy 3.1.1 vs 2.x 的三处差异——本卷探明并写进探测候选）

| 环节 | 2.x 习惯写法 | **3.1.1 实测** |
|---|---|---|
| SNOW 分割 | `ps.segment.snow` | **`ps.filters.snow_partitioning`**（且**顶层无 `segment` 模块**） |
| snow 返回值 | 裸 ndarray（regions） | **`Results` 对象**（含 `regions/im/dt/peaks`）——须取 `.regions` |
| Otsu 二值化 | `ps.filters.threshold_otsu` | **filters 里没有** → 改用 `skimage.filters.threshold_otsu`（porespy 既有依赖） |
| 孔径键 | `pore.diameter` | **`pore.equivalent_diameter`**（`pore.volume` 也在但语义是体积） |
| 配位数 | `pore.coordination_number` | **无现成键** → 从 `throat.conns` 两端孔索引 `bincount` 计算 |

`pore_analysis.py` 用**候选名探测**（`_resolve_api`）兼容 2.x/3.x，探测结果写进产物 JSON 的 `apis_used`（不静默）。

## 三、B mofdscribe 描述符（⚠️ 上游依赖链不兼容——如实记录，不静默）

`descriptors.py` 逻辑已就绪（featurizer/数据集探测 + 描述符矩阵 + 元数据落盘），但**上游 0.0.8 与当前生态不兼容**，实测三处：

| 障碍 | 实测错误 | 处置 |
|---|---|---|
| 1. `pkg_resources` 缺失 | `No module named 'pkg_resources'`（**setuptools≥81 已移除该模块**，本机原 84.0.0） | ✅ **已修**：降级 `setuptools<81`（装 80.10.2）——matminer 依赖链恢复 |
| 2. `rdkit` 未装 | `No module named 'rdkit'`（mofdscribe 的 featurizers 硬依赖） | ✅ **已修**：经清华镜像装上（`--index-url https://pypi.tuna.tsinghua.edu.cn/simple`，直连 PyPI 下载过慢） |
| 3. **pymatgen API 变更（决定性）** | `cannot import name 'BrunnerNN_relative' from 'pymatgen.analysis.local_env'`（**mofdscribe 0.0.8 依赖旧版 pymatgen API**，当前 pymatgen 已移除该类）——**障碍 1/2 清除后该错误依然拦死 `mofdscribe.featurizers` 的导入** | ⛔ **不做降级**（pymatgen 是研究生态公共依赖，为本卷降级会波及既有模块）→ **登记待上游**（mofdscribe 适配新版 pymatgen） |

**最终结论（终态实测）**：障碍 1、2 已修，但**障碍 3 单独即可拦死** `mofdscribe.featurizers`
的导入（rdkit 就位后错误从 `No module named 'rdkit'` 变为 `BrunnerNN_relative` 导入失败）。
**本报告不把 mofdscribe 写成「已接入」**——它是「适配层代码就绪 + 上游 pymatgen 兼容性待解」，
两条测试在环境不适配时 skip（skip reason 附带本节实测错误原文）。

**已向上游提 issue**：`lamalab-org/mofdscribe`
[#462](https://github.com/lamalab-org/mofdscribe/issues/462)——报告了三个障碍的完整复现链
（pkg_resources / rdkit / **pymatgen `local_env` API 变更**）与当前环境版本，并表明可提 PR。

**给上游的建议**（可选提 issue）：mofdscribe 0.0.8 需放开 `pymatgen` 版本上限或适配 `local_env` 新 API；另外 `pkg_resources` 用法应在 setuptools 81+ 移除前替换。
