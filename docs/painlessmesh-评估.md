# painlessMesh 评估（W71-01）

> 上游：painlessMesh/painlessMesh（GitLab，271★，C++）｜ <https://gitlab.com/painlessMesh/painlessMesh>
> 许可：GPL（GNU 通用公共许可证，仅参考设计不融合）

## 1. 项目定位

ESP8266/ESP32 的**自组织 mesh 网络库**——无主节点、自动路由、节点即插即用，用 Wi-Fi 在设备间
广播 JSON 消息实现网状拓扑，常用于 IoT 传感网与智能家居自组网。

## 2. 架构拆解

- **无主节点（decentralized）**：所有节点对等，任一节点故障不影响网络，靠定时心跳 + 邻居表维护拓扑。
- **自动路由**：节点间逐跳转发（消息带 TTL/去重），无需手工配置路由表。
- **同步机制**：painlessMesh 内含轻量时间同步（节点间时钟对齐，供协作调度）。
- **消息模型**：单播/广播 + JSON payload，业务与组网解耦。

## 3. 与本仓对照

| 维度 | painlessMesh | 本仓 |
|---|---|---|
| 无线侧 | Wi-Fi（2.4G，短距高带宽） | LoRaCanary 433MHz（长距低带宽）|
| 拓扑 | 对等 mesh（无主） | LoRa 星型（v1）+ 对等 mesh（弱链路）|
| 主控 | ESP32-S3 | ESP32-C3/S3 |

**边界结论（验收项）**：painlessMesh 补**短距高带宽 Wi-Fi 侧**自组网，LoRa mesh 补**长距低带宽**
433MHz 侧——两者互补而非替代：近距离多设备高吞吐用 Wi-Fi mesh，远距离低功耗用 LoRa。

## 4. 可落地借鉴点（≥3）

1. **无主节点自组网机制**：心跳 + 邻居表 + 逐跳转发 + TTL 去重的轻量路由，可迁移到 LoRa mesh 的
   对等拓扑（当前 LoRaCanary 偏星型），去掉单点网关依赖。
2. **节点时间同步**：mesh 内轻量时钟对齐，可复用到多 LoRa 节点的 TDMA 时隙分配与协同频谱感知。
3. **「业务/组网解耦」的消息模型**：JSON payload + 单播/广播抽象，借鉴为 LoRa 帧之上的统一消息层
   （二进制帧纪律之外加一层应用协议）。

## 5. 许可裁定

GPL——**只参考设计不融合代码**；若需复用需整体开源本项目相应部分，评估为「设计借鉴」级。

## 6. 结论

可借鉴（设计级）。建议：把「无主 mesh 路由 + 时间同步」思想落到 LoRaCanary 对等网，不动其 433MHz
物理层；Wi-Fi mesh 作为室内/近距离补充形态单独立项。
