# 分布式频谱仲裁 · 方案（S16）

> 工单：S16 分布式频谱仲裁（P0）
> 授粉源：`digest-gx-4c-2026-08-30.md` 过期约束授粉点（Agent 继承记忆中「过期约束」致决策失效，与频谱占用状态「过时」同构）
> 落点：`mcpserver/rf_brain/spectrum_arbitration.py` + `test_spectrum_arbitration.py`（numpy 原型，5 用例全绿）
> 验收：模拟节点声明冲突，仲裁结果与最新真实状态一致率 ≥ 90% —— 实测 **94.75%**

---

## 1. 问题与授粉映射

多 Agent（ESP32 + SDR 节点）协作感知频谱时，各节点持有各自的「占用状态」记忆。节点掉线/延迟
会导致其记忆残留**过期约束**——旧状态未失效时被误当现状，与其它节点的新状态冲突。

`digest-gx-4c` 指出：Agent 继承记忆中过期约束致决策失效。这与「频谱占用状态过时」同构：

| 授粉概念 | 频谱仲裁概念 |
|---|---|
| Agent 记忆中的过期约束 | 过时的频谱占用声明（旧时间戳的状态） |
| 约束失效导致决策错误 | 旧声明压制新声明导致仲裁错误 |
| 约束需带来源/时效 | 声明带 provenance（时间戳 + 来源节点 + 可信度） |

## 2. Provenance 设计

每份占用声明带完整 provenance：

```python
Claim(node, freq, state, t, trust)
# node   = 来源节点 id（谁声称的）
# freq   = 中心频率 Hz
# state  = 占用状态（0=空闲 / 1=占用，可扩展为信道分配 id）
# t      = 声明时间戳（epoch 秒，何时观测到的）
# trust  = 来源可信度 0..1（由 A26 DreamLedger 信用文件滚动更新）
```

`trust` 本模块只消费、不记账——由 A26（`tools/message_ledger.py`）按「确认/超时」滚动更新
节点可信度，两者衔接：A26 输出 trust → 本模块仲裁加权。

## 3. 仲裁算法（无中心节点）

每个节点本地运行同一套确定性逻辑，输入自己收到的声明，即可得到一致裁决：

1. **过时降权**：声明权重 `w = trust × 0.5^(age / half_life)`，`age = now - t`。
   半衰期 `half_life`（默认 30s）内旧声明指数衰减；`age=half_life` 时权重减半。
2. **按状态加权投票**：同一频点、同一状态的声明权重**叠加**（共识增强）。
3. **裁决**：胜出状态 = 累计权重最大的状态；置信度 `conf = 胜出权重 / 总权重`。

因此「新近 × 来源可信」的声明自然压倒「高可信但过时」的声明，无需任何中心节点或全局时钟同步
（只需各节点时钟大致对齐；时钟漂移可并入 `trust` 或加大 `half_life` 兜底）。

## 4. 验收评估（numpy 原型自测）

`test_spectrum_arbitration.py` 的端到端模拟：20 频点、200 时刻、6 节点，其中 5 个「新近节点」
（lag 1–25s）+ 1 个「高可信但滞后 60s」的节点（trust=0.98，无衰减时会误导全场）。真实状态分段
常数、随机翻转，节点按滞后取历史状态 + 独立误报。

- **仲裁一致率 = 94.75%**（≥ 90% 验收线）。
- 关键对照（单元用例 `test_stale_loses_to_fresh`）：单个 trust=0.98 但过时 60s 的声明，
  权重被衰减到 0.245，输给 trust=0.6 但新近 1s 的声明——证明「过时约束」被正确降权。

## 5. 与既有 rf_brain 的衔接

- 独立模块，不侵入 `decision_layer` / `rule_engine` / `schemas`，与现有频谱感知管线解耦。
- 输入：分布式邻居节点经 Mesh（`mesh_layer.py`）汇集的 `Claim` 列表；
  输出：`ArbitrationResult`（winner + confidence + 各状态权重，权重可审计）。
- 纯计算、无 LLM/网络调用，符合 rf_brain 纪律（ESP32 端可本地运行）。

## 6. 诚实降级与未验证项

- 时钟漂移：跨节点时钟不同步会让 `age` 失真。方案以「信任同一时间源（GPS 授时，LoRaCanary
  已带 NEO-6M）」为前提；无授时场景需把漂移并入 `trust` 或调大 `half_life`。
- `state` 目前建模为 0/1；真实频谱仲裁需扩展为「功率档 / 信道分配 / 调制识别」多维状态，
  权重投票结构不变，仅替换 `state` 的取值空间与比较语义。
- 单节点数据是「观测」非「地面真值」，94.75% 是合成场景下的结果，真机需以 SDR 实测回灌复评。
