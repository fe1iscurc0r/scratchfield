## 二、核心数据结构共鸣（附源行号）

1. **所有权凭证是设备身份的载体**：源 `OwnershipVoucher` 把协议版本、头部 HMAC、设备证书链、条目打包成可验结构（`ownershipvoucher.rs:37-45`，字段枚举于 `OwnershipVoucherIndex`）；本探针的 `OwnershipVoucher` 保留 serial/device_id/entries 语义，密码学字段显式退化为引用——台账「设备注册记录」应呼应这一结构（见 W102-07 schema）。
2. **四阶段状态机**：出厂（Manufactured）→ DI（生凭证）→ TO1（`to1.rs:12 HelloRV` 发现所有者）→ TO2（`to2.rs:19` 起完整消息链至 `:478 Done`）→ 上船完成。本探针以 `FdoStage` 枚举复刻同一阶段划分，非法转移显式抛错。
3. **所有权迁移的防抢注语义**：TO2 的 ProveOVHdr/GetOVNextEntry（`to2.rs:93/128`）逐条验证凭证归属后签发 SetupDevice（`:268`）；本探针以「凭证已绑定他主则拒绝」近似这一防重放/防抢注语义。

## 三、难度 × 收益

- 难度：★★☆（纯状态机模拟，无密码学；约 130 行 + 3 测试）
- 收益：★★★（补齐本栈「设备身份建立」机制空白——现状新设备靠手工登记；FDO 流程即台账身份层的注册协议草案）

## 四、结论与接入建议（≥3）

1. **分步接入**：第一步只落「凭证结构 + 状态机」进台账（本探针已给出骨架），设备首次上电时按 FDO 阶段演进登记状态；密码学留待真有厂商设备时再上（Rust 参考实现或 pri-fidoiot 可作互操作验证）。
2. **台账字段对齐**：设备注册记录增加 `voucher_serial / owner_ref / onboard_stage` 三字段（对应 W102-07 schema 草案的安全等级列，见该文档）。
3. **退化路径显式化**：本栈无 TPM/厂商密钥体系，FDO 的 DI 密钥预置应退化为「烧录时写入设备唯一 ID + 服务端签发引用」——探针的 `cred:{id}:{owner}` 即此路径。
4. **Rendezvous 决策点**：TO1 的 rendezvous 服务器天然是「设备接谁家」的调度点，后续可并入 Hermes 决策层做设备归属策略。
