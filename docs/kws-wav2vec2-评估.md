# W70-05 · wav2vec2-keyword-spotting 评估（关键词唤醒）

> 2026-09-02 · 第二十四期三榜单扫描批 · 勘察/评估（不写实现）
> 上游：litert-community/wav2vec2-keyword-spotting（HF，Apache-2.0，dl=80，likes=1，pipeline=audio-classification）

## 一、项目定位

基于 wav2vec2 的关键词唤醒（KWS）：以音频流为输入，检测「指定唤醒词」是否出现。litert-community 出品（面向 LiteRT/TFLite 端侧部署），目标是小模型、低功耗、端侧可跑。

## 二、架构拆解

- 主干：wav2vec2 声学编码器（自监督预训练）→ 分类头（关键词/非关键词二分类或多分类）。
- 部署：导出 LiteRT/TFLite 格式，端侧（手机/MCU）实时音频流 KWS。
- 输入：原始波形或声学特征；输出：关键词命中 + 置信度。

## 三、与本仓对照（KWS vs VAD）

| 维度 | 本仓 VAD（W65-02/03 滞后状态机） | wav2vec2 KWS |
|------|----------------------------------|-------------|
| 作用 | 检测「有人说话/停」 | 检测「特定唤醒词」 |
| 方式 | 能量/状态机（极轻量） | 神经网络（较重） |
| 误唤醒 | 低（只判有无语音） | 可做精准唤醒词 |
| 端侧 | 极轻量（纯逻辑） | 需 LiteRT（中等） |

结论：**互补而非替代**——VAD 做「语音活动检测」（无唤醒词概念），KWS 做「唤醒词精准触发」。二者可级联：VAD 检测语音活动 → KWS 确认唤醒词 → 触发 NEKO。

## 四、可落地借鉴点（≥3）

1. **wav2vec2 特征 + 轻量分类头**：自监督声学编码器 + 分类头做 KWS，可借鉴到 NEKO 语音线的唤醒/意图前置。
2. **LiteRT/TFLite 端侧部署**：wav2vec2 KWS 导出 LiteRT，为「唤醒词在端侧跑」提供部署范式（对应 xiaozhi-esp32 唤醒路线）。
3. **唤醒词词典可扩展**：多关键词分类头，支持角色名/自定义唤醒词（补 NEKO 角色名唤醒）。

## 五、KWS vs VAD 边界结论 + 许可裁定

- **边界**：KWS 解决「说什么」（唤醒词），VAD 解决「有没有说」（语音活动）；NEKO 唤醒链路应为「VAD 触发 → KWS 确认 → 主链路」。KWS 模型较重，适合「端侧常驻轻量唤醒」，复杂交互仍走主 LLM。
- 许可：**Apache-2.0，可借鉴代码**（wav2vec2 权重可按 Apache 使用）。
