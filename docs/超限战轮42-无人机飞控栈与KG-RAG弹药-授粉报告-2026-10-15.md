## §2 · 全新弹药（🆕 13 件，有 LICENSE）

### 2.1 KG-RAG 混合检索线（8 件）

#### 2.1.1 hhy-huang/HiRAG（⭐557 MIT, EMNLP'25 Findings）
- **定位**：「Hierarchical 知识 RAG」—— `HiRAG/Mix/Naive` 三模式 + 可选 LLM 缓存。论文: HiRAG: Retrieval-Augmented Generation with Hierarchical Knowledge (arXiv 2503.10150)
- **与已有差距**：edgequake 是「图嵌入即检索」（激进派），HiRAG 是「分层知识抽取+检索」（保守派）。前者要装图数据库/重索引，后者不动图结构、纯 query 时分层决策。**两者覆盖正交**——scratchpad 现在用的是 edgequake，HiRAG 作为「不想重索引」场景的对照系。
- **落点**：参考系。`docs/HiRAG-hierarchical-对照报告-2026-10-15.md`（用户跑通后建）
- **可拉**：✅ Python 3.10+ + `pip install -e .` 一行起步
- **难度×收益**：难度 1（纯 Python）/ 收益 4（增量能力「分层模式切换」+ 论文背书强）= 优先级 4

#### 2.1.2 XMUDeepLIT/MemGraphRAG（⭐226 MIT, KDD'26）
- **定位**：「Memory-based Multi-Agent GraphRAG」—— **三层记忆（schema/fact/passage）+ 双向链 + 冲突感知 + Personalized PageRank**。同一团队还产：LinearRAG(ICLR'26)、LogicRAG(AAAI'26)、GraphRAG-Benchmark(ICLR'26)、LegalGraphRAG/LogicPoison/BAPO(ACL'26)
- **与已有差距**：edgequake/HiRAG 都是单层图，MemGraphRAG 直接做三层记忆。**最值钱的不是 retrieval 本身，是「schema→fact→passage 三层双向链」——冲突检测/聚合质量对问计 KG 是关键**。
- **落点**：参考系 + 跑评测。读源码 → `docs/MemGraphRAG-三层记忆对照报告-2026-10-15.md`
- **难度×收益**：难度 2（需 OpenAI-compatible endpoint + 本地 embedding）/ 收益 7（KDD 论文 + 团队量产 + 记忆架构可授粉 scratchpad 长期记忆层）= 优先级 3.5

#### 2.1.3 FalkorDB/QueryWeaver（⭐1082 AGPL-3.0, FalkorDB 官方）
- **定位**：Text2SQL 工具——**REST API + MCP + 图谱 schema 理解**。Docker 一键起，Swagger UI 自带。
- **与已有差距**：本仓 scratchpad 「表 KG」 不在路线图，但**Text2SQL = 结构化数据 RAG 的延伸**——如果将来要做「数据对话/数据库对话」，QueryWeaver 是 FalkorDB 系内最短路径（同上游 GraphRAG-SDK）。
- **落点**：暂不落，但 `mcpserver/text2sql/` 接口契约先预留。
- **难度×收益**：难度 1（Docker pull + run）/ 收益 3（能力增量小、依赖 FalkorDB）= 优先级 3（**标 P3 候补**）

#### 2.1.4 FalkorDB/FalkorDB-MCPServer（⭐41 MIT, FalkorDB 官方）
- **定位**：**FalkorDB 官方 MCP 服务**——Node.js 18+，npm `@falkordb/mcpserver@latest` 一行起，提供 graph CRUD + OpenCypher + 只读模式。**mcp-name: glama/FalkorDB/FalkorDB-MCPServer**
- **与已有差距**：本仓现用 `lightrag`-backend（HTTP 客户端），FalkorDB-MCP 补登「图谱后端 MCP」接入路径——**「图即数据」式客服接入需求时，它是产业级最短路径**（同上游 FalkorDB）。
- **落点**：`mcpserver/falkordb-mcp/`（MCP 标准接入）
- **难度×收益**：难度 1（npm install 一行起）/ 收益 4（FalkorDB 官方背书 + MCP 标准 + 同上游）= 优先级 4

#### 2.1.5 verygoodplugins/automem（⭐822 MIT）
- **定位**：**「Long-term memory for AI assistants」—— FalkorDB（11 类 typed relationships）+ Qdrant（embedding）双栈**。**评测硬货**：LoCoMo 85.1% / BEAM 10M 57.4% / LongMemEval full 87.0%。
- **与已有差距**：**scratchpad 长期记忆层目前只有 LightRAG/edgequake 这类 RAG 路径，没有「**类 FalkorDB 关系类型 + 类 Qdrant 向量**」双栈的长期记忆**。automem 是「为 Agent 设计」的长期记忆，关系类型化（11 类）+ 9-component 评分排序 + 一键 Docker/Railway 部署。
- **落点**：融合参考。读源码 → `docs/automem-长期记忆双栈对照报告-2026-10-15.md`
- **难度×收益**：难度 2（需 FalkorDB + Qdrant 两套基础设施）/ 收益 8（**scratchpad 长期记忆层空白填上 + Agent 场景 benchmark 强**）= 优先级 **4** ⭐**P0**

#### 2.1.6 verygoodplugins/mcp-automem（⭐65 MIT）
- **定位**：automem 的 TypeScript MCP 客户端——给 Claude/Cursor/Codex 等 MCP 工具提供「durable graph+vector memory across conversations」。
- **与已有差距**：scratchpad 缺「多平台 MCP 客户端」，这是干净学习样本。
- **落点**：融合参考 → 改造为本仓 Lumo Bus MCP worker。
- **难度×收益**：难度 1（TS 一行起）/ 收益 3 = 优先级 3

#### 2.1.7 wise-vision/ros2_mcp（⭐90 MPL-2.0）
- **定位**：**ROS2 工业级 MCP 服务**——24 个工具，覆盖 Discover/Topics/Services/Actions/Perception/TF 全栈，支持 stdio + Streamable HTTP + SSE 三种 transport**。**mcp-name: io.github.wise-vision/ros2_mcp**（Docker Hub 13,750 pulls）
- **与已有差距**：本仓 ROS2 接入目前是 mcporter_bridge HTTP 转发路径，ros2_mcp 提供「**MCP 标准协议**」原生接入。**与本仓无人机栈（GAAS/Avem 已有）正好组成「决策层 MCP+飞控层」**——值班 agent 可通过 MCP 直接订阅 topic、调用 service。
- **落点**：`mcpserver/ros2_mcp/`（MCP 标准接入）
- **难度×收益**：难度 1（Docker pull + mcp add 一行起）/ 收益 7（**ROS2 MCP 工业级 + 实时性好**）= 优先级 **7** ⭐**P0**

#### 2.1.8 mergeos-bounties/ros2-mcp（⭐12 MIT）
- **定位**：轻量 ROS2 MCP——`pip install git+https://...` 一行起，提供 Grok plugin + stdio MCP。
- **与已有差距**：与 ros2_mcp 功能重叠但更轻量、无 Docker 依赖。**wiservision 已有 Docker，mergeos-bounties 适合「无 Docker 场景」备份**。
- **落点**：融合参考 → `mcpserver/ros2-mcp/`（轻量路径）
- **难度×收益**：难度 1 / 收益 3（备份用）= 优先级 3

### 2.2 无人机飞控/ROS2/SLAM 弹药（5 件）
