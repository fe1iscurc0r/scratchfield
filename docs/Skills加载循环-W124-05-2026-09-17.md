# Skills 技能加载循环（卷124 W124-05 · 2026-09-17）

Hermes 的 skills 模式落到陆墨：**技能清单 → 按意图检索 → 读 SKILL.md → 注入上下文 → 执行 → 回写**。
Lumo 原本有技能导入与 `skills_templates`，但对话层没有「按意图检索 → 注入」这一步——
技能装了也用不上。本项补上这条循环。

## 循环

```
用户消息 ──┬─ 关键词匹配技能库（frontmatter name/description/trigger + 正文关键词）
           ├─ 命中 Top-K（默认 2，阈值默认 2 分）→ 读 SKILL.md 正文（按 token 预算截断）
           ├─ 未命中 → 零注入（省 token，不硬塞）
           └─ 注入 system 层：并入 messages[0]（沿用卷121 的 relay 教训，避免被判注入）
                    ↓
            模型按技能规范执行 → 回写 lumo.skill.invoked 事件（技能名/命中分/注入长度/会话）
```

`agentic_tool_loop` 在开跑前调 `_inject_skill_context`，命中时额外发 SSE `skills` 事件。

## 技能库来源（同名以先出现的目录为准）

1. `<user_data>/skills/public/*/SKILL.md` —— 用户导入/安装
2. `<user_data>/skills/cache/*/SKILL.md` —— 技能市场缓存
3. `apiserver/skills_templates/*/SKILL.md` —— 内置模板（存在时）
4. `skills.extra_dirs` 配置的额外目录

## frontmatter 静态预检

```markdown
---
name: material-query
description: Query material properties ... (≥10 字符)
trigger: 材料, 材料性质, band gap      # 可选，中英文都行
---
正文（按需注入）
```

- `name` / `description` **必填**；非法技能在**扫描时跳过**、在**导入接口被拒**（400）
- 校验函数：`validate_frontmatter()` / `validate_skill_file()`；
  `/skills/import` 已接线（缺字段直接 400，不再等跑起来才发现）

## 匹配与预算

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 命中阈值 | `2` 分 | 英文词命中 +1、中文词命中 +2、技能名命中 +3 |
| Top-K | `2` 个 | 单轮最多注入几个技能 |
| 单技能正文上限 | `1200` 字符 | 超出截断并标注 |
| 角色白名单 | — | 走 Scope（W124-01）的 `role.skills`，桌宠角色可只给桌宠技能 |

## 实测（用户真实技能库，6 个技能）

```
帮我写一篇 Nature 风格的论文摘要和投稿信 → [('nature-writing', 2, 1213 字符注入)]
今天天气怎么样                          → 零注入
```

## 配置（`config.json` 的 `skills` 段）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `max_skills` | `2` | 单轮注入上限 |
| `threshold` | `2` | 命中阈值 |
| `max_chars_per_skill` | `1200` | 单技能正文字符上限 |
| `extra_dirs` | `[]` | 额外技能库目录 |

## 回滚

`skills.enabled=false` 关闭检索注入（技能库与导入接口不受影响）；删 `skill_loader.py` 与
loop 里的 `_inject_skill_context` 即回到无技能注入状态。
