## 一、SigMF 格式拆解

`.sigmf-meta`（JSON 元数据）+ `.sigmf-data`（二进制 IQ）两件套。`core:` 全局字段映射：

| SigMF core 字段 | 含义 | 映射到频谱录音需求 |
|----------------|------|-------------------|
| core:datatype | 数据类型（cf32_le 等） | 频谱 IQ dtype |
| core:sample_rate | 采样率 | 采样率 |
| core:frequency | 中心频率 | center_freq_hz |
| core:datetime | 时间戳 | 录音时间 |
| core:hardware | 设备信息 | IC-705 / RTL-SDR |
| core:description | 描述 | 场景备注 |

## 二、映射到 SPEC-SDR 频谱重做（源→目标→方式→收益）

| 源组件 | 目标模块 | 授粉方式 | 收益 |
|--------|---------|---------|------|
| SigMF 规范 + sigmf-python | 频谱数据层 | 录音/回放元数据标准化 | 跨工具可交换 |
| core: 元数据 schema | 频谱数据结构 | 字段对齐 | 审计可追溯 |
| .sigmf-data 二进制 IQ | 录音存储 | 标准化落盘 | 生态互通 |

## 三、字段对照表（SigMF vs 现有频谱数据结构）

| SigMF | 现有频谱数据 | 对照结果 |
|-------|-------------|---------|
| core:datatype | spectrum_db dtype | 需补（元数据化） |
| core:sample_rate | 采样率 | 已有，需标准化 |
| core:frequency | center_freq_hz | 已有，需标准化 |
| core:datetime | 无 | 需补 |
| core:hardware | 无 | 需补 |

## 四、与 GQRX / Universal Radio Hacker 互操作验证思路

生成标准 `.sigmf-meta`+`.sigmf-data` 后，用 GQRX/URH 打开验证可读——即「录一段频谱带参数回放」升级为 SigMF 兼容格式，未来可直接对接这些生态。

## 五、许可结论（接入边界）

- **规范（CC-BY-SA-4.0）**：只做格式引用/遵循，不抄文档文本——无传染风险。
- **实现（LGPL-3.0）**：作为**依赖引用**（pip 安装动态链接使用），不整包复制进主仓——LGPL 允许动态链接隔离。

## 六、接入建议（≥3）

1. **录音落盘 SigMF 化**：频谱界面「录音」输出标准 `.sigmf-meta`+`.sigmf-data`。
2. **元数据字段对齐**：把 center_freq/sample_rate/hardware/datetime 纳入 core 字段。
3. **回放兼容读取**：回放侧支持读取 SigMF 格式（含第三方录制的 IQ）。

## 七、结论

**接入（分步）**：把频谱数据层「录音/回放」升级为 SigMF 兼容格式；先落盘标准化，再字段对齐，最后回放兼容。许可边界清晰（规范引用 + LGPL 依赖），无传染风险。
