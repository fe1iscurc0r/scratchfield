# 跨总线桥映射（W119-04 · 2026-09-17）

系统里现有五个总线：**Lumo InProcessBus**（`apiserver/event_bus`）· **mcpserver workflow event_bus**
（`mcpserver/workflow/event_bus.py`，JSONL + trace_id）· **NEKO plugin bus**
（`NEKO/N.E.K.O/plugin/core/bus/` + `plugin/server/messaging/`）· NEKO ZMQ agent_event_bus ·
lifecycle_bus。

本卷只桥通三条主线中的两条，**NEKO 上游零改动**：

- **桥 A**：Lumo InProcessBus ↔ mcpserver workflow event_bus（同进程，直接 import）
- **桥 B**：Lumo InProcessBus ↔ NEKO plugin bus（本地适配层 + 传输抽象；实现方为 NEKO 侧用户插件）

实现：`apiserver/event_bus/bridge.py`（`WorkflowBusBridge` / `LumoNekoBridge` / `setup_bridges`）。

## 1. 统一信封

| 字段 | Lumo InProcessBus | mcpserver workflow Event | NEKO bus record（语义对齐） |
|------|-------------------|--------------------------|------------------------------|
| 事件 id | `id`（W119-02 信封，uuid4 hex） | `id` | `message_id` / `event_id` |
| 类型 | `topic`（`Topics.*`） | `event_type`（`task_done` …） | `type` |
| 来源 | `source`（`lumo` / `neko` / `workflow-bridge`） | `source` | `source` |
| 链路 | `trace_id` | `trace_id`（`new_trace_id()`） | `trace_id`（NEKO 侧 `_dedupe_key_from_record` 已按 trace_id 去重） |
| 时间 | `timestamp`（unix float） | `timestamp`（ISO8601） | `timestamp` |
| 载荷 | `payload` | `payload` | `payload` |

桥接事件必须带可去重 id：`id` 在两侧都保留，桥内按 `wf:<id>` / `lumo:<id>` / `neko:<id>` 三个命名空间去重。

**职责边界（沿用卷110 W110-05 洞察）**：NEKO 是 Lumo 的「手」——**命令/呈现语义走桥**，
模型推理与会话状态**不过桥**（避免把 NEKO 变成第二个大脑）。

## 4. 防环去重

- 桥接事件带全局 `id` 与 `source` 标记（`lumo-bridge` / `workflow-bridge` / `neko`）。
- 桥 A：workflow 侧收到 `source == "lumo-bridge"` 的事件**不再提升回 Lumo**（那是桥自己发出去的回声）；
  Lumo 侧收到 `source == "workflow-bridge"` 的事件**不再回桥**。两侧另有按 id 的有界去重窗口（2000 条）。
- 桥 B：命令记录 `source == "lumo"`；NEKO 侧回推同 id 记录被判重丢弃。
- 实测：`test_loop_prevention_dedupes_by_id` 与 `test_bridge_b_command_forward_and_event_promotion`
  覆盖；开发期曾真实触发过 137 次镜像回环 + RecursionError，修的就是这两个判据。

## 5. 挂载与后续

- 桥 A 在 `api_server` lifespan 里挂载：`get_service_instance("workflow").event_bus`
  （workflow MCP 服务实例不可用时只告警跳过，不影响启动）。
- 桥 B 需要 NEKO 侧提供一个实现 `NekoBusTransport` 契约的**用户插件**（订阅/发布走 NEKO 现有插件消息通道，
  不改 NEKO 上游源码）。仓库内现提供 `NekoStubTransport` 供测试与联调；拿到真实 transport 后
  `setup_bridges(lumo_bus, neko_transport=...)` 即可启用。
- 观测：`bridge_stats()` 返回两侧转发计数与 `skipped_loops`；`GET /debug/dump/bus` 的 topic 计数里能看到桥接 topic。
