# Turn 级模型路由 + 反馈飞轮（卷125 W125-01 · W125-02 · 2026-09-17）

参考 OpenSquilla（TokenRhythm 官方 harness，Apache-2.0）的 token 效率机制，**自研实现不整抄**：
每轮按复杂度选「最便宜能胜任」的模型，决策全程留痕，用数据反过来调阈值。

## 保守前提（工单硬要求）

| 约束 | 做法 |
| --- | --- |
| 默认不动现有行为 | `router.enabled=false`（默认）→ `route_override` 直接返回 None，llm_service 一行都不改 |
| 敏感任务不省钱 | 审批/审计/安全/权限/支付 等关键词命中 → **强制强模型**，连 `[CHEAP]` 显式指令都压不住 |
| 调用方指定优先 | 传了 `model_override`（如 VLM 会话）就完全不路由 |
| 预算可配 | `router.daily_budget_usd`（0=不限），超预算回落默认档 |
| 不引入新依赖 | 纯标准库 + 现有 litellm 调用链 |

## 决策信号（都来自已有信息，不额外调模型）

| 信号 | 来源 | 效果 |
| --- | --- | --- |
| 消息长度 | 本轮 messages 总字符 | > `length_threshold_chars`（默认 8000）→ +3 |
| 强任务关键词 | `strong_keywords`（code_exec/test_run/file_write…） | 命中 → +3 |
| 复杂正则 | `complex_patterns` | 命中 → +3 |
| 带工具 | 本轮有 tools | +1 |
| 步骤类型 | 卷123 Goal Mode 的 step type | `step_budget`（explore/test→cheap，code/review→strong）**优先于分数** |
| 显式指令 | 用户文本 `[STRONG]` / `[CHEAP]` | 直接定档（敏感白名单除外） |

分档：≥`strong_score_threshold`（默认 3）走强模型；0 分走便宜档；其余 default 档 =
**沿用现有配置不做覆盖**（这样 fallback 链完全不受影响）。

## 实测（真实决策输出）

```
简单 turn           → cheap  (deepseek-v4-flash-0731) 复杂度 0
复杂 turn           → strong (deepseek-v4-pro-0813)  复杂度 3  理由=['强任务关键词(code_exec,test_run)']
code 步（卷123 step）→ strong                         复杂度 2  理由=['步骤类型需强模型(code)']
敏感 turn（想省钱）  → strong                                    理由=['显式指令[CHEAP]', '敏感任务(审批)→强制强模型']
长上下文            → strong                         复杂度 3  理由=['长上下文(10000>8000)']
```

注意第 4 行：模型本想 `[CHEAP]`，因为撞上敏感白名单被强制拉回强模型 —— 省钱不能省在审批链路上。

## 反馈飞轮（W125-02）

每次决策落 `router_logs` 表（同库 `message_store.db`）：

```
ts / session_id / turn_id / task_type / step_type / complexity / tier / model_chosen
/ reasons(json) / sensitive / cost_estimate / success / latency / tokens / error
```

- 决策在 `route_override` 时记录；turn 结束后由 llm_service 回填 `success/latency/tokens/error`
  （流正常结束 = 成功；认证过期/连接耗尽/异常 = 失败，各带 error 标记）
- 成本按 `router.pricing`（美元/1K token）估算，`estimate_cost(model, tokens)`

### 周度分析 CLI

```bash
python -m apiserver.llm_router analyze --period week            # 打印 markdown 报告
python -m apiserver.llm_router analyze --period week --json     # JSON
python -m apiserver.llm_router analyze --period week --write    # 落盘 docs/router-analysis-<date>.md
```

报告含：各模型调用数/成功率/失败数/成本/tokens/平均延迟、总成本，
以及两类**错配对照**与建议：

| 错配 | 判定 | 建议方向 |
| --- | --- | --- |
| strong-on-simple | tier=strong 但 `complexity<=0` | 提高 `strong_score_threshold` 或补 `step_budget` 的 cheap 映射 |
| cheap-on-failed | tier=cheap 且 `success=0` | 把对应关键词/模式加进 `strong_keywords` / `complex_patterns` |

**调优建议只生成不改配置**（`summary["applied"]` 恒为 false）——人工确认后改 `config.json`，
自动化留作后续迭代。

> 判分口径：错配以**实际结果**为准（走了强模型且复杂度为 0 = 浪费；走了便宜档且失败 = 省出问题），
> 不是拍脑袋按模型名猜。

## 配置（`config.json` 的 `router` 段）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 总开关（灰度开启） |
| `cheap_model` / `strong_model` / `default_model` | flash-0731 / pro-0813 / 空 | 各档模型；default 空=沿用现有配置 |
| `strong_api_base` / `strong_api_key` | 空 | 强档可走独立端点 |
| `strong_score_threshold` | `3` | 达标走强模型 |
| `length_threshold_chars` | `8000` | 长上下文阈值 |
| `strong_keywords` | code_exec/test_run/file_write/… | 强任务关键词 |
| `complex_patterns` | `[]` | 复杂任务正则 |
| `step_budget` | explore/test→cheap，code/review→strong | 卷123 步骤类型映射 |
| `sensitive_keywords` | 审批/审计/安全/权限/支付/… | 命中强制强模型 |
| `sensitive_force_strong` | `true` | 敏感白名单开关 |
| `daily_budget_usd` | `0.0` | 当日预算（0=不限） |
| `pricing` | `{}` | 单价表（美元/1K token） |
| `log_enabled` | `true` | 是否记录决策（飞轮数据） |

`router.enabled=false` 即回到原行为（决策记录也不再产生）；删 `llm_router.py` 与
`llm_service` 里的接线、以及 `router_logs` 表即可完全复原。
