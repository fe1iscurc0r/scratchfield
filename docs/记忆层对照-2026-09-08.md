# 记忆层四件对照（W99-05 · memory_maas v2 机制储备）

> 许可均按工单 gh api 复核记录；本报告只做对照，不写实现、不硬插。

## 一、五件逐一裁定

| 项目 | ★ | 许可 | 形态 | 与 memory_maas 差异 | 裁定 |
|------|----|------|------|--------------------|------|
| engram | 6404 | MIT | Go 单二进制 SQLite+FTS5+MCP+HTTP | 持久化引擎（无 typed 实体层）；FTS5 全文检索是 memory_maas 缺的一块 | **借鉴：FTS5 全文检索机制** |
| kglite | 38 | MIT | Rust+Python 嵌入式 Cypher KG | 内嵌图引擎（无网络服务）；Python 绑定可作内嵌 KG 备选 | **备选：依赖体积/维护状态待核** |
| yantrikdb | 57 | Apache-2.0 | 时间衰减+矛盾检测+自主整理 | 三机制 memory_maas 均无 | **吸收：两机制拆解见下** |
| yantrikdb-hermes-plugin | 84 | MIT | NousResearch/hermes-agent 原生 memory provider | 本仓即 Hermes；与 memory_maas 双记忆体系冲突风险 | **候选：安装即用性待验证** |
| Athena-Public | 585 | MIT | local-first agentic PKM | PKM 应用形态（非记忆引擎） | **仅参考：交互形态** |

## 二、重点①：yantrikdb-hermes-plugin 直接可用性评估

- 定位：Hermes agent 原生 memory provider（MIT，84★）——本仓同生态，理论上安装即用。
- 冲突风险：与 memory_maas 形成「双记忆体系」——两份记忆源、两套 schema，注入/检索重复。
- 结论：**列为候选，不并排硬插**——若未来 Hermes 原生栈需要，作为「应用层记忆适配器」
  挂接（Hermes 工具位），与 memory_maas（仪器层实体图谱）分层共存；插件质量/安装
  验证留接入期实测。

## 三、重点②：yantrikdb「时间衰减 + 矛盾检测」机制拆解（memory_maas v2 吸收候选）

1. **时间衰减**：记忆权重随写入时间衰减（越旧越弱）→ 可映射为 v2 的
   `retention_rule` 升级：从「到期删除」升级为「权重衰减 + 软归档」。
2. **矛盾检测**：新写入与既有记忆冲突时标记/仲裁 → 可映射为 v2 的写时校验扩展：
   `provenance` 之外再加「冲突检测 + 告警」（与供应链铁律同构：来源分级 → 冲突仲裁）。
3. **自主整理**：周期性合并/清理 → 可映射为 v2 的 consolidation 调度（已有 consolidated_from
   雏形，补调度器）。

## 四、kglite Python 绑定可行性（内嵌 KG 引擎备选）

- 依赖体积：Rust 编译产物（wheel），体积中等；维护状态 9-08 活跃。
- 备选判定：若 v2 需要「无 Neo4j 的内嵌图查询」，kglite 是候选；否则沿用现有
  Neo4j/自研图谱层。**备选登记，不立即引入**。

## 五、memory_maas v2 机制建议清单（≥3）

1. **FTS5 全文检索**（源自 engram）：hybrid_search 向量路 + 图谱路之外补全文路（P0）。
2. **时间衰减软归档**（源自 yantrikdb）：retention_rule 从硬删除升级为权重衰减（P1）。
3. **写时矛盾检测**（源自 yantrikdb）：provenance 写时校验扩展冲突仲裁告警（P1）。
4. **consolidation 调度器**（源自 yantrikdb 自主整理）：周期性合并的调度化（P2）。
5. **内嵌图引擎备选**（源自 kglite）：无 Neo4j 环境时的降级路径（P2 备选）。
