# S23 CamoDocs RAG 投毒防御方案

## 0. 结论速览

CamoDocs 的杀伤力在于**绕过「查询包含检测」**：传统 RAG 投毒防御假设「中毒文档会包含攻击者想触发的查询词」，于是检查「文档是否包含查询」。CamoDocs 用「伪装文档 + 分散 token 扩散嵌入」把毒载荷拆散到多个文档/多个位置，使单个文档不包含完整查询，从而让包含检测失效。

## 1. 攻击机制拆解

| 环节 | 做法 | 为何绕过防御 |
|---|---|---|
| 伪装文档 | 毒文档伪装成正常知识，内容与目标领域相关 | 逃过「内容异常」检测 |
| 分散 token 扩散 | 毒触发载荷的 token 分散到多个文档/段落 | 单文档不包含完整查询 → 查询包含检测失效 |
| 检索期激活 | 用户查询命中多个毒片段，拼接后激活毒指令 | ASR 61.8%（GPT-5.4-mini） |

## 2. 防御层设计（≥3）

### 防御 1：跨文档拼接检测（针对分散扩散）
- **设计**：不只检测「单文档是否包含查询」，而是检测「多个文档的检索片段拼接后是否形成可疑指令」。
- **检测指标**：检索窗口内跨文档 token 共现的「毒载荷重构率」——把同一查询命中的 top-k 片段做拼接，跑指令注入检测器。

### 防御 2：来源信誉 + 入库清洗（针对伪装文档）
- **设计**：RAG 入库前按来源历史/签名/血统打分（复用 `mcpserver/trust_layer.py` 的信任评分），低信誉源文档隔离或降权；对「与现有知识冲突」的新文档标记待审。
- **检测指标**：来源信誉分、内容与语料库的语义冲突度。

### 防御 3：检索结果确定性溯源（针对检索期激活）
- **设计**：检索返回的每个片段都带「源文档 ID + 血统」；下游 LLM 只能引用带有效溯源的片段，无溯源的片段被 A34 式起源门控拦截。
- **检测指标**：检索片段的溯源覆盖率、毒片段注入率。

## 3. 边界与待办

- 方案基于 digest 授粉点原文 + RAG 安全常识推理，未读原始论文的完整攻击实现（诚实标注）。
- 防御层的「拼接检测」需真实注入指令检测器，本方案只给设计 + 指标，未实现。
