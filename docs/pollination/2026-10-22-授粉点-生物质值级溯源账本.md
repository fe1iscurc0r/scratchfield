## 1. 借鉴点（机制 → 本侧部件 → 档位）

### 1.1 immutable 样品目录：五层，写清"哪层只增不改"（`2610.27859`）

- **机制**：值级溯源的成立前提是"原料 → 处理 → 测量"这条链上每一层都不可回改；
  一改就断链，数字就退回"报告级"。
- **本侧部件**：五层目录
  1. `raw_material/`（原料批次：供应商、批号、到货日期）— **只增不改**
  2. `pretreatment/`（预处理：温度/时长/气氛，含设备编号）— **只增不改**
  3. `formulation/`（配比：各组分质量、天平编号、环境温湿度）— **新增版本而非覆盖**
  4. `instrument_raw/`（仪器原始文件：二进制原样入库，**不做格式转换**）— **只增不改**
  5. `derived/`（处理脚本 + 脚本哈希 + 输出）— 可重算，但**每次重算生成新版本**
- **档位**：**立即**（目录约定 + 命名规则，零代码）。

### 1.2 表的形态：数值只以指针出现（`2610.27859`）

- **机制**：账本里不该出现"裸数字"，只出现"指向某个原始文件的指针 + 抽取方法"。
- **本侧部件**：见 §2.1 的真实行样例——`value` 列不存数字，存指针；数字由指针+方法**算出来**。
- **档位**：**立即**（表结构定了，后面所有录入才有地方落）。

### 1.3 「拟合不合理就返回 NaN」接进账本：NaN 也要留证据（上轮遗留接口）

- **机制**：上轮定了"拟合不合理返回 NaN"，但**只返回 NaN 不记原因等于丢证据**。
- **本侧部件**：`derived` 层每条记录强制三字段：`status ∈ {ok, nan, failed}` / `reason_code` / `diagnostics_ptr`。
  `nan` 必须带 `reason_code`（如 `R2<0.9` / `参数越界` / `点数不足`），并指向诊断产物（残差图、拟合日志）。
- **档位**：**立即**（与 1.2 同批）。

### 1.4 agent 闭环四步：每步留什么、失败写什么（`2610.27859`）

- **机制**：原文账本同时服务人与 agent，所以"agent 每步动作"本身就是可审计对象。
- **本侧部件**：

| 步骤 | 留什么证据 | 失败时账本写什么 |
|---|---|---|
| ① 配方 | 配方版本号 + 各组分质量 + 天平编号 | `status=failed, reason=称量超差`, 记实际值 |
| ② 表征 | 仪器原始文件指针 + 采集参数快照 | `status=failed, reason=仪器未就绪`, 记设备状态码 |
| ③ 拟合 | 脚本哈希 + 参数 + 残差诊断指针 | `status=nan, reason=R2<0.9`, 记残差图指针 |
| ④ 下批配比 | 采用了哪条拟合 + 哪些被拒 + 拒绝理由 | `status=blocked, reason=上游 nan`, 记阻塞点 |

- **档位**：**本周**（四步是流程约定，账本字段同批加）。

### 1.5 编码侧借鉴一：2D Viterbi 只用于"二维谱图局部损坏恢复"（`2610.27978`，**同构非同一问题**）

- **机制**：2D 卷积码天然适合二维数据；但原文解决的是**编码-译码**问题。
- **本侧部件**：本侧场景是**已有谱图被局部损坏**（坏点/条纹），没有编码端 ⇒ 只能借"二维网格上的路径搜索"这个**结构**，
  不能声称"用了 2D 卷积码"。
- **档位**：**季度**（属于后处理算法，且需先有损坏样本库）。

### 1.6 编码侧借鉴二：ECC 内嵌水印用于 LoRa 遥测元数据溯源（`2610.13357`，**关键是抗时域失同步**）

- **机制**：常规水印怕时域失同步；用纠错码把元数据嵌进信号，能在部分失同步下恢复。
- **本侧部件**：LoRa 遥测帧的**发送端元数据**（节点 ID、固件版本、标定批次）可嵌进前导/载荷冗余位，
  接收端用纠错码恢复。验收必须包含"**故意错开 ±N 个符号**仍能解出"。
- **⚠️ 边界**：原文是 ECG 波形水印（体域信号），本侧是 LoRa 帧；借的是"ECC + 抗失同步"这一对机制，
  不借其医学结论（"波形相似 ≠ 诊断保持"这句只提醒我们别用相似度当唯一判据）。
- **档位**：**季度**（要改帧格式，且与既有协议兼容性需评估）。

## 4. 验收（≥2 个可判定实验）

### 实验 1 · 任意数字可复算（对应 1.2）

- 做法：随机抽 5 行账本记录，只给 `value`/`method`/`diagnostics` 三列，让另一个人（或 agent）复算。
- 判据：**5/5 复算结果与账本一致**（相对误差 <1e-6）；任何一行不能复算即视为该行无效。

### 实验 2 · NaN 有证据（对应 1.3）

- 做法：构造一次必然失败的拟合（如点数 <5）。
- 判据：账本出现 `status=nan` + `reason_code` + **可打开的 diagnostics 指针**；反向对照：
  正常拟合必须 `status=ok` 且 `reason_code` 为空（防止"一律写 nan 交差"）。

### 实验 3 · 只增不改可验证（对应 1.1）

- 做法：尝试覆盖 `instrument_raw/` 下的已有文件。
- 判据：**写入被拒**（权限或 CI 检查），且账本留下 `blocked` 记录；反向对照：在 `derived/` 下写新版本必须成功。
