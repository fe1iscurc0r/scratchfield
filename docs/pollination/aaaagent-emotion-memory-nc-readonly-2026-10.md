## 一、openlabs 半页定性：**值得跟踪**（观察期，不引入）

**是什么**：面向个人的"可恢复、可连续运行的轻量科研工厂"。短生命周期 tick 维护全局任务、租约、
质量门；数学/AI-ML/材料/量化金融/物理五个 Lab **彼此不 import**，只交换**版本化任务文件和结果包**。

**workflow schema 核心**（contracts.py 源码实读）：
- 契约三件套：`openlabs.task.v3`（任务）/ `openlabs.result_bundle.v1`（结果）/ `openlabs.result_receipt.v2`（回执）；
- 结果状态机：`{completed, succeeded, failed, needs_replan, needs_human, quarantined}`，
  其中 **COMMITTABLE = {completed, succeeded, needs_replan}**（可提交 ≠ 领域目标达成——语义切分干净）；
- **编排单元**：Lab runner 只读 task 文件、输出 result_bundle，**不能直写数据库**；控制面校验
  URI/SHA-256 → payload 发布到 objects/sha256/ → 小型引用 manifest 晋升 data 仓 → 暂存清理/失败隔离；
- **断点恢复**：attempt 检查点 + 租约 + 心跳 + 有限重试 + 硬预算（RESOURCE_GUARD：cpu_threads/memory_mib/scratch_mib）。

**对材料线（工单213 快通道）的对口价值**：它的"证据门 + 结果包版本化"正是本科实验数据快通道
长大后的形态（quick_import → result_bundle 化）；**隐藏有序/软模材料 campaign** 与邵长组方向直接同域。

**判定：值得跟踪（低星但设计成熟度高——契约/门禁/隔离三件套比多数高星项目严谨）**。
跟踪点：matfactory 材料协议的 schema 演化；不引入（它的控制面是完整产品，我们的 orchestrator
需求还小，抄契约设计即可——`task.v3`/`result_bundle.v1` 的字段划分可作 lumo 工单协议 v2 参考）。

**⭐ 召回公式**（其代码默认值，含三个半衰期设计）：

```
活跃度半衰期 H = 30 × (1 + 2×I) 天          # 重要性 I∈{0, 0.5, 1} 拉长半衰期（30→90 天）
普通事件活跃度 A(t) = A₀ × 2^(−t/H)
稳定档案类活跃度 A(t) = 1                    # 档案类不衰减
情绪强度 E(t) = E₀ × 2^(−t/7)               # 情绪 7 天半衰期（快衰减）
召回优先级 P = C × (0.55 + 0.25A + 0.15I + 0.05E)
有效强化 A' = A + 0.2 × (1 − A)             # 重提强化有上限（不无限拔高）
门槛：C > 0 且 P ≥ 0.35，至多补入 6 条，受输入预算约束
```

**情绪三层次**：每条消息的观察 O / 用户持续情绪 U / 桌宠持续心情 M——**分别维护、快照不改写历史**、
来源+置信度留档、未知强度=null（≠0）。仅明确重提/确认才触发强化——"浏览/搜索不把记忆越看越重要"
（与 EngramEdit 的复用度保护异曲同工，但方向相反：AAA 保护的是**不被无谓强化**）。

**防误伤设计**：遗忘/纠正的待处理请求有独立保护（旧个人信息暂排除，防未完成的遗忘被下轮重新引用）；
后台整理失败不隐藏历史；回退参数不复活已遗忘内容。
