# EngramEdit → Hermes 记忆更新模式报告（工单223 任务三）

> 日期：2026-10-09 ｜ 论文：**arXiv 2610.10533v1**《EngramEdit: Decoupled Knowledge Updates in LLMs
> through Conditional Memory》（PDF 已精读，目标函数逐字核对）。
> ⚠️ 工单红线遵守：本报告**严格区分训练层机制（论文本体）与推理层应用（我们可借的）**，分两节写。

---

## 第一节：训练层机制（论文在做什么——**我们不做**）

**背景**：DeepSeek Engram 类条件记忆架构用输入 n-gram 查表取已学嵌入，扩充 LLM 容量。
问题：同一事实的不同表达激活不同 n-gram 嵌入；**共享嵌入被多事实复用，更新它会误伤其他事实**。

**EngramEdit 三步**（论文原文）：
1. **算目标表示**：让模型在**多个表达**下都预测出更新后的事实（multi-expression targets）；
2. **联合更新**：解优化——
   > `U* = argmin_U ‖AU − B‖²_F + Σⱼ λⱼ‖uⱼ‖²`
   >
   > A = 嵌入→表示的映射（哪些表达用哪些嵌入），B = 目标表示；uⱼ = 第 j 个嵌入的更新量；
   > **λⱼ 按复用频率加权**——被高频复用的嵌入 λ 大（罚得重），低频的 λ 小（放行更新）。
   > 解析式最小二乘 + 加权岭回归形态（原文给出闭式解）。
3. **只动条件记忆，backbone 冻结**：Transformer 不变，事实更新=改嵌入表。

**效果**（论文实验）：CounterFact/ZsRE 编辑近满分；未见表达与多跳推理可用（MQuAKE CoT 近 3× 基线）；
无关知识与通用能力基本无损。

**为什么我们不做**：这需要**可训练的条件记忆模型**（DeepSeek Engram 架构）。陆墨的 LLM 是 API 调用
（tokenrhythm 网关），无嵌入表可改——训练层机制**整体不适用**，抄了也是摆设。

## 第二节：推理层应用（条目管理层可借什么——本节才是重点）

把论文思想从"嵌入编辑"抽象到"**记忆条目的外科手术式更新**"：

| 论文概念 | 推理层对应（Hermes 记忆体系） |
|---|---|
| 多表达联合目标（一个事实多种说法都要对） | 更新记忆时**同义项的多条目/多别名一起改**（不是只改命中的那一条） |
| 共享嵌入误伤无关事实 | **一条记忆被多处引用时，改它会影响所有引用处** |
| λⱼ 复用频率加权惩罚 | **高复用条目的修改要更谨慎**（复用度=被检索命中/被其他条目链接的次数） |
| backbone 冻结 | 只改记忆层，不动检索索引结构 |

### 与 Hermes 现有记忆的映射（memory 工具 + FTS5 session_search）

现状：Hermes 记忆更新是"**若 full 先清后加**"（全量重写语义）——这正对应论文批评的
"updating shared embeddings can unintentionally change predictions"：全量清加=无条件大改，
无复用度考量。

**可借层**：写入前的**条件触发更新**（而非全量重写）——
1. 检测冲突：新事实与既有条目矛盾（FTS5 命中同 key/同实体）；
2. **复用度检查**：被命中条目的历史检索频次高 → 走"增量修正"（更新字段+留 changelog）而非删改；
   频次低 → 直接覆盖代价小；
3. 多表达：同实体的别名条目（NEKO facts 的 SHA-256 去重近邻）联动更新。

### 记忆污染防御对照

| 现有策略 | 论文思想补强 |
|---|---|
| "若 full 先清后加"（全量） | 高复用条目**跳过清理**，走增量修正——防"一次误更新毁掉高频正确记忆" |
| SHA-256 内容去重（NEKO facts） | 去重之外加**复用度**维度：同样内容，被引用多的条目有"编辑保护" |

### ⭐ 最小落地判定（不实施，给结论）

**值得做的最小改动**：`memory` 工具写入路径加**复用度检查**——
- memory_maas 的 index_cards 已有 lineage 链（工单214 盘点）；检索命中时**计数 +1**（复用度信号源，FTS5/SQLite 一列即可）；
- 写入冲突时：`reuse_count > 阈值` → 改"update + 保留旧版快照（lineage 追加）"；否则现行为不变。
- **工作量**：一个计数字段 + 写入分支，≈30 行；价值：把"全量重写"升级为"外科手术式"，对齐论文核心思想
  而不引入任何训练层机制。

**不建议做的**：多表达联合优化（推理层无解 A 矩阵——我们不做表示对齐，只做条目联动，即上面第 3 点的简化版）。

## 边界

- 论文数字（3×/近满分）是**模型编辑基准**，与推理层条目管理**无直接可比性**——引用其思想而非数字；
- 最小改动的阈值（复用度多少算高）需实测标定，本报告不给拍脑袋数。
