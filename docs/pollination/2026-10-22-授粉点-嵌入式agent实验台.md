## 1. 借鉴点（每条：机制 → 本侧可搬的具体部件 → 档位）

### 1.1 事实知识库：先有"怎么量出来"，再谈调参（`2610.27797`）

- **机制**：设计流若从不在目标硬件上跑，就既看不到存储/数值限制、也看不到目标独有的成本结构
  ⇒ 作者把"目标事实"作为工作流的第一等输入，而不是事后补的参数表。
- **本侧部件**：一张**事实表 schema**（下面 §2.1），四个字段必须齐：`字段名 / 单位 / 怎么量出来 / 复现脚本路径`。
  缺"怎么量出来"的行视为无效行。
- **档位**：**立即**（这是后面所有评测的地基，一张表 1 天内能写出来）。

### 1.2 每步评测器：三档闸门，各档明确"拒绝什么、放过什么"（`2610.27797` + `2610.27174`）

- **机制**：27797 的经验是"能编译"和"能跑对"之间隔着目标硬件的数值/内存现实；
  27174 的教训是**没有固定 setup 的比较没有意义**。
- **本侧部件**：三档 evaluator
  1. **语法/编译档**：能否 `idf.py build` 通过、静态检查无错（拒绝语法与类型错，放过逻辑错）。
  2. **仿真档**：`mcpserver/esp32/cluster_sim/` 里跑通逻辑（拒绝死循环/越界/协议字段错，放过时序抖动）。
  3. **板上实测档**：真机误码率 / RSSI / 功耗（拒绝"仿真过但板上不过"的实现，放过性能未达标）。
  每档都要写"**不许 agent 绕过**在实现上靠什么保证"——本侧答案是：**闸门脚本由 CI/CLI 调用，不是由 agent 自述**。
- **档位**：**本周**（三档里前两档能立刻做，第三档依赖硬件在位）。

### 1.3 提交前重验：把"过期观测"堵在提交口（`2610.28019`）

- **机制**：异步推理下，chunk 生成时看的观测到提交时已经旧了；作者把校验挪到**提交前一刻**，用最新观测验。
- **本侧部件**：**改参前重验**——凡改频率/带宽/扩频因子/滤波器系数，提交前强制抓一帧频谱（预算 **≤200 ms**）并比对
  事实表里的期望区间；不一致则**回退到上一个参数组**并记账（不是重试）。
- **为什么不是"提交后监控"**：本侧改一次参要写进设备 flash，写错了恢复成本高；提交前拦一次比事后回滚便宜 10 倍以上。
- **档位**：**立即**（复用现有频谱快照能力即可）。

### 1.4 基准任务：SNR / 包长 / 天线高度三项不固定就没法跨月比较（`2610.27174`）

- **机制**：Sionna Bench 的核心论点是"科学债来自 setup 未统一"，而不是"方法不够好"。
- **本侧部件**：固定一组基准任务 `BENCH-3`：① SNR 档（-10/-5/0/+5 dB 四档）② 包长（16/64/255 B）
  ③ 天线高度（桌面 0.2 m / 杆上 1.5 m）。任一维度变了，结果只能与**同 setup** 的历史比。
- **档位**：**立即**（只是约定 + 记录格式，零代码）。

### 1.5 盲自适应：不要信道估计也要能动（`2610.27593`，**有偏差，见 §5**）

- **机制**：只用"上一次译码成功/失败"这一个比特做 AID 游走，`O(1)/slot`，不做信道估计。
- **本侧部件**：把它当作**控制律模板**（不是把它当 LoRa 方案）：SF/CR 的自适应也只需要"上一包 ACK/NACK + 当前 AoI"两个输入，
  控制器参数（增/减步长、驻留时间）可标定。
- **⚠️ 偏差**：原文是 **Polar 码前缀长度选择**，不是 LoRa 扩频因子；搬的是**控制器结构**，不是结论。
- **档位**：**本周**（控制器易写，参数标定要实测）。

### 1.6 天线分集：第二块天线换 dB 级余量（`2610.30015`）

- **机制**：固定朝向 + 邻近金属是主因；多极化天线显著改善。
- **本侧部件**：给 SX1278 节点加**第二路正交极化天线** + 简单选择/合并；验收用"中位 RSSI 差 ≥10 dB"。
- **档位**：**季度**（要改硬件与结构件）。

### 1.7 RSSI 指纹要分"已测/未测"两档记账（`2610.22680`）

- **机制**：回溯评估强调"哪些格子真的勘测过、哪些是插值"，并把中继端滤波（Kalman）写进口径。
- **本侧部件**：指纹库每条记录带 `measured: true/false` 与 `survey_id`；未测格子的估计值**不得**与已测混在同一误差统计里。
- **档位**：**本周**（数据结构改动）。

## 4. 验收（≥2 个可判定实验）

### 实验 1 · 事实表可复算（对应 1.1）

- 做法：按 §2.1 四行实测一遍，把脚本与原始输出入库。
- 判据：**换一台同型号板子重跑，四行数值偏差 ≤15%**；超出则说明"怎么量出来"写得不够实，退回重写。

### 实验 2 · 提交前重验能拦住坏参数（对应 1.3）

- 做法：故意提交一档越界参数（如把 SF 设为厂商不支持值、或把带宽设到滤波器边缘）。
- 判据：**重验在 ≤200 ms 内拦下并回退**，且账本留下一条 `rejected: 原因 + 期望区间 + 实测值`。
  反向对照：提交一组合法参数必须**放行**（防止"一律拒绝"）。

### 实验 3 · BENCH-3 跨 setup 不可比（对应 1.4）

- 做法：同一实现，改变天线高度（0.2 m → 1.5 m）各跑 20 包。
- 判据：两组结果**必须被标记为不可直接比较**（脚本层面拒绝把不同 setup 的均值放进同一张对比表）。
