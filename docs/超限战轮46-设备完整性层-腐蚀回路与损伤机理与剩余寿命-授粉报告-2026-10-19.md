# 超限战轮 46 — 设备完整性层：腐蚀回路 / 损伤机理 / 剩余寿命

**角度**：前几轮把链条铺到了「纸」上——41 物质会怎样、43 装置怎么建、44 装置怎么跑、45 图纸和风险怎么被读懂。但 45 建出来的那张图有个隐含假设：**图上的设备是永生的**。没有壁厚、没有损伤、没有时间。这一轮补的正是这层缺席的**时间维度**：管线在图上慢慢变薄，换热器慢慢结垢，蒸煮锅在碱液里慢慢裂。

一句话：**45 管「图怎么读」，46 管「图上的设备怎么烂」。**

这一层不是新学科，是**设备完整性（asset integrity）**：腐蚀回路 → 损伤机理 → 检测概率 → 退化速率 → 剩余寿命 → 检验计划。它跟用户本行贴得很紧——碱法蒸煮的 caustic corrosion / caustic SCC、黑液蒸发器的结垢与碱脆、保温层下腐蚀（CUI），都是纸浆造纸设备失效的经典模式。

## 二、最值钱的四处（源码级证据）

### 2.1 损伤机理本体的 6 条 object property，正好是 P&ID 图的边

`Damage_Mechanism_Identification_Ontology.owl` 实测：**41 个 owl:Class、131 个 NamedIndividual、6 个 ObjectProperty、27 个 DatatypeProperty**。六条对象属性是：

```
belongsToUnit · getsHeatFrom · hasDegradation
hasFluidPhase · hasMaterialOfConstruction · hasStream
```

把 45 轮的图摊开看：设备节点（`BoilerTube` / `Column` / `Drum` 这些类都在本体里）× 工艺边（`hasStream`）× 材质（`CarbonSteel` / `AusteniticStainlessSteel`）× 相态（`hasFluidPhase`）——**这四样正好是 45 的 `pyDEXPI` 图能提供的全部上下文**。而 `hasDegradation` 这一条，就是图上现在缺的那条边：`设备 --hasDegradation--> 损伤机理`。

类目不是泛泛的"腐蚀"，是 API 571 的机理 × 材料组合：`Caustic Corrosion (Low Alloy Steel)`、`Caustic SCC (Low Alloy Steel)`、`Corrosion Under Insulation (Low Alloy Steel)`、`CO2 Corrosion (Low Alloy Steel - Gas)`、`Chloride SCC - Internal (Gas)`、`Creep`、`Metal Dusting`、`Sigma Phase Embrittlement`……

**这一处为什么值钱**：碱法蒸煮的蒸煮锅、黑液蒸发器，失效模式就是 caustic corrosion + caustic SCC + 结垢下的 CUI。这张本体把「设备—材质—介质—温度」到「可能怎么坏」的映射做成了可查询结构，而 scratchpad 的 `graph_memory_adapter/engine.py:191 ingest_entities(nodes, edges)` 接受任意 `type` 字符串——**只差一个节点类型约定，不需要改引擎**。

**许可红线**：该仓无 LICENSE，OWL 文件不能复制进主仓。可用的只是「术语结构」——类名/属性名来自 API 571 标准术语，属于事实性清单，不是版权表达。落地方式：按这份结构**自己写**一份 `damage_mechanisms.json`（41 类 × 材料），不搬运 .owl 文件。

### 2.2 `progpy` 的两层，刚好把 `device_metrics` 变成 RUL 分布

`src/progpy/state_estimators/__init__.py` 导出 `KalmanFilter` / `UnscentedKalmanFilter` / `ParticleFilter`；`src/progpy/predictors/__init__.py` 导出 `MonteCarlo` / `UnscentedTransform` / `ToEPredictionProfile`；另有独立的 `uncertainty_data` 与 `metrics` 包。

这正是「退化模型 + 观测更新 → 剩余寿命分布」的标准骨架：状态估计器吃 `device_metrics` 的时序，预测器把状态推到失效阈值，`ToEPredictionProfile` 给的是**到失效的时间分布**而不是一个数。对照本侧：`docs/设备台账-schema-草案-2026-09-11.md` 的 `device_metrics` 表只有 `cpu_percent / mem_percent / status / restart_count / decision`——**全是电子设备的健康，没有工艺设备的退化量**。缺的不是框架，是「壁厚/振动/温度/压力」这几列。

**许可纠正**：API 报 `NOASSERTION`，`pyproject.toml` 写的是 `license = "NASA-1.3"`，附 `prog_models license.pdf`。NASA-1.3 不在 GPL 兼容清单里 → **只授粉设计（接口分层、失效阈值语义、uncertainty 表达），不并码**。想并码就用 `UniPHM`（GPL-3.0）或自己按同样接口写。

### 2.3 腐蚀回路聚类：把「Excel 行」换成「图节点」，其余照搬

`process/corrosion_loop/corrosion_looping.py` 的实现很短：

```python
categoricalGroups = df.groupby(by=categoricalFeatures, axis=0)
for k in range(1, len(members)+1):
    model = KMeans(n_clusters=k, random_state=42).fit(membersNumerical)
    diff = max - min per feature
    if diffList < maxDiffList:   # 组内各数值特征极差小于阈值就停
        return members, mean(inertia)
name = feature1 + "-" + feature2 + "-" + str(LABEL)   # 自动命名回路
```

输入是 `./temp/excel/input.xlsx` 的行，列就是 `categoricalFeatures`（材质/介质/单元）+ `numericalFeatures`（温度/压力/流速）。而 45 的 `pyDEXPI` 图节点带的正是这些属性。

**改造量**：`df = pd.DataFrame([n["attrs"] for n in G.nodes])` 一行替换数据源，其余分组/KMeans/命名逻辑原样保留；产出的 `LABEL` 直接写成 `corrosion_loop` 子图，挂到 `graph_memory` 的关系表里。这是本轮**投入产出比最高**的一处——1★ 的原型，但算法骨架是现成的，缺的只是数据源适配。

### 2.4 `otpod`：把「检测得到吗」从口号变成概率

`otpod/` 目录下是 `_adaptive_hitmiss_pod.py` / `_adaptive_signal_pod.py` / `_kriging_pod.py` / `_pli_pod.py` / `_polynomial_chaos_pod.py` / `_quantile_regression_pod.py` / `_sobol_indices.py`。

POD（probability of detection）是完整性管理里被长期忽略的一环：**RBI 算出的风险，前提是「缺陷被发现了」；没发现的那部分，才是爆炸的来源**。otpod 给的是「给定缺陷尺寸，检出概率多少」的曲线，外加 Sobol 指数告诉你哪个检测参数（探头频率/扫查速度/耦合）最影响检出率。这比再写一个 YOLO 检测器值钱——它补的是**检测本身的置信度**。
