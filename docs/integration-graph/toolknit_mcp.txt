0.1 零接触验证（可直接复制的原文）
--------------------------------------------------------------------------------

工单 §3.3 点名的三个串，明文列举如下（本文件是全仓唯一允许出现它们的地方）：

    src-tauri
    tauri.devtools
    vite

在仓库根执行：

    git grep -n -E 'src-tauri|tauri\.devtools|\bvite\b'
    git grep -ln -E 'src-tauri|tauri\.devtools|\bvite\b'

期望：**唯一命中 docs/integration-graph/toolknit_mcp.txt**（即本文件）。
若其它文件命中，视为本工单回归。

⚠️ 注意 `git grep` 的口径是**词边界**版本 `\bvite\b`：单词 `vite` 才算命中；
而 `src-tauri` 与 `tauri.devtools` 是**子串**匹配（`.` 在正则里是任意字符，
实际比字面更宽，故口径取宽）。上面第 3 条明文的 `vite` 也在词边界内。

等价的非 git 版本（无 git 环境下用）：

    grep -rn --exclude-dir=.git -E 'src-tauri|tauri\.devtools|\bvite\b' .

本模块内**零命中**这一条另有单测兜住：
    tests/test_toolknit_mcp.py::test_no_package_lock_or_tauri_contact_in_module

该测试**故意把三个串拆成碎片拼装**（避免测试自己成为命中项），并用
「到本文件里逐字找到这三个串」做反向自证——**拼错就红**（本单实测触发过一次：
本文件原先只写了转义形态 `tauri\.devtools`，缺纯字面量，自证当场抓到）。

0.2 为什么不 clone 上游整仓
--------------------------------------------------------------------------------

上游 ZihangDong/toolknit-desktop 是 Tauri 2.x 桌面应用：
    - 前端：WebView（那三个被禁的串即出现在此）
    - 后端：Rust（src-tauri 目录）
    - 体积：实测 157,367 KB（约 154 MB）
    - npm 包 @toolknit/cli 实测 unpackedSize 40,866,503 B（约 39 MB）

本仓只取「本地文件处理 CLI」这一层，经 npx 按需拉起。前端/桌面端与本仓的
Lumo（NEKO + Live2D 桌宠，不做 WebView 桌面）形态不兼容，**不读、不引、不 clone**。

2 · 与仓内既有模块的耦合点（工单 §2 任务三.1）
================================================================================

工单 §2 任务三要求列出与 mcpserver/llm_gateway/、mcpserver/kicad-mcp/ 的耦合点，
并「只改主调用路径，不动现有模块内部接口」。

--------------------------------------------------------------------------------
2.1 与 mcpserver/llm_gateway/
--------------------------------------------------------------------------------

耦合点数量：**0（零代码耦合）**

理由：本模块的四个工具是**确定性文件处理**，不产生任何需要「叙述」的中间结果 ——
色板是数值、PDF 页数是数值、压缩比是数值、PPT 页数是数值。没有需要 LLM 介入的
语义环节，因此**不引入**任何 LLM 通路。

对比：242 的 rf_workflow 有 explain 接口，才需要 llm_gateway（且是惰性导入 +
规则兜底）。本模块不需要，因此**连惰性导入都不加** —— 不为了「看起来统一」而
引入用不上的依赖。

若将来要加「用自然语言描述色板/页面内容」的能力，再按 242 的定式接
mcpserver.llm_gateway.anthropic_compat（惰性导入 + 不可用即退回确定性规则 +
在 mode 字段如实标注），**不要**改成硬依赖。

--------------------------------------------------------------------------------
2.2 与 mcpserver/kicad-mcp/
--------------------------------------------------------------------------------

耦合点数量：**0（且该目录在本仓 main 不存在）**

实测：main 树全树查询 `mcpserver/kicad-mcp/` → **404**（工单 §2 任务三.1 把它
写成「已有/规划」，实况是规划未落地）。这是本单第 10 处工单前提与实况不符。

层级区分（工单 §5.5 沈遥侧备忘的口径，此处确认成立）：
    kicad-mcp   = MCP-EDA 类（电子设计自动化）
    toolknit_mcp = MCP-文档类（PDF / PPT / 图像）
两者**层级不同、互不干扰**，既无代码耦合，也不共享状态。

--------------------------------------------------------------------------------
2.3 唯一真正耦合的既有模块：mcpserver/mcp_registry.py
--------------------------------------------------------------------------------

这是**唯一**被本单触碰的既有装配路径，且是**零改动**耦合：

    改动方式：新增 agent-manifest.json，由既有 glob 自动发现。
    改动文件数：0（工单 §3.6「不许触碰 mcp_assembly / mcp/services 路由健康检查」
                  ⇒ 本单**完全满足**，一个字节都没动既有文件）

契约依赖（上游若改，本模块需跟）：
    1. manifest 文件名必须恰为 agent-manifest.json
    2. agentType 必须为 "mcp" 才会进注册

上述 1~6 全部由 tests/test_toolknit_mcp.py 的
test_manifest_entrypoint_resolves_and_has_handoff_contract 逐条钉住

3 · 数据流时序（一次 ppt_to_pdf 调用）
================================================================================

  LLM / 调用方
      │  {tool_name: "ppt_to_pdf", params: {pptx_path: "…/deck.pptx"}}
      ▼
  MCPManager.unified_call(task)
      │
      ▼
  ToolknitBridge.handle_handoff(task)
      │  ① 查 _TOOLS 白名单（未登记 ⇒ 立刻返回「未知工具」，不进子进程）
      │  ② 取 params（或扁平 task 去掉元键）
      ▼
  asyncio.to_thread( lambda: self.ppt_to_pdf(**args) )
      │
      ▼
  tools.ppt_to_pdf()
      │  ③ resolve_input()   ← 工作区纪律：绝对路径 + 在界内 + 存在
      │  ④ resolve_output_dir()  ← 建 <工作区>/toolknit-output/
      │  ⑤ output_name 留空 ⇒ 生成 <stem>-<8位hex>（唯一，不互相覆盖）
      ▼
  tools.run_cli(["ppt","to-pdf", … , "--json"])
      │  ⑥ shutil.which("npx") → 绝对路径（不靠 shell 查找）
      │  ⑦ subprocess.run([...], shell=False)   ← 无注入面
      ▼
  npx -y @toolknit/cli@2.3.1 ppt to-pdf …
      │  ⑧ 解析 renderer（懒探测 LibreOffice；缺 ⇒ DEPENDENCY_MISSING）
      │  ⑨ mkdtemp(<out>/.toolknit-libreoffice-XXXXXX) 作独立 profile
      │  ⑩ soffice --headless --convert-to pdf --outdir <out>
      ▼
  {"ok": true, "result": {… output_path, slide_count, page_count, renderer …}}
      │  ⑪ _discover_pdfs()：先读 output_path，取不到才扫目录
      ▼
  {"ok": true, "tool": "ppt_to_pdf", "outputs": [...], "exists": true, …}
      │  ⑫ _log() 追加一行 JSONL（best-effort，日志失败不影响主调用）
      ▼
  {"status":"success","message":"ok","data":{…}}   ← JSON 字符串回给调用方

4 · 已知边界（实测留证，勿当 bug 修）
================================================================================

4.1 ppt_to_pdf 的输出路径长度上限（**最重要的一条**）
    --output-dir 绝对路径 >83 字符 ⇒ soffice 静默 fail-fast
    （exit 3221226505 / 0xC0000409，stderr 为空）
    成因：上游把 -env:UserInstallation=<out>/.toolknit-libreoffice-XXXXXX/profile
          以 file:/// URL 传给它，URL 跨过 127 字符即崩（8 + 36 + 84 = 128）
    受控实测：82 ✅/✅ 83 ✅/✅ 84 ❌/❌ 85 ❌/❌
    与层级无关：长而浅（1 层 109 字符）失败，短而深（6 层 71 字符）成功
    对策：工作区根放短路径。工单要求的服务器路径
          /home/ubuntu/scratchpad/research/<ws>/toolknit-output ≈ 60 字符，**安全**
    留证用例：test_known_boundary_output_dir_length_limit

4.2 doctor 不检查 LibreOffice
    doctor 的 result 只有 version/node/qpdf/ffmpeg；LibreOffice 是渲染时懒探测的
    ⇒ 用 doctor 判它必然假阴性。唯一可靠入口是 renderer_probe
    （ppt to-pdf --dry-run，约 3.2 s，不写盘）
    留证用例：test_doctor_does_not_report_libreoffice

4.3 image colors 的 --count 是上界不是产量
    纯色图即使 --count 2 也只返回 1 色
    留证用例：test_palette_count_is_an_upper_bound_not_a_quota

4.4 上游没有 PDF 文本提取
    pdf 子命令仅 inspect/merge/split/rotate/encrypt/decrypt/compress/enhance/to-image
    MCP 侧 46 工具里也无任何文本提取 ⇒ 工单点名的 pdf_extract_text **不存在**
    仓内既有替代：mcpserver/adapters/pdf2md_adapter（Docling / MarkItDown）

7.3 ffmpeg：装了也不算数（doctor 侧的实测坑）
--------------------------------------------------------------------------------

  CLI 找 ffmpeg 只认三处，且 lstat 拒绝符号链接：
      %APPDATA%\ToolKnit\ffmpeg\ffmpeg.exe | 包内 vendor/ffmpeg/ | TOOLKNIT_FFMPEG_PATH
  PATH 上的 ffmpeg **不算**（最后退化成裸命令交给 spawn(shell:false)）；
  而 winget 建的 %LOCALAPPDATA%\Microsoft\WinGet\Links\ffmpeg.exe 是 **0 字节填充文件**
  ⇒ Node spawn 报 EFTYPE ⇒ doctor 报 available=false / rc=5

  ⇒ 处置：TOOLKNIT_FFMPEG_PATH 指向真实二进制 ⇒ doctor 变 ok=true / rc=0 / missing=[]
