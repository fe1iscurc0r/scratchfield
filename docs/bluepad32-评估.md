# bluepad32 评估（W71-04）

> 上游：ricardoquesada/bluepad32（GitLab，43★，C）｜ <https://gitlab.com/ricardoquesada/bluepad32>
> 许可：Apache-2.0（Ricardo Quesada 系列，可借鉴；NOASSERTION 需最终核对标「许可待核」）

## 1. 项目定位

ESP32 / Raspberry Pi Pico W 的**蓝牙 HID 主机栈**——支持蓝牙游戏手柄、鼠标、键盘作为输入设备接入，
把 ESP32 变成「无线输入接收端」。

## 2. 架构拆解

- **蓝牙 HID 主机（host）角色**：ESP32 作为 host 连接手柄/键鼠（而非作为外设），解析 HID 报告。
- **输入事件映射**：HID 报告 → 统一输入事件，供上层应用（游戏/桌宠/控制）消费。
- **多平台**：ESP-IDF / Pico SDK，轻量 C 实现。

## 3. 与本仓对照

| 维度 | bluepad32 | 本仓 |
|---|---|---|
| 交互输入 | 蓝牙手柄/键鼠 | NEKO 交互层（桌宠/游戏）|
| 连接方式 | 无线（蓝牙） | 键盘/串口（有线为主）|

**应用场景结论（验收项）**：给 NEKO 桌宠/游戏加**无线手柄输入**是明确增量场景（桌面交互更自然）；
有线输入仍保留作调试/低延迟兜底，无线作为增强。

## 4. 可落地借鉴点（≥3）

1. **蓝牙 HID 主机栈**：ESP32 作为 host 连接蓝牙手柄的链路（协议栈 + HID 报告解析），可直接借鉴为
   NEKO 交互层的无线输入通道。
2. **「输入事件统一抽象」**：把手柄/键鼠/触摸统一映射为输入事件，避免上层耦合具体设备。
3. **低延迟 HID 处理**：C 实现的事件处理路径，对桌宠实时交互（低延迟）有参考价值。

## 5. 许可裁定

Apache-2.0（待最终核对）——**可借鉴代码**；HID 协议栈部分参考设计 + 协议解析，避免整体 fork。

## 6. 结论

可借鉴（功能增量）。建议：立项「NEKO 蓝牙输入通道」，用 ESP32 + bluepad32 思路给桌宠加无线手柄/键鼠输入。
