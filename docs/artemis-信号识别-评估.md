## 1. 项目定位

「the reference for radio signal identification」：辅助 RF 信号**识别与归档**的软件——
实时频谱分析 + 信号特征比对 + 识别结果入库。社区由 sigidwiki 管理员与多位呼号持有者
（IZ1MLL/KI7POL/HB9GZL…）背书，识别知识库（Artemis-DB）与代码仓分离、独立版本化。
对本仓频谱诊疗主线的意义：它是「识别人」角色的完整参照——我们目前有频谱**显示**
（Y-04 面板）与调制**分类特征**（rf_brain Phase 4），缺的是「信号→已知型号/制式」的
识别闭环与知识库组织。

## 2. 架构拆解（顶层实测）

```
artemis/   # 主程序（Python，实时频谱采集 + 识别引擎）
ui/        # GUI（Qt 系）
data/      # 本地识别库缓存/用户归档
config/    # 配置（设备/频段/识别阈值）
scripts/   # 工具脚本
（Artemis-DB 独立仓：信号特征库，版本化发布）
```

要点：
- **识别库与代码分离**：DB 独立仓 + 版本号徽章 → 知识库可独立更新/分发，
  本仓若建「信号识别库」应沿用此组织（数据不进代码仓历史）。
- **专家社区驱动**：β 测试者名单即领域专家名单——识别库质量靠人肉背书，
  本仓可借鉴「识别结果附来源/置信度/审核状态」的元数据设计。
- **实时频谱 + 识别联动**：采集→特征→比对→归档一条链，GUI 只做呈现。

## 4. 可落地借鉴点（≥3，GPL 只参考设计不抄代码）

1. **识别库独立仓 + 版本化**：建 `signals-db`（或 ELN 子卷）存信号特征样本与元数据
   （制式/带宽/来源/置信度/审核状态），代码仓只读引用。
2. **识别闭环接线**：rf_brain 特征向量 → 识别库最近邻/规则比对 → 结果入 ELN，
   形成「频谱→识别→归档」链；先做规则级（带宽+调制+占空比匹配），再上嵌入向量。
3. **元数据审核状态机**：识别结果带「自动/待审/已确认」三态，专家（用户）确认后
   才进库——避免自动识别污染知识库。
4. **设备/频段配置外置**：config/ 独立目录 + 阈值可调，本仓频谱监测配置照此外置。
