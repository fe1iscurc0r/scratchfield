# Lumo 运行时接线与组件获取 SPEC（2026-10-16）

> 出单：沈遥 · 对象：`fe1iscurc0r/scratchfield`（发布仓）· 关联工单：`TRAE_WORKORDER_PROMPT_AGENT_250.md`
> 触发问题：安装器假设用户是裸机（无 Node / Python / Vue），发行包要不要「提示下载 / 一并安装 / 提示安装」这些环节。

---

## 〇 · 结论先行

**运行时早就一并安装了，缺的是接线。**

`build.py` 已经把便携 Node 22.13.1、Python standalone（含裁剪）、uv、openclaw 下载并解压进
`frontend/backend-dist/runtime/`，再由 `frontend/electron-builder.yml` 的 `extraResources`
打进 `<安装目录>/resources/runtime/`。用户裸机不需要装任何环境。

**断点在两处**：

1. 打包模式下 Electron 启动后端时**没有把 runtime 路径告诉后端**（`backend.ts` 只注入了 `PYTHONUNBUFFERED`）；
2. 后端探测函数 `_find_node()` / `_find_python()` 的候选表里**只写死了两条本机开发路径 + PATH**，
   没有包内 runtime —— 裸机必然返回 `None`，且 `_start_neko_shell()` **静默 return False**。

> **根因归因**：上述两处均属**本仓自写实现**范围（`frontend/electron/modules/backend.ts` 与
> `mcpserver/agent_open_launcher/local_apps.py` 都由本仓维护），**非上游 N.E.K.O / NagaAgent 代码**。
> 即本地实现期的遗留缺陷，由本单自行收口，不涉及第三方代码或上游改动，也不存在责任外推。

→ 用户点 NEKO 按钮：桌宠永不出现，日志里一个字都没有。用户以为软件坏了。

**决策**：能内置的全内置（Node / Python / Vue 都不该让用户碰）；只有「大到不该进主包」和「许可不允许进包」
的东西才配拥有下载环节（NEKO 主体组件 / Ollama+模型 / HamLog 提示安装）。

## 二 · 决策表（回答"提示下载 / 一并安装 / 提示安装"）

| 依赖 | 用户裸机是否要装 | 档位 | 理由 |
|---|---|---|---|
| Vue / Vite | 否 | **不涉及** | 纯构建期，编译进 `dist/` 静态资源 |
| Node.js | 否 | **已一并安装**（接线即可） | Electron 44.5.1 自带 Node；包内另有便携 Node 22.13.1 |
| Python（主后端） | 否 | **已一并安装** | PyInstaller 冻结 + 包内 standalone |

## 三 · 改动点（本次范围 = 接线 + 可诊断 + 清理）

### A. `frontend/electron/modules/backend.ts` —— 注入运行时路径

在 `startBackend()` 构造 `env` 处（打包与开发模式共用），新增：

```ts
function resolveRuntimeBin(name: 'node' | 'python'): string | null {
  const base = join(process.resourcesPath, 'runtime', name)
  const candidates = process.platform === 'win32'
    ? [join(base, `${name}.exe`), join(base, 'bin', `${name}.exe`)]
    : [join(base, 'bin', name)]
  return candidates.find(existsSync) ?? null
}

// env 构造后（仅 app.isPackaged 时注入，开发模式仍由 ps1/venv 决定）
if (app.isPackaged) {
  const rtNode = resolveRuntimeBin('node')
  if (rtNode) { env.LUMO_FUSION_NODE = rtNode; appendBackendLog(`[Runtime] node → ${rtNode}`) }
  const rtPython = resolveRuntimeBin('python')
  if (rtPython) { env.LUMO_FUSION_PYTHON = rtPython; appendBackendLog(`[Runtime] python → ${rtPython}`) }
}
```

要求：命中与否都要进 `appendBackendLog`（现有后端日志面板可见），便于远程排障。

### B. `mcpserver/agent_open_launcher/local_apps.py` —— 包内路径探测 + 删开发机路径

新增模块级辅助（不依赖前端注入，作为兜底）：

```python
def _bundled_runtime_bin(name: str) -> str | None:
    """包内运行时：<resources>/runtime/<name>/…（打包态）。
    开发态 sys.executable 在 .venv 下，父两级的 runtime 不存在 → 返回 None，不影响开发。"""
    root = Path(sys.executable).resolve().parent.parent / "runtime" / name
    candidates = (
        [root / f"{name}.exe", root / "bin" / f"{name}.exe"]
        if sys.platform == "win32"
        else [root / "bin" / name]
    )
    return next((str(c) for c in candidates if c.exists()), None)
```

- `_find_node()` 顺序改为：`LUMO_FUSION_NODE` → **`_bundled_runtime_bin("node")`** → 系统 PATH
- `_find_python()` 顺序改为：`LUMO_FUSION_PYTHON` → **`_bundled_runtime_bin("python")`** → `sys.executable` → 系统 PATH
- **删除**两条本机开发路径硬编码（见 §0 根因归因）：`.trae-cn/binaries/node/versions/24.18.0/node.exe`、`python-sdk/python3.13.2/python.exe`
  （它们在生产环境永不成立，只会误导后续排查者以为"有 fallback"）

### C. `local_apps.py` —— 失败不再静默

`_start_neko_shell()` 返回 `(ok, reason)` 或抛具名异常，`launch_neko()` 把 reason 带进返回 `message`：

| 情况 | 面向用户的文案（示例） |
|---|---|
| node 缺失 | `NEKO 桌宠组件启动失败：未找到 Node 运行时（已查找：包内 runtime / 系统 PATH）` |
| shell 目录缺失 | `NEKO 桌宠组件未安装：未找到 neko-electron-shell（请到组件中心获取）` |
| shell 的 node_modules 缺失 | `NEKO 桌宠组件未完成初始化：neko-electron-shell 缺少 node_modules（需 npm install）` |

**禁止 `return False` 无痕迹**——这是本次问题的直接成因。

### D. 回归要求

- 开发模式（`npm run dev` / `lumo_fusion.ps1`）行为**完全不变**：仍是 venv Python + ps1 注入的 env 优先
- macOS / Linux 同样要注入（`bin/node`、`bin/python` 分支）
- 不改 `build.py` 与 `electron-builder.yml`（运行时已在包内，无需新增下载逻辑）

## 四 · 验收硬线

1. **裸机路径命中**：Windows 无 Node/Python 环境安装 → 启动 → 后端日志出现 `[Runtime] node → …\resources\runtime\node\node.exe`；Python 端 `_find_node()` 实测返回包内路径而非 `None`
2. **本机路径硬编码清零**：`grep -rn 'trae-cn\|python-sdk' mcpserver/` → **0 命中**
3. **失败可诊断**：移除 `neko-electron-shell` 后点 NEKO → 返回含「未安装 / 未找到」的明确文案，且后端日志有对应行（不再静默）
4. **开发模式不回归**：`npm run dev` 正常起后端，env 不覆盖 ps1 注入值
5. **三平台构建不回归**：CI（test → 三平台 build）全绿，v5.2.x tag 流程不受影响
