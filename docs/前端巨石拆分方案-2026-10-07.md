### 1.1 补充勘察（2026-10-07 晚）——**方向修正：应抽 composable，不是组件**

实测 App.vue 的 `<template>` 只有 **145 行**，而且**已经是组件编排**：

| 组件 | template 出现次数 | 说明 |
|---|---|---|
| `FloatingView` | 1 | 已独立（浮动模式） |
| `WindowResizeHandles` | 1 | 已独立（窗口缩放手柄） |
| `SplashScreen` | 1 | 已独立（启动闪屏） |
| `LoginDialog` | 1 | 已独立（登录弹窗） |
| `RouterView` | 1 | 路由容器 |

→ **抽组件解决不了 App.vue 的问题**。反例：splash 块（L700-712）本身就只是对 `SplashScreen`
的薄包装（7 个 props + 2 个事件），再往外包一层只会把这 9 个符号变成 props/emits —— **更糟**。
（`WindowResizeHandles` 同理：工单说的 resize handles 其实早已是组件。）

**真正的巨石是 `<script setup>` 的 615 行逻辑**，六类职责：
Live2D 渲染与源缓存 / 启动闪屏 / 窗口壳与 resize / 路由态 / 背景主题 / 浮动模式。

**正解：抽 composables**

| 候选 composable | 覆盖职责 | script 内大致范围 |
|---|---|---|
| `useLive2dSource()` | 源缓存读写 + resolved/effective 计算 + 角色映射表 | L47-173 为主 |
| `useSplash()` | 闪屏可见性 / 进度 / 阶段 / 超时提示 | L52、L199 起 |
| `useWindowChrome()` | isElectron / isMaximized / resize 可见性 / 标题栏内边距 | L54-134 |
| `useAppBackground()` | 背景主题（现已走 `useBackground`，可能已够用） | L144-146 |

**前置条件（硬性）**：`resolvedLive2dSource` 这类计算同时依赖**路由态**与**启动缓存** ——
必须**先画状态依赖图**（可产出 `docs/app-vue-state-graph-*.md`）再动手；
否则抽出来的 composable 会带隐式耦合，比现在的巨石更难维护。

**排期建议**：单独一轮 —— 先出依赖图，再逐个抽 composable（每个抽完即跑 `npm run build`）。
判断依据同样来自今天的经验：**跨块重构的真正安全网是「残留自检 + 构建」**，
而 composable 抽取的耦合面比组件搬运更大，必须先有图。

## 3. 通用方法论（SkillView 三步验证过）

1. **定位锚点**：对**整文件** `grep -n`（⚠️ 先 `awk` 再 `grep -n` 得到的是"匹配序号"不是文件行号）；
2. **脚本化迁移**：按行区间**读取**原文再组装（避免手工复制几百行）——写脚本用 **Write 工具**（bash heredoc 会吞反斜杠）；
3. **删除必须从后往前**（先删小行号会让后续索引位移、删错内容）；
4. **残留自检**：删完 grep 关键符号，逐个确认为 False；
5. **构建即安全网**：`npm run build`（vue-tsc 能抓"删多了/删漏了"的类型错误；
   但**抓不到 CSS 截断**——CSS 边界必须精确到规则的 `}`，否则 `CssSyntaxError: Unclosed block`）；
6. **共享样式父子各留一份**（scoped 不跨组件生效，构建不报错但运行时会掉样式）。
