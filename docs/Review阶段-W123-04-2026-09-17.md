# Review 阶段：执行后变更审查（卷123 W123-04 · 2026-09-17）

改完不直接交付。任务所有步骤完成后自动进 `review`，系统生成审查报告给用户看，
用户裁决三选一——**确认**（done 存档）/ **打回**（回 running 按意见继续修）/ **跳过**（done 但标记未经 review）。

## 触发

- 自动：所有步骤 `done`/`skipped` 时任务转 `review`（W123-02 的 `record_step_result` 判定）
- 手动：`task:review [id]`（会把任务置为 `review` 再出报告）

## 报告内容（`apiserver/task_review.py`）

| 段落 | 内容 |
| --- | --- |
| 概要 | 目标 / 状态与进度 / 会话 / git 基线 |
| 改动摘要 | `git diff --stat`：来源、文件数、+/- 行数、文件清单、原始 stat |
| 验证结果 | 每步的验证门结论（pytest/py_compile、通过与否、重试次数） |
| 涉及文件 | 任务 `file_refs` |
| 待确认问题 | 规则自评：未完成步骤 / 验证未全绿 / 无验证记录 / 非 git 工作区 / 重试过的步骤 / 无 git 基线 |

**改动来源判定**（踩过的坑）：不能无条件拿仓库 `git diff` 当任务的改动——那只说明
「当前仓库脏」，与这个任务做了什么无关。规则是：先看任务工作区（`workspace/<session>`），
只有任务 `file_refs` 确实指向仓库内文件时才用仓库 diff，并且**用 pathspec 限定到这些文件**；
都没有就退回「任务记录里的文件清单」并标注行数缺失。

**结论词必须整取**：`未通过` 含 `通过`，早期用子串判断把验证失败读成了成功——现在用
`通过|未通过|超时|跳过|未执行` 整词匹配，并给出 `ok` 布尔。

## 裁决

| 指令 | 效果 |
| --- | --- |
| `task:accept` | 任务 → `done`，轨迹追加 `review:confirm`（存档） |
| `task:reject <意见>` | 任务 → `running`，轨迹追加 `review:reject` + 意见（LLM 据此继续修） |
| `task:skip-review` | 任务 → `done`，轨迹标记「未经 review」 |

裁决写进任务的 `review_json`（`verdict` / `verdict_at` / `verdict_note`），并回写报告文件的
「裁决」段（用户意见一并落盘）。

## 报告落盘与保留策略

- 路径：`docs/task-reviews/<task_id>.md`（`task_flow.review_dir` 可覆盖）
- **一任务一文件，不自动清理**；同一任务重跑覆盖同名文件（旧版本看 git 历史）
- 字节写入（避免 Windows 文本模式改行尾），目录不存在自动创建

## 实测证据

真实任务（由 `tools/e2e_task_flow.py --seed-broken` 的真实 LLM 跑出）生成的报告：
`docs/task-reviews/7adb023e980d4602a3599295468620b3.md`

```
## 验证结果
- s2（code，done）：pytest 通过
- s3（test，done）：pytest 通过
## 待确认问题
- 工作区非 git 仓库，改动清单来自任务记录，行数统计缺失
- 任务未记录 git 基线，无法对比任务前后的版本差异
## 裁决
- 待裁决（确认 / 打回 / 跳过）
```

仓库内改动（`file_refs` 指向仓库文件）走 repo diff，实测输出：

```
- 来源：repo（D:\my git\scratchpad）
- 文件数：1｜+49 / -2
- 文件清单：apiserver/task_flow.py
apiserver/task_flow.py | 51 ++++++++++++++++++++++++++++++++++++++++++++++++--
 1 file changed, 49 insertions(+), 2 deletions(-)
```

裁决三路径实测：`打回 → running`、`确认 → done`、`跳过 → done（未经 review）`。

## 对话侧接线

任务转入 review 时 loop 会发 `task_review` SSE 事件（内含报告要点 + 三条裁决指令）；
`task:review` 元指令直接回报告全文（含裁决提示）。

## 测试


覆盖：汇总完整性（改动/验证/文件/问题/裁决段）/ 验证未全绿与未完成被列出 / 确认存档 /
打回带意见回 running / 跳过标记 / 非法裁决与不存在任务 / 元指令三路径 / review 提示与目录统计 /
done 任务不再算活动任务。
