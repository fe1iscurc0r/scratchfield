## 1. 架构一句话（**描述级**）

**自进化记忆 OS**：把记忆做成操作系统层（调度 + 检索 + 跨任务技能复用），
并用"token 节省率"作为可量化卖点。

## 2. 与自家对应模块的差距 / 落点

工单给的落点是**精准的**："与其再做一个记忆库，不如借其**记忆调度（MemCube）**"。

| 维度 | MemOS | 陆墨现状 |
|---|---|---|
| 层次 | **OS 级调度**（谁在何时用哪段记忆） | `memory_maas` 有分层存储，但**调度**是薄层（时间阈值 + 事件驱动） |
| 检索 | hybrid-retrieval | 向量 + 图谱双通道 |
| 复用 | **cross-task skill reuse**（技能级复用） | 我们有 MCP 工具面 + `workflow/chains`，但**没有"技能记忆"**概念 |
| 度量 | token savings 量化 | 缺同类指标（我们只有 telemetry 的调用画像） |

**差距的本质**：我们缺的不是"存"，是**"调度 + 度量"**。

## 3. 可借用的具体设计（非代码）

1. **MemCube 的调度粒度**：记忆单元（cube）如何定义、如何按任务上下文选取 ——
   可对照 `memory_maas` 的 `index_cards` / `typed_entities` 做**选取策略**升级。
2. ⭐ **cross-task skill reuse**：这是我们**完全没有**的一层 ——
   把"某任务里成功的工具序列"沉淀成可复用的技能记忆（与工单205 的
   `tool_chain_audit` 任务级调用链**天然衔接**：调用链是原料，技能复用是产物）。
3. **token 节省率作为可验证指标**：我们所有记忆改动目前都缺**量化口径**，
   这条值得直接借（用它当 KPI 才说得清"记忆改动到底有没有用"）。
4. **论文 arXiv 2507.03724** 可作方法学来源（比读代码更快领会设计意图）。
