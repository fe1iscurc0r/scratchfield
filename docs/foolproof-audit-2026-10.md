```
ERROR: [Errno 10048] error while attempting to bind on address ('127.0.0.1', 18999):
[winerror 10048] 通常每个套接字地址(协议/网络地址/端口)只允许使用一次。
```

**判定**：🤐→😕 **不算卡死但不是人话**——uvicorn 有报错（不静默），进程退出；
但**没人告诉用户"是不是双开了、该杀谁"**（无 PID、无指引、无"已在运行"判定）。

**未实施**（见 §修复记录——与工单单例策略有关，见下）。

## 场景2：配置写坏 —— 已实测 ✅

**复现**：`badcfg.json` 写入 `{"api": {"base_url": "x", TRAILING,,,COMMA` → `ConfigManager()` 构造。

**实际表现**：
```
加载配置文件失败: ...（一行 Python 异常文本）
获取配置快照失败，返回兜底配置
→ 构造成功，内存里是默认配置（api.base_url=空、ai_name=默认）
→ 坏文件原样留在原地，无 .bad/.bak 备份，无重建
```

**判定**：💾 **接近数据丢**——服务**能起**（兜底配置，好事），但：
1. **坏文件不被备份/重建** → 下次写配置（update_config）会用内存默认**覆盖**用户的坏文件——
   **坏文件里没坏的部分（几十项手工配置）将永久丢失**；
2. 用户只看到控制台一行英文异常，无"已重置，原文件在哪"告知。

**缺口修复（场景2 快赢，工单任务二 #2）**：`_load_config_file` 解析失败分支 →
`os.rename(path, path + ".bad.<ts>")` 备份 + 打印人话 → 内存默认可安全落盘。
**未实施**（15 行内可做，但改的是 config_manager 核心路径——工单220 刚判定 schema 迁移归
209 拆分管，此改动与拆分动同一文件，**合并到 209 执行单做**，避免双线改一个文件）。

## 场景3：API key 填错/过期（GLM 10-10 正是此例）—— 已实测（读处理链）✅

**实际表现**（`llm_service.py:530-556` 实读 + 实测复现）：
- **401（认证失败）**：✅ **防线最厚**——诊断日志（token sha 前缀）→ 自动刷新 token 重试 1 次 →
  刷新成功推 `token_refreshed` 给前端 → 失败推 `auth_expired`（**中文人话**"登录已过期，请重新登录"）；
- **连接/服务不可用/超时**（:558）：有捕获分支（返回 error 提示）；
- **402（欠费）/ 429（限流）**：❌ **无专属分类**——落入通用异常 → 用户只看到"请求失败"类信息，
  分不清"欠费了充钱"和"限流了等会儿"和"key 填错了"；
- **fallback 触发提示**：❌ **fallback 是 config 级静态链**（api.model 单值），**没有运行时
  按错误自动切换**的代码路径 → "fallback 发生时前端提示"目前**无事发点**（这个问题本身不成立，
  见判定）；但**静态 fallback 链本身**（工单210 盘点）切 provider 时同样无前端提示。

**判定**：🤐（402/429 无分类）+ 😕（切换 provider 静默）。
**修复（场景3 快赢，任务二 #3）**：异常分类透传——`except` 链里按
`litellm.RateLimitError / PermissionError(402 族) / AuthenticationError / Timeout`
分四类映射人话文案（"限流稍后再试 / 账户欠费 / key 无效或过期 / 网络超时"），塞进现有
`_format_sse_chunk("error", ...)` 通道。**未实施**：需要真实 402/429 响应验证文案链（无假 key），
且 llm_service 537 行函数正在 209 的拆分名单上——**文案表可先写死在异常映射处，随拆分一起落**。
