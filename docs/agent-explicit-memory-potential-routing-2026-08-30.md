## 一、问题陈述

多 Agent 机器人调度有两个老问题：
1. **记忆**：策略的知识固化在参数里，部署后难以持续学习新情况（sim-to-real 漂移）。
2. **路由**：任务如何分配给"能力匹配的执行器"，且在执行中能逐跳重选（某个执行器失效/不匹配时换路）。

授粉点 3 给出三件套：
- **显式优势记忆（2608.25610）**：策略把行为外包给**非参数索引**，关键事件直接索引，**部署期持续学习**。
- **语义势场路由（2608.25396 SPFR）**：把任务路由给能力匹配执行器，**逐跳重选**，势场指数衰减，无环有限终止。
- **ROS2 Connect（2608.25102）**：打通 WAN 的分布式通信。

三者组合 = 分布式多 Agent 网络的"记忆-路由-通信"完整骨架。

## 二、方案设计

### 2.1 显式记忆（部署期持续学习）
- 关键事件/经验写入**非参数索引**（而非回写参数）。
- 部署时遇到新情况，直接索引记忆，无需重训；sim-to-real 漂移通过持续写入新记忆缓解。

### 2.2 语义势场路由（能力匹配 + 逐跳重选）
- 每个执行器有**能力语义标签**；任务有**需求语义**。
- 路由按"需求 ↔ 能力"的语义匹配度构造势场：匹配度高 → 势场强 → 吸引任务。
- **势场指数衰减 + 逐跳重选**：任务转发到下一跳前重新评估最优执行器；若当前执行器失效，自动重选。
- 保证**无环、有限终止**。

### 2.3 通信（ROS2 Connect）
- 跨 WAN 打通，让显式记忆与路由信息在分布式节点间同步。

## 三、模拟对比设计

对比两个调度策略：
1. **基线**：静态任务分配（固定路由，无逐跳重选）。
2. **本方案**：显式记忆 + 语义势场路由 + 逐跳重选。

**指标**：任务完成率、平均完成时延、执行器失效时的恢复成功率。
**预期**：执行器动态失效场景下，本方案恢复成功率显著优于静态路由（势场逐跳重选的优势）。
