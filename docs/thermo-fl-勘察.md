# Thermo-FL 热感知联邦 LoRA 勘察报告（R59）

> 2026-08-31 · 智能体 12 · 来源：digest-g1-2 2608.21172v1（Thermo-FL：热感知联邦 LoRA，TERRA 鲁棒聚合，Jetson 物理测试台）
> 状态：勘察（不写实现）

## 一、结论（TL;DR）

Thermo-FL 把**设备热状态**作为联邦学习聚合的一等信号：边缘设备（Jetson 等）过热会降频、中断训练、产出劣质梯度，传统联邦聚合（FedAvg）把这些劣质更新等权平均，拖垮全局模型。其 TERRA 聚合按温度加权/筛选客户端更新，并用 Jetson 物理测试台实测热行为。对 LoRa/边缘联邦的借鉴价值：**用热状态（或更广义的「设备健康度」）指导聚合权重与调度**，把物理约束纳入联邦协议。

## 二、聚合机制

- 基线 FedAvg：所有客户端更新等权平均，隐式假设客户端同质、稳定。
- Thermo-FL：客户端上报**温度 + LoRA 更新**；服务端按温度估计该更新的可靠性，TERRA 鲁棒聚合：
  - 过热/降频客户端的更新降权或剔除（温度 > 阈值 → 视为「退化的 straggler」）
  - 温度梯度可预测「即将过热」的客户端，提前调度/降载，避免训练中途掉线
- LoRA 载体：只交换低秩适配器（B·A），通信量远小于全模型——契合窄带边缘链路。

## 三、温度感知建模

- 物理层：设备功耗 → 结温 → 降频（DVFS）→ 训练延迟↑ / 更新质量↓。
- 温度是**慢变但有先兆**的状态量：比「是否掉线」更早、更连续地暴露设备退化。
- 建模把温度映射为「更新可信度权重 w(T)」（单调递减），温度是聚合的隐式先验。

## 四、自建门槛（我们若自建需面对）

1. **真机热数据缺失**：需要 Jetson 级测试台或温度传感器日志；无硬件时只能 mock（诚实降级）。
2. **热模型异构**：不同设备（ESP32/SX127x vs Jetson）热行为差异大，通用 w(T) 难定。
3. **LoRa 上行瓶颈**：LoRa 上行极窄，联邦更新本身可能传不动，LoRA 降通信只是缓解。
4. **温度-质量因果弱**：温度高不一定更新差（可能只是慢），需实测标定而非假设。

## 五、可落地借鉴点（≥3 条）

1. **「设备健康度」作为聚合权重**：LoRa 传感网可把 RSSI/电池电压/温度映射为更新权重，劣质节点自动降权——比「硬剔除掉线节点」更平滑。
2. **鲁棒聚合（TERRA 思想）**：对「退化的 straggler 更新」用中位数/裁剪聚合替代均值，抗个别节点异常（与 R42 分布式鲁棒性呼应）。
3. **LoRA 作为边缘联邦载体**：只交换低秩增量，大幅降上行字节，可直接用于 rf_brain 的分布式频谱模型微调。
4. **先兆调度**：用温度梯度预测过热，提前降载——映射到 LoRa 节点「电量即将耗尽」时提前切换上报策略（承接 v1.6 的功耗主线）。

## 六、离栈度

中。核心是「物理状态 → 聚合权重」的通用范式，与 LoRa/边缘联邦直接相关；但 Jetson 热建模的具体实现离 ESP32/LoRa 栈较远，需替换为「电量/链路健康度」等价物。
