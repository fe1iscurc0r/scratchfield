# LightRAG 架构参考笔记

> HKUDS (港大数据智能实验室) · EMNLP 2025 · 35k+ Star

---

## 一、是什么

**基于知识图谱的双层 RAG 框架**。传统 RAG 只做向量"找相似"，LightRAG 先抽取实体关系建图谱，实现"找相似 + 找关联"双路并行。

---

## 二、核心架构

```
输入(PDF/DOC/PPT/CSV/MD) → 分块(4策略) → LLM抽取实体/关系三元组
  → 实体去重合并 → 知识图谱 → 存储层{图+向量+KV+文档状态}
  → 双层检索{Low-Level实体 + High-Level主题} → LLM生成
```

### 双层检索

| 层级 | 对象 | 目的 |
|------|------|------|
| **Low-Level** | 具体实体、关系 | 精确匹配查询相关事实 |
| **High-Level** | 主题、概念、社区摘要 | 跨文档全局关联 |

查询模式: local / global / hybrid(默认+重排序) / naive(纯向量)

### 多存储后端

| 类型 | 后端 |
|------|------|
| 图 | Neo4j / NetworkX(默认,零依赖) |
| 向量 | Milvus / Qdrant / pgvector / OpenSearch |
| KV | Redis / PostgreSQL / MongoDB |
| 文档状态 | 同上 |

**OpenSearch 或 PostgreSQL 可单一后端承载全部四种存储**。

## 三、关键设计模式

### 1. 增量图谱更新
新文档仅对新内容提取合并，不重建全图；API 支持手动 CRUD 实体/关系；自动实体去重 + 图库向量库一致性保证。

### 2. 角色专用 LLM
| 角色 | 触发 | 推荐策略 |
|------|------|----------|
| EXTRACT | 文档入库 | 快模型，高频调用 |
| QUERY | 用户提问 | 强模型，低延迟 |
| KEYWORDS | 查询预处理 | 快模型，提取关键词驱动图检索 |
| VLM | 图像/表格 | 多模态模型 |

### 3. 分块策略
**Fix**(固定长度) / **Recursive**(段落边界递归) / **Vector**(语义切分) / **Paragraph**(纯段落)。按文档类型自适应选择。

### 4. 多模态 (RAG-Anything)
图像/表格/公式经 MinerU/Docling 提取，图谱节点关联多模态证据，VLM 角色处理视觉理解。

### 5. 可观测性
Langfuse 全链路追踪 + RAGAS 评估；API 返回检索上下文便于调试召回质量。

## 四、对 Scratchpad 的借鉴

| 维度 | 可迁移模式 |
|------|-----------|
| **双路召回** | 全文搜索 + 实体关系图谱 → "找匹配+找关联" |
| **可插拔存储** | 本地 JSON → PostgreSQL → Neo4j 渐进升级 |
| **增量索引** | 单条文档即时生效，避免全量重建 |
| **角色 LLM** | 按任务(抽取/生成/关键词)分配不同模型控成本 |
| **分块可选** | 用户按文档类型选择最优切分策略 |

> 洞察：图谱+向量双路融合是跨文档关联推理的有效范式——RAG 不应止于语义相似度。
