# Graphiti 架构参考笔记

> Zep 团队开源 · AI Agent 的时序感知知识图谱框架
> github.com/getzep/graphiti · help.getzep.com/graphiti/

---

## 一、是什么

**专为 AI Agent 设计的动态、时序感知知识图谱**。核心痛点：大多数 AI 系统会话结束就"失忆"。Graphiti 将对话/文档/API 响应持续转化为随时间演化的图谱，让 Agent 理解事物关联并记住它们在什么时间、什么背景下成立。它是 Zep Memory 的底层引擎。

---

## 二、核心架构

```
非结构化输入(对话/文档/API/邮件)
  → Episode 创建(信息基本单元)
  → LLM 抽取 Entities + Facts/Relationships
  → 增量写入图谱 带双时态标记
  → 混合检索{语义+BM25关键词+图遍历} → LLM生成
```

### 四层数据模型

| 层 | 定义 | 关键特性 |
|------|------|----------|
| **Episodes** | 原始信息源，所有事实的溯源根 | 时间戳、来源、原始内容 |
| **Entities** | 人/物/概念，摘要演化 | 名称、类型、演化摘要 |
| **Facts** | 三元组(主→谓→宾) | valid_at/invalid_at 时间窗口 |
| **Custom Types** | Pydantic 扩展本体 | 自定义实体和边 |

### 双时态 (Bi-Temporal) —— 核心创新

| 时态 | 字段 | 含义 |
|------|------|------|
| **事件时间** | valid_at / invalid_at | 事实在现实中何时生效/失效 |
| **系统时间** | created_at / expired_at | 系统何时记录/废弃 |

新事实与旧事实冲突时，旧关系标记 `invalid_at` 而非删除——历史状态永久可回溯。

### 混合检索 (亚秒级)

语义向量 + BM25 关键词 + 图遍历，三路融合，不依赖 LLM 摘要。

---

## 三、关键设计模式

### 1. 自治图谱构建
从非结构化文本自动提取实体/关系/事件，无需预定义 schema；智能判断新增/修正/失效；社区结构组织相关实体群。

### 2. 增量更新
单条新消息即时更新，不触发批量重建；并行处理大规模数据；冲突旧关系标记失效而非删除。

### 3. 事件溯源
每条关系可追溯到来源 Episode——"你怎么知道？"→回溯到原始对话；支持按来源过滤和置信度排序。

### 4. MCP Server
通过 MCP 协议暴露图谱能力，Claude/Cursor 可直接交互。场景：Agent 长对话记忆、项目知识库、客户360画像。

### 5. 多后端
图数据库: Neo4j / FalkorDB / Kuzu / Amazon Neptune
LLM: OpenAI / Azure / Gemini / Claude / Groq / Ollama(本地)

## 四、与 GraphRAG 的关键差异

| | GraphRAG (微软) | Graphiti (Zep) |
|------|------|------|
| 定位 | 静态文档分析 | 动态数据持续管理 |
| 更新 | 批量处理 | 持续增量 |
| 时间建模 | 基本时间戳 | 显式双时态 |
| 检索 | LLM 摘要顺序查询 | 语义+关键词+图混合 |
| 延迟 | 数秒~数十秒 | 亚秒级 |

## 五、对 Scratchpad 的借鉴

| 维度 | 可迁移模式 |
|------|-----------|
| **Agent 长期记忆** | Episode → Entity → Fact 三层提炼，跨会话知识积累 |
| **双时态** | 决策/偏好变化记录"当时"+"现在"+"变更时间点" |
| **混合检索** | 向量+BM25+图谱遍历，超越纯语义相似度 |
| **增量更新** | 单条追加即时生效 |
| **事件溯源** | 所有结论保留"从哪得出"的追溯链 |
| **MCP 封装** | scratchpad 封装为 MCP Server，被其他 AI 调用 |

> 洞察：将**时间维度**和**事件溯源**作为一等公民融入图谱建模，使 Agent 记忆从"快照"变成"可回放的连续历史"。
