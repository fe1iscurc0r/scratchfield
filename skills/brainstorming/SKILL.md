# brainstorming — 需求收敛（动手前三问）

## 何时用
用户提出的需求存在以下任一情况时**必须**先走本流程，禁止直接写代码：
- 没说清"做成什么样"（无验收标准）
- 有 ≥2 种合理做法且选择影响架构
- 涉及删除/覆盖/外发等不可逆动作

## 流程（三步一批准）

### 第 1 步：复述 + 意图三问
向用户复述理解，并问（一次问全，别挤牙膏）：
1. **要解决什么问题？**（真实动机，不是表面需求）
2. **做成什么样算成？**（可验证的验收标准）
3. **有什么约束？**（时间/技术栈/不碰什么）

### 第 2 步：出设计方案（≤2 个）
每个方案给：思路一句话 / 关键取舍 / 工作量档位（小时级/天级）。
有推荐就明确推荐 + 理由，不做无立场的罗列。

### 第 3 步：等批准
明确问"按方案 A/B/改，选哪个？"——**收到明确答复才进入实现**。
用户说"你定"= 授权按推荐项走，记录在案。

## 输出格式
```
## 需求理解
（复述）
## 三问
1..2..3..
## 方案 A（推荐）/ 方案 B
## 待批准
```

## 与其他 skill 的衔接
批准后 → `writing-plans`（SPEC→分块任务）→ 实现 → `verification-before-completion`（验收门）。
