# verification-before-completion — 完成前验收门

## 何时用
在说"做完了 / 已完成 / 可以用了"**之前**，逐关过。任何一关不过 → 不算完成。

## 五关（按序）

### 关 1：测试真实跑过
- 新代码有测试且 `pytest`/对应命令**本机实际执行**过
- 输出贴出通过数（"11 passed"），不是"应该没问题"
- 存量测试无新失败（跑受影响范围的测试集）

### 关 2：验收断言逐条核验
- 对照工单/SPEC 的验收标准**逐条**标 ✅/⏳/❌
- ⏳/❌ 必须写明阻塞原因和需要的输入，不许静默略过
- 验收里"≥N%"类指标给出实测数字

### 关 3：副作用清点
- git status：列出本次新增/修改/删除的文件，确认无意外文件混入
- 系统级改动（安装/配置/端口/后台进程）逐一列出，标注可回滚方式
- 秘钥/token 未出现在任何落盘文件

### 关 4：遗留问题明示
- 未做的事、已知缺陷、后续建议 → 写进交付报告"遗留"节
- 禁止把"没做"写成"做了"

### 关 5：证据留档
- 测试输出、验收数据、关键截图/日志 → 落 `docs/<任务>-report.md` 或工单系统
- 报告含：做了什么/验收数据/遗留/回滚方式

## 输出格式（交付报告骨架）
```
# <任务> 验收报告
## 结果：<一句话结论>
## 验收对照（逐条 ✅/⏳/❌ + 实测数字）
## 测试证据（命令 + 通过数）
## 副作用清单（文件/系统改动/回滚）
## 遗留问题
```

## 铁律
> 没跑过的测试 = 不存在的测试；没度量的指标 = 没达成的指标。
