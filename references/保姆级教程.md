## 一、环境准备

### 1.1 系统要求

| 项 | 要求 | 说明 |
|----|------|------|
| 操作系统 | Windows 10/11（64 位） | 本文档按 Windows + PowerShell 写；脚本里有 `.bat` |
| Python | **3.11（推荐）** | `requirements.txt` 明确建议 3.11；3.10/3.12 一般也能跑，但官方按 3.11 打包 |
| 浏览器 | Microsoft Edge | `MatchatBridge` 用 `channel="msedge"` 启动；需系统已装 Edge |
| Node.js | ≥ 18（建议 20 LTS） | 仅在跑前端 UI 时需要；只跑后端/测试脚本可不装 |
| 网络 | 能访问 `ai.matchat.cn` 与 LLM API | MatChat 与大模型 API 都要联网 |

### 1.2 安装 Python 3.11

1. 打开 https://www.python.org/downloads/release/python-3119/ （或任意 3.11.x），下载 **Windows installer (64-bit)**。
2. 双击安装，**务必勾选 "Add python.exe to PATH"**。
3. 安装完成后，新开一个 PowerShell，验证：
   ```powershell
   python --version
   ```
   应输出 `Python 3.11.x`。若提示"找不到命令"，说明 PATH 没加好，重装时勾选该项，或手动把 Python 安装目录加到系统 PATH。

### 1.3 创建虚拟环境并安装依赖

项目自带脚本 `setup_venv.bat`，它会：创建 `.venv` → 激活 → 升级 pip → 安装 `requirements.txt`。

**方式 A（推荐，一键）：**
```powershell
cd "d:\my git\scratchpad"
.\setup_venv.bat
```
脚本会问"是否删除已有 .venv"，首次安装直接回车（N）即可。看到 `虚拟环境重配完成` 即成功。

**方式 B（手动）：**
```powershell
cd "d:\my git\scratchpad"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

> 若 `Activate.ps1` 报"禁止运行脚本"，先执行一次：
> `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`

激活成功后，命令行前面会出现 `(.venv)` 前缀。**之后所有 `python` / `pip` 命令都应在激活状态下运行。**

### 1.4 安装 Playwright 与 Edge（MatChat 自动化必需）

⚠️ **关键易漏点**：`requirements.txt` **不包含** playwright，但 `matchat_bridge.py` 依赖它。必须单独装：

```powershell
# 确保 .venv 已激活
pip install playwright
# 下载 Edge 驱动（MatchatBridge 用 channel="msedge"）
playwright install msedge
# 若上面命令不可用，可改用 chromium 兜底（需改代码里的 channel）
playwright install chromium
```

验证：
```powershell
python -c "from playwright.sync_api import sync_playwright; print('playwright OK')"
```
输出 `playwright OK` 即可。

确保系统已装 **Microsoft Edge**（Win10/11 默认自带）。`MatchatBridge` 启动时用 `channel="msedge"` 直接调系统 Edge，无需额外下载浏览器二进制。

### 1.5 安装 Node.js（前端 UI）

只有要跑前端桌面 UI（`start.bat` / `npm run dev`）才需要。

1. 到 https://nodejs.org/ 下载 20 LTS，默认安装。
2. 验证：`node -v` 输出 `v20.x.x`。
3. 装前端依赖：
   ```powershell
   cd "d:\my git\scratchpad\frontend"
   npm install
   ```
   （首次较慢，约 3-10 分钟）

## 二、配置说明（config.json）

### 2.0 安全说明与文件位置

- 配置文件：`d:\my git\scratchpad\config.json`（**真实配置，含密钥，勿外传、勿提交 git**）
- 模板文件：`d:\my git\scratchpad\config.json.example`（**不含真实密钥，可参考字段含义**）
- **首次使用**：复制模板为真实配置并填入你的密钥：
  ```powershell
  cd "d:\my git\scratchpad"
  Copy-Item config.json.example config.json
  ```
  然后用记事本/VSCode 编辑 `config.json` 填入 API Key 等。
- ⚠️ **本文档只读不改 `config.json`**。下面字段含义以 `config.json.example` 为准。

### 2.1 各字段含义速查表

config.json 是一个 JSON 对象，按"段"划分。每段作用如下：

| 段 | 作用 | 关键字段 / 默认值 | 你需要改什么 |
|----|------|------|------|
| `system` | 全局系统开关 | `version`、`debug:false`、`log_level:INFO`、`stream_mode:true` | 一般不动；排错时把 `debug:true` |
| `api` | **大模型 API 配置** | `api_key`、`base_url`、`model`、`provider`、`use_gateway`、`max_tokens` | **必改**：填你的 `api_key`；默认用 deepseek |
| `api_server` | 本地 API 服务 | `host:127.0.0.1`、`port:8000`、`auto_start:true` | 端口冲突时改 `port` |
| `agent_server` | Agent 调度服务 | `port:8001` | 一般不动 |
| `mcp_server` | MCP 工具服务（MatChat 桥接走这里） | `port:8003`、`agent_discovery:true` | 一般不动 |
| `grag` | 知识图谱（GRAG，基于 Neo4j） | `neo4j_uri/user/password`、`auto_extract:true` | 不用图谱可设 `enabled:false`；用时填 Neo4j 密码 |
| `handoff` | 多 Agent 工具循环上限 | `max_loop_stream:5`、`max_loop_non_stream:5` | 死循环时调小 |
| `browser` | Playwright 浏览器开关 | `playwright_headless:false` | MatChat 登录必须 `false`（要看见窗口） |
| `tts` | 语音合成 | `port:5048`、`default_voice:zh-CN-XiaoxiaoNeural` | 不用语音可忽略 |
| `asr` | 语音识别 | `port:5060`、`engine:local_funasr` | 不用语音可忽略 |
| `filter` | 输出过滤 | `filter_think_tags:true`、`clean_output:true` | 一般不动 |
| `difficulty` | 难度评估（默认关） | `enabled:false` | 需要时开 |
| `scoring` | 评分系统（默认关） | `enabled:false` | 需要时开 |
| `mqtt` | MQTT 消息（默认关） | `enabled:false` | 一般不动 |
| `ui` | UI 参数 | `user_name`、`bg_alpha`、`animation_duration` | 改 `user_name` 为你的名字 |
| `live2d` | 桌面 Live2D 模型 | `model_path`、`enabled:true` | 不用 Live2D 设 `enabled:false` |
| `web_live2d` | 网页端 Live2D | `model.source`、`ssaa:2` | 一般不动 |
| `floating` | 悬浮球 | `enabled:false` | 需要时开 |
| `voice_realtime` | 实时语音对话（默认关） | `enabled:false`、`provider:qwen` | 需要时开 |
| `online_search` | 联网搜索 | `searxng_url`、`engines:["google"]` | 按需配置 |
| `openclaw` | OpenClaw 网关（默认关） | `enabled:false`、`gateway_port:20789` | 一般不动 |
| `auth` | API 服务鉴权 | `enabled:true`、`require_auth:false` | 生产环境建议 `require_auth:true` |
| `notifications` | 飞书/QQ 通知（默认关） | `feishu.enabled:false`、`qq.enabled:false` | 按需开 |
| `telemetry` | 遥测 | `enabled:true`、`upload_enabled:true` | 不想上报设 `upload_enabled:false` |
| `computer_control` | 电脑控制（Gemini 视觉） | `model:gemini-2.5-flash`、`api_key` | 需要时填 `api_key` |
| `guide_engine` | 游戏攻略引擎（默认关） | `enabled:false` | 一般不动 |
| `memory_server` | 长期记忆服务 | `url:http://localhost:8004` | 按需配置 |
| `embedding` | 嵌入模型（RAG 用） | `model:tongyi-embedding`、`api_base`、`api_key` | 用 RAG 时配置；不配则 RAG 走本地 bge 降级 |
| `system_check` | 系统自检结果（自动写） | `passed:false` | 别手改，由系统写 |

### 2.2 最小可跑配置

只想跑通 MatChat + RAG 测试脚本，最少要改：

1. `api.api_key` → 填你的 DeepSeek/OpenAI Key
2. `browser.playwright_headless` → 保持 `false`（MatChat 登录要可见）
3. （可选）`embedding.api_key` → 想用在线嵌入时填；不填 RAG 会用本地 bge-small-zh 或降级随机向量

## 四、MatChat 内嵌使用流程

### 4.1 流程总览

```
┌─────────────┐    ┌──────────────┐    ┌─────────────┐    ┌──────────────┐
│ 1. 登录      │ -> │ 2. 提问       │ -> │ 3. 拿到回复  │ -> │ 4. 入库 RAG   │
│ MatchatBridge│    │ search/chat  │    │ AI 文本      │    │ ingest_document│
└─────────────┘    └──────────────┘    └─────────────┘    └──────────────┘
   persistent          DOM 操作            提取文本           分块+嵌入+落库
   浏览器复用          _send_message       _capture_latest    rag_service
```

> 说明：在 NagaAgent 完整产品里，"提问 → 入库"由 Electron 侧 `frontend/electron/modules/matchat.ts` 编排（手动问答 → 入库）。`MatchatBridge` 专注给 AI Agent / MCP 工具链做自动化调用。两者解耦。本节讲的是用 Python 脚本走通这条链路。

### 4.2 第一步：登录

**为什么要登录**：MatChat 的 28 万篇论文知识库和 AI 对话都需要账号 session。`MatchatBridge` 不模拟登录（不填手机号、不碰验证码），而是启动一个可见的 Edge 让你手动登一次，session 持久化后后续自动复用。

**怎么登**：
1. `python test_matchat_e2e.py`（或 `dom_probe.py`）会弹出 Edge。
2. 在 Edge 里正常登录 MatChat（手机号/验证码或第三方登录）。
3. 登录成功、看到聊天界面后，创建 flag 文件触发后续：
   ```powershell
   New-Item 'd:\my git\scratchpad\matchat_e2e_ready.flag'
   ```
4. 脚本自动继续。

**怎么判断登录成功**：`bridge.ensure_login()` 返回 `{"needs_login": false, "logged_in": true}`。判断依据：URL 不含 `login/passport/account/auth`，且页面没有"登录"按钮。

**登录态存哪**：`C:\Users\<你>\.naga\matchat_browser_data\`（即 `~/.naga/matchat_browser_data`）。删掉这个目录等于"退出登录"，下次要重登。

### 4.3 第二步：提问

两种提问方式（都是 `MatchatBridge` 的方法）：

| 方法 | 签名 | 用途 | 区别 |
|------|------|------|------|
| `search_literature` | `search_literature(query, max_results=5)` | 文献检索 | 会把 query 包装成"请帮我搜索关于 X 的文献，列出 N 篇…" |
| `chat` | `chat(message)` | 直接对话 | 原样发送 message |

返回值统一是 `dict`：`{"success": bool, "response": "AI 回复文本", "error": "..."}`。

**底层流程（`_send_message`）**：
1. `query_selector("textarea#ai-input")` 找输入框 → `click()` + `fill(message)`
2. 找发送按钮：`button[data-tooltip-id='send-btn-tooltip']`，找不到用兜底 `button:has(img[alt='发送'])`
3. 检查按钮是否 disabled：是则用键盘 `Ctrl+Enter` 兜底发送
4. `_wait_for_response`：轮询 `#chat-scroll-container` 内消息块数量/文本长度变化，连续 2 轮稳定且文本 >150 字就认为回复完成；超时返回已捕获的部分文本
5. 内置 2 次重试，每次间隔 3s

### 4.4 第三步：入库

拿到 AI 回复文本后，写入 RAG 知识库（见第五章）。典型代码：

```python
import tempfile
from rag import get_rag_service

svc = get_rag_service()

# 把 MatChat 回复写成临时 txt 走标准管线
qa_text = "Q: 木质素基碳材料碳化温度优化\nA: ..."  # 实际从 bridge.chat() 拿
with tempfile.NamedTemporaryFile("w", delete=False, suffix=".txt", encoding="utf-8") as fp:
    fp.write(qa_text)
    tmp = fp.name

result = svc.ingest_document(
    file_path=tmp,
    title="【MatChat】木质素碳化温度",
    tags=["碳材料", "MatChat"],
    metadata={"source": "matchat", "qa_pair": True},
)
print(result)  # {'success': True, 'doc_id': 'doc_xxxx', 'chunk_count': N, ...}
```

> `metadata.source` 建议固定为 `"matchat"`，方便后续用 `list_documents(source="matchat")` 单独筛 MatChat 来源的问答。

## 五、RAG 知识库使用方法

### 5.1 RAG 是什么 / 能干什么

RAG = Retrieval-Augmented Generation（检索增强生成）。本项目 RAG 模块在 `rag/` 目录，提供：
- **入库**：把文档（txt/md/pdf/docx）解析 → 分块 → 嵌入向量 → 存进本地向量库
- **检索**：用自然语言提问，向量召回 + 可选重排序，返回最相关的片段

技术栈：`sqlite-vec`（向量库）+ `BAAI/bge-small-zh-v1.5`（嵌入模型，本地 CPU 可跑）。嵌入引擎不可用时会**降级为随机向量**（能跑通流程但检索质量不可靠，仅用于环境自测）。

入口：`from rag import get_rag_service` → 返回 `RAGService` 单例。

### 5.2 入库（ingest_document）

```python
svc.ingest_document(
    file_path="xxx.txt",        # 必填：文件路径（支持 txt/md/pdf/docx）
    title="文档标题",            # 可选：默认用文件名
    tags=["标签1", "标签2"],     # 可选：标签列表
    metadata={"source": "matchat", "qa_pair": True},  # 可选：任意元数据
)
```
返回：`{"success": True, "doc_id": "doc_xxxx", "chunk_count": N, "elapsed_ms": ms, ...}`

注意：
- 入库会**复制一份原始文件**到数据目录 `data/rag/documents/`，删源文件不影响检索。
- 失败时 `success=False`，看 `error` 字段。

### 5.3 检索（query）

```python
svc.query(
    query_text="淀粉基和明胶基塑料哪个拉伸强度更高",
    top_k=3,            # 返回前 3 条
    tags=None,          # 可选：按标签过滤
    min_score=0.6,      # 最低分数阈值，低于不返回
    rerank=True,        # 是否启用关键词重排序
)
```
返回：`{"query_id": "q_xxxx", "results": [...], "total_matches": N, "latency_ms": ms}`

调参建议：
- 结果太少/为空：把 `min_score` 调低（如 0.3），或关掉 `rerank` 看原始向量召回
- 结果不相关：开启 `rerank=True`，或减小 `top_k`
- 嵌入降级时（`get_stats().fallback_mode == True`）：检索结果基本随机，需先修复嵌入（装 torch/transformers 或配置在线 embedding）

### 5.4 列表 / 删除 / 统计

```python
# 列表（可按 keyword / source 过滤）
svc.list_documents(source="matchat", limit=10)
# 返回 {"docs": [...], "total": N}

# 删除
svc.delete_document("doc_xxxx")
# 返回 {"success": True, "doc_id": "doc_xxxx"}

# 统计
svc.get_stats()
# 返回 {"collections": {...}, "embedding_available": bool, "fallback_mode": bool, ...}
```

## 六、常见问题排查（FAQ）

### Q1：`python test_matchat_e2e.py` 报 `AttributeError: 'MatchatBridge' object has no attribute 'close'`
**A**：这是历史 bug，本次已修复。`MatchatBridge` 只有 `disconnect()`，没有 `close()`。若你看到的代码里还有 `bridge.close()`，改成 `bridge.disconnect()`。

### Q2：Playwright 报 `Executable doesn't exist at ... msedge`
**A**：没装 Edge 驱动。执行 `playwright install msedge`。若系统没装 Edge 浏览器本身，去微软官网装 Edge。

### Q3：`dom_probe.py` 一直"等待用户登录"，但我已经登录了
**A**：flag 文件建错位置了。脚本检测的是**脚本目录下**的 `dom_probe_ready.flag`（绝对路径）。必须用：
```powershell
New-Item 'd:\my git\scratchpad\dom_probe_ready.flag'
```
不要用相对路径 `New-Item dom_probe_ready.flag`（除非你当前正好在 `d:\my git\scratchpad` 目录）。本次已把脚本提示改成绝对路径。

### Q4：`test_matchat_e2e.py` 卡在"等待用户登录"超时
**A**：8 分钟没建 flag。重新跑脚本，登录完成后**及时**建 flag 文件触发。

### Q5：MatChat 发消息返回 `error="找不到聊天输入框 (DOM selector 未匹配)"`
**A**：MatChat 改版了，`textarea#ai-input` 选择器失效。先跑 `dom_probe.py` 重新抓 DOM，从输出里找到新的输入框 id/class，然后改 `mcpserver/material_science/matchat_bridge.py` 顶部的 `CHAT_INPUT_SELECTOR` 常量。

### Q6：发消息返回 `error="AI 回复超时"`
**A**：
1. 网络慢 → 把构造函数 `timeout` 调大（如 `MatchatBridge(timeout=120000)`）
2. AI 还在生成 → `_send_message` 内置 2 次重试，再失败可重跑
3. 页面没真正登录 → 用 `ensure_login()` 确认 `needs_login=False`

### Q7：RAG 检索结果为空 / 不相关
**A**：
1. 看 `svc.get_stats()`：`fallback_mode=True` 说明嵌入降级为随机向量，检索无意义。需修复嵌入：装 `torch`+`transformers`，或配置 `config.json` 的 `embedding` 段用在线嵌入。
2. `min_score=0.6` 太高 → 调到 0.3 试。
3. 文档没真入库 → 先 `list_documents()` 确认有数据。

### Q8：`pip install -r requirements.txt` 装不上
**A**：
- 网络 → 换国内源：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`
- `chromadb`/`torch` 编译失败 → 确认 Python 是 3.11 64 位；必要时单独装 `torch`（CPU 版）

### Q9：端口被占用（8000/8001/8003/5048/5060）
**A**：改 `config.json` 对应段的 `port`，或杀掉占用进程：
```powershell
Get-NetTCPConnection -LocalPort 8000 | Select-Object OwningProcess
Stop-Process -Id <上面查到的PID>
```

### Q10：`Activate.ps1` 不能运行
**A**：`Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`，再激活。

### Q11：persistent 浏览器启动失败"user_data_dir 被占用"
**A**：上次 Edge 没正常关闭。任务管理器结束所有 `msedge.exe` 进程，或重启，再重跑。
